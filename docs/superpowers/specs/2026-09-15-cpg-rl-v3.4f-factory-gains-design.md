# CPG-RL v3.4f：馬達增益完全照原廠（實驗線）—— 設計（2026-09-15）

- 分支 `feat/d1-edu-cpg-rl`；基準 = v3.3（`docs/superpowers/specs/2026-09-15-cpg-rl-v3.1-unified-kinematic-generator-design.md` §10）
- 使用者要求：「把馬達的 Kp、Kd 完完全全按照原廠控制，這樣就可以直接套用我們錄製的內容」。其餘與 v3.3 相同。
- 這是 **v3.1 spec §0.1 當時明講「另開線」的那條線**：要用 kp 120 得連命令方式一起換成大幅度命令。
- 代號 `v3.4f`（f = factory gains）。v3.3 那條線不受影響、預設路徑逐位元不變。

## 0. 先量過的事實（2026-09-15 晚，逐檔掃 `logs/m_logs_trip21`）

### 0.1 原廠錄檔只有兩組增益，17 檔全部一致

| 段落 | 腿 ABAD/HIP/KNEE kp | 腿 kd | 腿前饋 | 輪 kp | 輪 kd | 輪前饋 |
|---|---|---|---|---|---|---|
| **動作段**（佔每檔 58–91%） | **60 / 120 / 120** | **1.0** | **全 0** | **0** | **0.1** | ±0.20 ~ 0.54 N·m |
| 靜止段 | 250 / 250 / 250 | 5.0 | 0 | 20 | 0.1 | 0 |

`ref_idle` 整檔都是靜止那組。前進／後退／平移／原地轉／弧線／切換檔的動作段**沒有例外**：
腿 kp 一切到 120，輪 kp 同時切 0。**輪 kd 全程 0.1，沒有第二個值。**
→ 這證實 L 報告 §0 的摘要，並補上「kp 20 只出現在靜止段」這個先前沒寫的細節。

「輪子互相反轉」不是增益的事，是輪的力矩／速度圖案；錄檔的 `tau`、`v` 都有記到，
v3.3 的 `cycle_offsets` 已經在用（對角反向、同側反向都在裡面）。照搬增益不會動到它。

### 0.2 ★ 輪子的 `v_des` 沒有錄到，而且原廠也是「PD 當力矩源」

`kp = 0` 時 `des` 欄是無意義佔位值（`D1Max_機器狗資訊.md` §8.2 已警告）。
用 `v_des = (τ − ff)/kd + v`（kd = 0.1）反推動作段：

| 檔 | 反推 \|v_des\|max | 實測 \|v\|max |
|---|---|---|
| ref_fwd_fast | 38.9 rad/s | 12.1 |
| ref_turn_left | 31.4 | 14.2 |
| ref_arc_right | 45.4 | 15.5 |
| ref_startstop | 50.3 | 14.5 |

全部 20–50 rad/s 對實際 12–17：**原廠對輪子用的手法與腿完全相同**——把 kd 壓到 0.1、
速度目標開到實際的 3 倍，把 PD 當力矩源。

**實質後果**：輪子的擾動抑制變成我們現在（kd 1.0）的 1/10，被地面推著時幾乎自由滾。
這正是原廠平移能側滑、原地轉能刮地的機制之一，**值得照搬**。
代價是 v3.3 的 `WHEEL_RES` ±2 rad/s 殘差只剩 ±0.2 N·m，等於廢掉 → §2 改到力矩空間。

### 0.3 58° 只是 ABAD，髖膝其實很小

動作段 `|des − q|`（15 檔合併；`ref_turn_to_fwd` 2599 筆那個作廢檔跳過）：

| 關節 | p50 | p90 | p99 | p99.9 | max |
|---|---|---|---|---|---|
| ABAD | 0.131 | 0.406 | 0.798 | 0.949 | **1.020 rad（58.4°）** |
| HIP | 0.083 | 0.117 | 0.149 | 0.196 | 0.230（13.2°） |
| KNEE | 0.132 | 0.172 | 0.247 | 0.299 | 0.322（18.5°） |

→ v3.1 spec §0.1 的「ABAD 目標差最大 58°」是**只有 ABAD**。髖膝最大 0.32 < 現行護欄 0.45。
**護欄只需要動 ABAD 一格**（§4），不是整排放寬。

### 0.4 已有的支持證據

`inference/diag/replay_factory.py`（v3.1 spec §8.1）已經證明：用 `scene_flat_mjx.xml`
（腿 kp 60/120/120、kd 1.0，正是原廠動作段那組）直接餵錄檔 `des`，
原地轉做到原廠偏航的 **0.52–0.76 倍且不摔**。「換原廠增益 → 原廠命令可 1:1 套用」在模擬裡有證據。

## 2. 模型 `scene_flat_mjx_v3f.xml`

`model/zgws/make_mjx_model.py` 的 `build()` 已經吃 `kp3`/`kd3`/`wheel_model`，`build_all()` 加一段：

```python
WHEEL_MODEL_V3F = dict(kv=0.1, frictionloss=0.13, damping=0.015, armature=0.004)  # 增益照原廠動作段，輪關節物理照 M11
xml = HERE / "zgws_mjx_v3f.xml"
build(dst=str(xml), kp3=KP3, kd3=KD3, wheel_model=WHEEL_MODEL_V3F)   # KP3=[60,120,120]、KD3=[1,1,1] 本來就在 max_model
build_scene(str(HERE / "scene_flat_mjx_v3f.xml"), xml.name)
```

- **腿增益不用新增常數**：`mm.KP3` / `mm.KD3` 就是原廠動作段那組（kp120 線的原值）。
- **輪關節的 frictionloss / damping / armature 維持 M11 實測不動**——那是硬體特性，不是控制參數。
  只有 `kv` 從 1.0 換成 0.1。
- `max_model.py` 加 `SCENE_MJX_V3F` 常數。

## 3. 輪控制律改到力矩空間

v3.3 現況：`wheel_ctrl(v_des) → ctrl = v_des + sign·τ_ff/kv`，`kv = 1.0`。
在 `kv = 0.1` 下，輪行族運動學差速算出的 v_des（約 5 rad/s）只產生 0.5 N·m，推不動 → 必須改。

**改法**：`wheel_ctrl(tau_cmd, v_meas) → ctrl = v_meas + (tau_cmd + τ_f·sign(tau_cmd)) / kv`

| 來源 | v3.3（速度空間） | v3.4f（力矩空間） |
|---|---|---|
| 週期族（平移／原地轉） | `blend(tau) / KV_WHEEL` | `blend(tau)` 直接用（錄檔 τ 原值） |
| 輪行族（直走／弧線） | `wheel_cmd()` 的 v_des | `τ = G_w · (v_des − v_meas)`，`G_w` 由 G0 掃，起點 1.0（＝現在 kd 1.0 的等效行為） |
| RL 殘差 | `WHEEL_RES = 2.0` rad/s | `WHEEL_RES = 2.0` **N·m**（數字不變、單位換） |
| 死區 | `\|v_des\| < 0.3` | `\|tau_cmd\| < 0.13`（τ_f） |

- `_ctrl()` 要多收實測輪速 → 變成 **50 Hz 外環**（實機 M9 推論也是 50 Hz，一致；原廠必然也有外環，只是沒錄到）。
- `KV_WHEEL` 常數改由模型讀（`self.kv_wheel` 已經存在），不再寫死 1.0。
- obs 的 `c["wheel"] / 5.0` 那格單位跟著變（現在是 rad/s，改後是 N·m）→ 正規化除數重定，測試要跟。

## 4. 撓度重掃（36 → 72 mm）

M8 實機：kp 250 撓度 36 mm、**kp 120 撓度 72 mm**（模擬對撓度系統性高估，kp 越低偏越多）。
以下常數全部是為 kp250 調的，一個都不能留：

| 常數 | v3.3 值 | 處理 |
|---|---|---|
| `Z_SAG` | 0.036 | 掃，起點 0.072 |
| `NOMINAL_HEIGHT` / `_settled_qpos` 的 assert | 0.54 / (0.42, 0.60) | 先量站定高度再定 |
| `lat_cmd_gain` | 1.5 | 掃（命令放大倍率，kp 軟了倍率應該降） |

| `step_hz_turn/lat`、`duty_turn/lat`、`lift`、`lift_lat` | 1.8/2.1、0.5/0.7、0.035/0.025 | 重掃（L 報告：2.5 Hz 配 25 mm 在 kp250 下做不到；kp120 更軟，窗口可能反而開了） |

## 6. 程式形式：`DualModeEnv(gains=...)`

`gains="kp250"`（預設，＝ v3.3）或 `"factory"`。切四樣：

1. `scene`：`SCENE_V3` → `SCENE_V3F`
2. `domain_randomize` 的 `_KP_NOM`（`mm.KP3_A` → `mm.KP3`）與 kv 標稱值
   —— 現在是模組級 `_KP_NOM_j`，要改成由 sys 讀或由 factory function 帶入
3. `REF` 疊 `REF_FACTORY` overlay（§4 掃出來的值）
4. `self.err_bar12`（§5）

**v3.3 預設路徑必須逐位元不變**，測試釘住：同 seed 下 `gains="kp250"` 的 `reset`/`step` 輸出與改動前相同。

notebook：`notebooks/build_nb_v3.py` 加 `--gains factory` → 產 `cpg_rl_v3_4f_colab.ipynb`
（`DualModeEnv(gains="factory")`、`eval_env` 同步、其餘超參數同 v3.3）。

## 7. 驗收順序

1. **`replay_factory` 回歸**：改用新的 v3f 模型 ＋ 新的力矩空間控制律再跑一次，
   對 v3.1 spec §8.1 的舊數字（原地轉偏航比 0.52–0.76、弧線 0.42–0.52、fwd 輪速比 1.08–1.13）。
   目的是確認力矩空間這條路沒把已驗證的東西弄壞。**不過就不往下走。**
2. **G0 六指令開迴路掃** → 定 §4 常數，輸出 `outputs/g0_v34f_final.txt`。
   ⚠️ **若 G0 連站都站不穩，這版就停在 G0，不上 Colab**（§8 風險 1）。
3. **Colab 2 億步**，停損同 v3.3：1 億步時「進度 yaw < 3.5 或 len < 600」→ 停。
4. **對標** `outputs/ref_gait_dataset.md`：roll std／峰、偏航率、速度、膝／髖／ABAD 力矩峰值與 RMS、抬腳高度。
   原廠數字：膝 τ 峰 28–38、髖 17–26、ABAD 40–60 N·m、roll std 0.5–1.1°、平移速度 0.3–0.5 m/s。
   **這版的力矩應該要比 v3.3 更接近原廠**（同命令下 kp 減半、kd 減半），是這條線最直接的檢驗點。

## 8. 風險與備案

1. **kp 120 配 41 kg「沒有可用窗口」是 trip16／E 報告的結論，但那是配運動學命令。**
   這版改配原廠大幅命令，成不成立要 G0 才知道。
   備案：停在 G0，把 G0 數字寫成結果文件（「原廠增益在我們的模擬器裡站不住」本身就是一個結論），不上 Colab。
2. **輪 kd 0.1 讓輪子幾乎自由滾**，可能在直走時追不上指令速度（外環 `G_w` 在 50 Hz、
   內環只有 0.1）。G0 第 2 步要專門看直走 0.17–0.73 m/s 的追蹤。
   備案：`G_w` 往上調，或退回 `kv=1.0` 只留腿照原廠。
3. **`TAU_BAR` 失效**（§5）：RL 可能學出力矩很大但護欄不罰的動作。
   若訓練中 `tau_pk` 明顯超過原廠的 40–60，把 `TAU_BAR` 往下調到 35–40 重訓。

## 9. 上機（不在本次範圍，另開 spec）

這版若訓出來要上狗，**三條 M9 沒驗過的路徑要一起改**：
1. 實機腿增益 250 → 120（trip17／19 走的是 250 / kd 5.0）
2. M9 誤差護欄 0.45 rad → ABAD 要放寬（原廠 ABAD 命令差本來就到 1.02 rad）
3. 實機輪 kd 0.5 → 0.1 ＋ 力矩前饋

三條都動等於整個安全網重做，**不能沿用 v2.3 的上機 SOP**。
