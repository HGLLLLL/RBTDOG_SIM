## 1. 這個專案在做什麼

在電腦模擬裡，讓一隻**宇樹 Go2 四足機器狗**走路，並用感測器讓牠**走直線、走正方形不會歪掉**。整個專案分三階段：

| 階段 | 目標 | 狀態 |
|---|---|---|
| 任務 1 | 建好模擬環境，把 Go2 模型載進 MuJoCo | ✅ |
| 任務 2 | 讓機器狗在環境裡走路 | ✅ |
| 任務 3 | 加 9 軸 IMU（含電子羅盤），做航向校正走直線/正方形 | ✅ |

### 為什麼要「自己寫走路」？

你可能會想：宇樹官方不是有走路功能嗎？**在模擬裡沒有**，原因有三：

1. **原廠的走路（Sport Mode）只跑在真機**內部的控制器上，模擬環境裡沒有對應模組。
2. **四足沒有現成、可下載的走路 AI 權重**（宇樹開源的預訓練只有人形機器人 G1/H1）。
3. 用**強化學習（RL）自己訓練**需要 NVIDIA GPU，這台電腦是 Intel 內顯、沒有 CUDA，不方便訓練。

所以本專案的策略是：**自己用數學寫一個步態控制器**（不需訓練、純 CPU 就能跑）。這件事聽起來難，但拆開後其實是「節拍器 + 幾何 + 彈簧」三件事，第 6 章會完全講白。

## 2. 先建立直覺：五個核心問題

在鑽進細節前，先用一句話回答五個大哉問，建立全局地圖：

1. **狗怎麼動？** → 它有 12 個馬達（關節），我們每 1/500 秒算一次「每個馬達該出多少力」，送給物理引擎。
2. **怎麼決定該出多少力？** → 先決定「每隻腳掌此刻該在哪」（步態節拍），換算成關節角度，再用「PD 控制」把馬達推向那個角度。
3. **怎麼知道自己面朝哪？** → 機身裝了 IMU，裡面的磁力計等於電子羅盤，可以量「航向角」。
4. **怎麼走直不歪？** → 比較「目標方向」和「羅盤量到的方向」，用比例控制把差別轉回來（像騎腳踏車一直微調龍頭）。
5. **怎麼不會倒？** → 沒有主動平衡；靠腿的彈性、低重心、對稱步態被動地撐住（第 9 章詳述）。

## 3. MuJoCo 是什麼（從零開始）

### 3.1 一句話定義

**MuJoCo 是一個「物理引擎」**——你給它一個機器人的描述（有哪些部件、關節、馬達），它就能算出「施力之後，下一瞬間各部件會怎麼動」。可以把它想成**一個很精準的 3D 物理沙盒 + 遊戲引擎**，專門給機器人研究用。它由 Google DeepMind 維護，用 `pip install mujoco` 就能裝，我們用它的 Python 版。

### 3.2 兩個最重要的物件：`model` 與 `data`

這是 MuJoCo 的核心觀念，務必記住：

| 物件 | 是什麼 | 比喻 |
|---|---|---|
| `model`（mjModel） | **不會變的設定**：有幾條腿、關節長度、質量、馬達上限… | 遊戲的「地圖檔／角色設定」 |
| `data`（mjData） | **會隨時間變的狀態**：現在各關節角度、速度、位置… | 遊戲的「當前存檔」 |

程式裡長這樣：

```python
import mujoco
model = mujoco.MjModel.from_xml_path("scene.xml")  # 讀設定
data  = mujoco.MjData(model)                       # 建立狀態
```

### 3.3 狀態怎麼存：`qpos` 與 `qvel`

機器人「現在長什麼樣」全存在兩個陣列裡：

- **`data.qpos`**：所有「位置」自由度（關節角度、身體位置）。
- **`data.qvel`**：對應的「速度」。

我們這隻 Go2 的實際數字（**已用程式驗證**）：`nq=19`（qpos 長度）、`nv=18`（qvel 長度）、`nu=12`（馬達數）。qpos 的排列是：

```
qpos[0:3]   身體在世界中的位置 (x, y, z)          ← 「浮動基座」的位移
qpos[3:7]   身體的姿態，用「四元數」表示 (w,x,y,z)  ← 朝向
qpos[7:19]  12 個關節的角度                        ← 4 腿 × 3 關節
```

> **為什麼位置有 7 個數但速度只有 6 個？** 因為姿態用 4 個數的四元數表示（位置維度），但旋轉速度只需要 3 個數（角速度）。所以 `nq=19` 但 `nv=18`。這就是為什麼程式裡關節角度是 `qpos[7:19]`、關節速度卻是 `qvel[6:18]`——差一格就是這個原因。

**「浮動基座（floating base）」**：機器狗不像機械手臂被鎖在桌上，它整個身體可以在空間中自由移動旋轉，所以身體本身就有 6 個自由度（3 平移 + 3 旋轉），這叫浮動基座。

### 3.4 馬達（致動器 actuator）

Go2 的 12 個關節各有一個馬達。**重點：這些是「力矩致動器」**——你只能命令「給這個關節多少力矩（扭力）」，**不能**直接命令「轉到 45 度」。命令寫在 `data.ctrl` 裡：

```python
data.ctrl[:] = 我算出來的12個力矩
```

這 12 個馬達的名字和力矩上限（驗證過）：

```
FL_hip/thigh/calf, FR_..., RL_..., RR_...
力矩上限：hip 23.7 Nm、thigh 23.7 Nm、calf 45.43 Nm
（FL=左前 Front-Left, FR=右前, RL=左後 Rear-Left, RR=右後）
```

> **為什麼是力矩而不是角度？** 因為真實 Go2 的馬達底層就是控制電流/力矩。用力矩控制比較貼近真實硬體；想控角度就得自己補一層轉換（第 6 章的「PD 控制」）。

### 3.5 感測器（sensor）與掛載點（site）

MuJoCo 可以在模型上加感測器。感測器通常掛在一個 **site**（一個看不見的參考點，像「貼紙」貼在某個部件上）。我們在機身的 `imu` site 上掛了加速度計、陀螺儀、磁力計等（第 7 章）。讀值從 `data.sensordata` 拿。

### 3.6 讓時間前進：`mj_step` 與 `mj_forward`

兩個最常用的函式，差別要搞清楚：

- **`mujoco.mj_step(model, data)`**：**推進一個時間步**。它會讀 `data.ctrl` 的力矩、算物理、更新 `qpos/qvel`、時間 +Δt。我們的 Δt = **0.002 秒（即 500 Hz）**。走路就是「算力矩 → mj_step → 再算 → 再 step」不斷重複。
- **`mujoco.mj_forward(model, data)`**：**只算「幾何/運動學」，不推進時間**。給定關節角度，算出各部件在世界中的位置。用來做「正運動學查詢」（第 6 章建雅可比會用到）。

## 4. 機器狗運動學基礎

「運動學（kinematics）」＝研究「關節角度」和「身體/腳掌位置」之間的幾何關係，**不管力，只管幾何**。

### 4.1 關節與自由度

Go2 每條腿有 **3 個關節**（3 個自由度）：

| 關節 | 別名 | 作用 |
|---|---|---|
| **hip** | 髖（外展/內收） | 讓整條腿往身體外側/內側擺（左右） |
| **thigh** | 大腿（髖屈伸） | 讓腿往前/後、往上抬（前後） |
| **calf** | 小腿（膝） | 彎曲小腿 |

4 腿 × 3 = **12 個關節**。站立標準姿勢（專案用的 keyframe，驗證過）每條腿都是：

```
hip = 0.0,  thigh = 0.9,  calf = -1.8   (單位：弧度 rad)
```

### 4.2 弧度、座標與四元數

- **弧度（radian）**：角度單位。180° = π ≈ 3.14 rad，90° ≈ 1.57 rad。程式裡角度幾乎都用弧度。
- **世界座標**：x 通常朝前、y 朝左、z 朝上（本專案走直線目標是沿 +x）。
- **四元數（quaternion）**：用 4 個數 (w, x, y, z) 表示 3D 旋轉/朝向。為什麼不用大家熟的「歐拉角（roll/pitch/yaw）」？因為歐拉角有「萬向鎖」等數值問題，四元數更穩。**但四元數不直觀**，所以我們常把它轉成 yaw（航向角）來用。

### 4.3 從四元數取出「航向 yaw」

航向（yaw）= 身體繞垂直軸（z）轉了多少，就是「面朝哪個方向」。從四元數 (w,x,y,z) 算 yaw 的公式（程式 `true_yaw()` 就是這個）：

```
yaw = atan2( 2(wz + xy),  1 − 2(y² + z²) )
```

`atan2` 是「考慮象限的反正切」，能正確回傳 −180°~+180° 的角度。

### 4.4 正運動學 vs 逆運動學（超重要）

| | 輸入 → 輸出 | 難度 | 比喻 |
|---|---|---|---|
| **正運動學 (FK)** | 關節角度 → 腳掌位置 | 簡單、唯一解 | 「手肘彎 30°、肩膀抬 45°，手會在哪」 |
| **逆運動學 (IK)** | 想要的腳掌位置 → 該轉的關節角度 | 較難、可能多解 | 「我要摸到那個杯子，關節各要轉幾度」 |

走路時我們知道「腳掌想去哪」，需要反推「關節該轉幾度」→ 這是 **IK**。本專案用一個聰明又簡單的 IK 做法（第 6.4 節）。

## 6. 走路是怎麼實作的（最重要的一章）

走路控制器全部在 `go2_gait.py`。它**沒有用任何走路/AI/控制的 library**，只 import 了 `numpy`（數學）和 `mujoco`（物理）。整個走路 = 四個步驟每 1/500 秒跑一次：

```
① 節拍器決定「每隻腳掌此刻該在哪」   （CPG 步態）
② 把腳掌位置換算成關節角度            （逆運動學 IK）
③ 把關節角度用「力矩」實現            （軟體 PD）
④ mj_step 前進一步 → 腳動了、身體被推著往前
```

### 6.1 什麼是 CPG 與 trot 步態

**CPG（中央模式產生器）**：生物走路的節律是由脊髓的一個「節拍產生器」驅動的。我們模仿這個概念，用一個**隨時間前進的相位（phase）**當節拍器，驅動四條腿週期性擺動。

**trot（對角小跑）**：四足最穩的基本步態之一。**對角線的兩隻腳同一拍**：左前(FL)+右後(RR) 一組、右前(FR)+左後(RL) 一組，兩組差半拍交替。程式裡：

```python
LEG_PHASE = {"FL": 0.0, "RR": 0.0, "FR": 0.5, "RL": 0.5}  # 差 0.5 = 半拍
```

每條腿的相位 = `頻率 × 時間 + 該腿的相位偏移`。一個週期分成兩半：

- **站立相（stance）**：腳掌**貼地**、由前往後推 → 把身體往前推進。
- **擺動相（swing）**：腳掌**抬起**、由後往前擺回去，準備下一次踩地。

### 6.2 腳掌的軌跡（手寫的橢圓）

`_foot_traj()` 決定腳掌在腿的「側視平面」上走的路徑（x=前後、z=上下）：

```python
def _foot_traj(self, phase, stride_leg):
    ph = phase % 1.0                       # 取這一拍的進度 0~1
    if ph < self.duty:                     # 站立相：貼地由前往後
        s = ph / self.duty
        x = stride_leg * (0.5 - s); z = 0.0
    else:                                  # 擺動相：抬起由後往前
        s = (ph - self.duty) / (1 - self.duty)
        x = stride_leg * (-0.5 + s)
        z = self.lift * np.sin(np.pi * s)  # 用 sine 抬腳、再放下
    return x, z
```

- `stride`（步幅）：一步跨多遠。
- `duty`（站立相佔比）：一個週期裡腳貼地的比例。trot 約 0.5~0.6；**越大支撐越久、越穩**。
- `lift`（抬腳高度）：擺動時抬多高。

### 6.3 本專案調校後的步態參數（含由來）

```python
GAIT = dict(freq=2.6, duty=0.60, lift=0.12, stride=0.32, kp=90, kd=3.0, turn_gain=0.18)
```

| 參數 | 值 | 意義 |
|---|---|---|
| freq 步頻 | 2.6 Hz | 每秒踏 2.6 拍 |
| stride 步幅 | 0.32 m | 一步跨 0.32 公尺 |
| duty 站立佔比 | 0.60 | 腳貼地時間佔 60% |
| lift 抬腳 | 0.12 m | 擺動抬 12 公分 |
| kp / kd | 90 / 3.0 | PD 的剛度/阻尼（見 6.5） |
| turn_gain | 0.18 | 轉彎用的左右差動量 |

**調校故事（很有教育意義）**：一開始步頻高、步幅短（3.5Hz/0.24m），走起來像「碎步」又慢；把步幅拉長速度變快，但身體開始**左右搖晃**（trot 天生會往無支撐的對角傾）；最後折衷成上表——步幅適中、站立久、抬腳低——**側傾減少約 46%、垂直彈跳減少約 24%**，速度約 **0.89 m/s**。這說明：**沒有主動平衡時，穩定度完全由這些被動參數決定**（第 9 章）。

### 6.4 逆運動學：用「數值雅可比」反解（本專案的巧思）

我們要把「腳掌目標 (x,z)」換成「大腿/小腿角度」。這裡不套現成 IK，而是用**數值雅可比**：

**雅可比（Jacobian）**：描述「關節角度動一點點 → 腳掌位置動多少」的比例矩陣。概念像「斜率」的多維版本。

做法（`_calc_ik()`，只在啟動時算一次）：

1. 在站立姿勢下，把 thigh 角度動 ±ε（很小的量），用 `mj_forward` 看腳掌 (x,z) 變多少 → 得到雅可比的第一欄。
2. 同樣對 calf 動 ±ε → 第二欄。組成 2×2 雅可比 `J`。
3. 求反矩陣 `J⁻¹`。

之後每一步（`targets()`）：`關節角度變化 = J⁻¹ × 腳掌位置變化`。這是把 IK「線性化」在站姿附近——**簡單、夠快、夠準**（代價：步幅太大就會不準，這也是為何步幅不能拉太大）。

### 6.5 軟體 PD：把「角度」變成「力矩」

有了「目標關節角度」，但馬達只吃力矩，所以自己補一個 **PD 控制器**（`step()`）：

```python
tau = self.kp * (qdes - self.d.qpos[7:19]) - self.kd * self.d.qvel[6:18]
self.d.ctrl[:] = np.clip(tau, -self.flimit, self.flimit)   # 截到馬達力矩上限
mujoco.mj_step(self.m, self.d)                             # 前進一步
```

直覺：**在每個關節裝一個「虛擬彈簧 + 阻尼器」**。

- `kp × (目標角 − 目前角)`：像**彈簧**，離目標越遠、拉力越大。
- `−kd × 角速度`：像**阻尼器**，動太快就踩剎車，避免震盪。

這個「彈簧」不只讓關節跟上目標，也順便撐住身體、提供被動平衡（第 9 章）。

### 6.6 轉彎

不用多複雜——**左右腿給不同步幅**就會轉：

```python
stride_leg = self.stride * v_cmd + SIDE[leg] * self.turn_gain * turn_cmd
#            └ 前進成分 ┘         └ 左右差動（轉彎）成分 ┘
```

`turn_cmd` 從 −1（左轉）到 +1（右轉）。校準後：`turn=+1` 原地約 **58.7°/s** 右轉。

## 7. 感測器與航向：IMU 與電子羅盤

### 7.1 9 軸 IMU 是什麼

**IMU（慣性量測單元）** 是機器人的「內耳+指南針」。「9 軸」= 三種各 3 軸的感測器：

| 感測器 | 量什麼 | 類比 |
|---|---|---|
| 加速度計 (accelerometer) | 加速度（含重力方向） | 感受「哪邊是下」 |
| 陀螺儀 (gyro) | 角速度（轉多快） | 感受「正在轉」 |
| 磁力計 (magnetometer) | 磁場方向 | **電子羅盤**，感受「北在哪」 |

程式用 MuJoCo 的 `MjSpec` 把這些掛到機身 `imu` site（`go2_model.py`）。

### 7.2 從磁力計算航向

磁力計量到磁場向量，投影到水平面就能算航向。最基本的公式（保留在 `mag_yaw()`）：

```
yaw = atan2(−mag_x, −mag_y)
```

### 7.3 進階：模擬真實感測器 Xsens MTi-680G 的「融合航向」

**這是本專案航向的實際來源**（`compass_yaw()`）。真實高階裝置（如 Xsens MTi-680G）**內部已經把陀螺/加速度/磁力計融合**後才輸出航向，比裸磁力計穩得多。所以我們不直接用磁力計，而是**模擬它的融合輸出**：

```
量測航向 = 真實航向 + 慢速零偏(Gauss-Markov) + 白噪 →  合成 RMS ≈ 0.5°（規格值）
```

- **RMS 0.5°**：規格書說航向誤差的「典型大小」約 0.5°。
- **慢速零偏**：像羅盤有個「慢慢飄」的偏差，這一刻和下一刻幾乎一樣、但幾十秒尺度會漂（用 Gauss-Markov 過程模擬，時間常數 τ=20s）。
- **白噪**：每一瞬間都不同的小抖動。
- 兩者用「平方和開根號」合成到 0.5°（零偏約占 0.9、白噪補足）。

> **為什麼要這麼講究？** 因為真實感測器不完美。若用「完美航向」，校正效果會好得不真實。加上這個誤差模型，實驗結果才可信。

## 8. 航向校正的邏輯

### 8.1 核心：一個比例 (P) 控制器

「走直不歪」的關鍵就這一行（`walk_line.py`）：

```python
turn = np.clip(COMPASS_GAIN * wrap(compass_yaw() - target), -1, 1)
```

白話：**「現在方向」和「目標方向」差多少，就按比例轉多少回去。** 差越多、轉越急；差歸零、就不轉。像騎腳踏車時眼睛盯著遠方，一直微調龍頭。

- `COMPASS_GAIN = 4.0`：比例增益（Kp）。換算：每偏 1° 給約 0.07 的轉彎指令；偏超過約 14° 就給到最大轉（±1）。
- `wrap(...)`：把角度差包進 −180°~+180°，避免「差 350°」被當成大誤差反向猛轉。
- `clip(..., -1, 1)`：限制轉彎指令範圍。

> 注意：這個 `COMPASS_GAIN`（航向層，純 P）和第 6.5 節關節 PD 的 `kp`（關節層）**是不同層的兩個增益**，別搞混。這叫「串級（雙層）控制」：外層看羅盤決定「要轉多少」，內層 PD 把它落實成馬達力矩。

### 8.2 兩個對照版本：開環 vs 閉環

為了凸顯感測器的價值，每個實驗都做兩版：

| 版本 | 做法 | 結果 |
|---|---|---|
| **V1 開環（無 IMU）** | 完全不看感測器，靠「時間」推算走多久、轉多久（**航位推算 dead-reckoning**） | 誤差隨時間累積、越走越歪 |
| **V2 閉環（IMU 羅盤）** | 用上面的 P 控制即時修正方向 | 方向不累積誤差、走得直 |

**航位推算（dead-reckoning）**：不看感測器、純靠「速度 × 時間 = 距離」「角速度 × 時間 = 角度」來估計走了多遠、轉了多少。任何微小偏差都會累積放大——這正是 V1 會歪掉的原因，也是感測器校正的價值所在。

## 9. 這隻狗如何保持平衡

**重要觀念：這隻狗沒有「主動平衡控制器」。** 它靠**被動自穩**。

回顧 PD 那行，回授的只有「12 個關節自己的角度/速度」，**身體的傾斜（roll/pitch）完全沒有回授**。沒有「偵測快倒了 → 跨步救回」這種反射。那為什麼不倒？三個被動機制：

1. **關節 PD = 虛擬彈簧**：身體被推歪時，支撐腿的關節角偏離目標 → PD 立刻產生「把身體推回原姿勢」的回復力矩。等於**站在四根彈簧腿上**，推它、腿頂回來。
2. **低重心 + 對稱 trot**：重心低、對角輪流支撐、左右對稱，正常走時擾動互相抵消。
3. **持續踏步 + 慣性**：腳不斷重新踩地重建支撐，加上身體慣性，短暫擾動來不及推倒它。

**被外力推時（走直線實驗，±35N 推 0.5 秒）**：它**不做主動反應**，靠上面三點硬扛過去（35N 約是體重 15kg≈147N 的 1/4，推得歪但推不翻）。你會看到身體晃一下，然後**羅盤事後只把「方向」轉回**——羅盤修的是航向、不是平衡；站穩是被動撐住的。

> **誠實的邊界**：若推得更大力或更久，它會直接倒——沒有「跨步救回」的能力。要真正抗擾平衡，得再加「用 IMU 姿態回授即時調整落腳點」的平衡控制器，那是更進階的主題。

## 12. 怎麼看懂結果

### 走直線（`line_result.png`）

- 橫軸 x = 前進距離，縱軸 y = 橫向偏移（理想應保持 0）。
- **V1（紅線）**：被外力推歪後回不來，終點漂到 **y ≈ +14.0 m**。
- **V2（藍線）**：每次被推只小凸一下就回正，終點 **y ≈ +0.24 m**。

### 走正方形（`square_result.png`）

- 左圖軌跡：**V2（藍）** 5 圈疊成乾淨方形、回到起點；**V1（紅）** 散成亂麻。
- 右圖航向：V2 緊貼目標階梯、V1 持續累積偏差。
- **終點誤差**（終點離起點多遠）：V1 **7.87 m** vs V2 **0.04 m**（改善約 206 倍）。

### 一個必須理解的限制：只準「方向」、不準「位置」

羅盤只能量「朝向」、量不到「位置」，所以校正只鎖**方向**、不鎖**位置**：

- 走直線被推歪後，V2 只是把「朝向」轉回 +x，之後沿一條**平行但有點平移**的線繼續走——所以終點 y 是 0.24m 而非 0。
- 走正方形形狀方正（方向準），但每條邊長度靠時間推算會略短，方形比理想的 10×10 稍小。

要連「位置」也準，得再加位置估測 + 位置控制（例如用 MTi-680G 的 RTK 位置），那是後續延伸。

## 13. 常見踩雷與除錯

| 症狀 | 原因 / 解法 |
|---|---|
| 渲染/存影片報 EGL 錯或無畫面 | 忘了加 `MUJOCO_GL=egl`；離屏 framebuffer 上限 **640×480**，別設更大 |
| 直接改 XML 加感測器→網格路徑錯 | 用 `MjSpec`（見第 10 章） |
| 換了步態參數後，正方形 V1 亂掉 | V1 靠「標稱速度/角速度」推算，換步態要**重新校準** `NOMINAL_SPEED`（0.892）、`NOMINAL_YAWRATE`（58.7°/s） |
| 狗一直原地抖/站不穩 | 步幅太大、kd 太小、或 IK 線性化失準；縮步幅、加 duty、加 kd |
| 程式結束時跳一堆 EGL 錯誤訊息 | 那是直譯器退出時的清理雜訊，**無害**，可忽略 |
| GUI viewer 在背景 shell 開不起來 | 背景 shell 沒有螢幕（DISPLAY）；GUI 要在你自己的桌面終端機開 |
