## 0. 三個名詞的直覺

- **CPG（中樞模式產生器）**：生物脊髓裡會自動產生走路節律的迴路。機器人裡＝一個會自動產生「平順、週期、左右協調」擺腳節奏的數學振盪器。大腦（高階）只要調它的快慢、大小。優點：動作天生平順、可解釋。
- **RL（強化學習）**：讓機器人「自己試錯學會做事」。不教它每一步，只給「評分規則」（獎勵函數），它在模擬器走幾億步，好行為高分、跌倒低分，學出一個「看狀況下指令」的神經網路（策略 policy）。優點：能學出應變力（抗推、變滑、負重）。
- **為什麼合起來（Hybrid）**：
  - 純 CPG：平順但**不會應變**（不看回饋，被推就垮）。
  - 純 RL（直接輸出 12 顆馬達角）：會應變但**難訓練、動作鬼畜、要大 GPU**。
  - **CPG+RL**：CPG 出平順骨架，RL 只調幾個旋鈕。→ 好訓練 + 平順 + 有應變力。

## 1. 那篇論文

**Bellegarda & Ijspeert, "CPG-RL" (2022)**，arXiv:2211.00458。

核心主張：**RL 不直接控關節，而是去控「一組 CPG 振盪器的參數」。**

1. 每條腿一個振盪器（四足＝4 個）。每個有：振幅 r（跨多大步）、相位 θ（一直在轉的時鐘指針，決定抬腳/踩地階段）。
2. RL 動作＝給每個振盪器的旋鈕（目標振幅 μ、頻率 ω、側向振幅）。
3. 振盪器把「振幅+相位」→ 腳掌空間位置 → 逆運動學 → 關節角 → 馬達。
4. 腿間耦合（Kuramoto）讓四個振盪器對時、鎖 trot。論文發現：**關掉耦合，RL 能自己學出 trot**——步態是學出來的。
5. 訓練加大量干擾（domain randomization：摩擦/推撞/負重）→ 耐操、可 sim-to-real。

意義：訓練快、穩、能追指令速度、換步態、抗干擾，兼具可解釋骨架與學習應變力。

## 2. 我們如何從純 CPG 演進到 CPG+RL

### 2-1 出發點：task3 純 CPG（本質是開迴路節律控制器）
- 相位＝頻率×時間+固定偏移 → **照表操課，完全不看回饋**。
- 預算橢圓腳掌軌跡 + 站姿附近固定 Jacobian 做 IK + 軟體 PD。
- 嚴格說還不是論文那種「有狀態、會耦合」的振盪器，比較像「照節拍器擺腿」。
- **問題**：地面變/被推/負重毫無應變；參數靠人工調；走直線要靠外掛羅盤硬拉。

### 2-2 過渡：研究四種 hybrid（CPG+RL / Residual RL / MPC+RL / 模仿），選 CPG-RL
理由：最能重用 task3 既有的腳掌軌跡、IK、PD，改動最小、風險最低。

### 2-3 關鍵改造：只換「時鐘」那一塊
> **不打掉重練。保留 IK 和 PD，只把「固定時鐘」換成「RL 可調的振盪器」。**
- 原本：相位＝頻率×時間（寫死）。
- 現在：相位由真正的振盪器演化，振幅與頻率**每 0.02 秒由 RL 依當下身體狀態重算一次**。
- → 被推/地面變，網路即時調「哪條腿擺大、擺快」，應變力就這樣加進來。

### 2-4 分兩階段落地
**第一階段 5 維起步版（POC）**：動作 5 維（4 振幅+1 共用頻率）。先打通「Colab 訓練→本機推論」工具鏈。結果成功（0.57 m/s、不跌倒），但**腳會拖地**（抬腳綁振幅+獎勵沒鼓勵抬腳→學成貼地滑行）。

**第二階段 論文標準版（對齊 Bellegarda 2022）**：
- 動作擴 12 維（每腿 μx 前後、μy 側向、ω 頻率）。
- 腳掌 2D（含側向，用髖外展）。
- 加腿間耦合振盪器鎖 trot。
- **抬腳改固定常數 g_c（不乘振幅）→ 結構上根除拖地**（腿一擺就強制抬固定高度，偷懶不了）。
- 結果成功且更好：加干擾走 10m 只偏 2cm、腳抬約 4.6cm、扛住側推。

**演進一句話**：從「照節拍器擺腿、不看回饋、會拖地」→「RL 每 20ms 看回饋調振盪器、耦合鎖步態、結構上不拖地、能抗干擾」。

## 2.5 CPG 產生器三方對照（task3 純 CPG / 論文 / task4 你的 CPG-RL）

> 前面比的是「RL 包裝層」。這節專門比 **CPG 產生器本身（振盪器核心）**，承接 task3→task4 的脈絡。
> 注意「你的 CPG」有兩個版本：task3 你最早自寫的、task4 對齊論文的。

### 核心方程式骨架

**task3 純 CPG（`go2_gait.py`）——其實不是真振盪器，是「時鐘」：**
```
相位：ph = freq·t + 固定偏移        ← 沒有狀態，時間的線性函數
步幅：stride_leg = stride·v_cmd     ← 常數，不會演化
腳掌：站立相 x=stride(0.5−s), z=0
      擺動相 x=stride(−0.5+s), z=lift·sin(πs)
```

**論文 CPG（Bellegarda 2022，eq 1/2/6-8）——真振盪器：**
```
振幅(二階)：r̈ᵢ = a(a/4·(μᵢ−rᵢ) − ṙᵢ)               ← 有狀態，收斂到 μ
相位：      θ̇ᵢ = ωᵢ + Σⱼ rⱼ·wᵢⱼ·sin(θⱼ−θᵢ−φᵢⱼ)    ← 帶腿間耦合(但論文設 wᵢⱼ=0)
腳掌：      xᵢ = −d_step(rᵢ−1)cosθᵢ·cosφᵢ
            yᵢ = −d_step(rᵢ−1)cosθᵢ·sinφᵢ           ← 用一個方向角 φ 轉整條軌跡
            zᵢ = −h + g_c·sinθᵢ  (擺動相)
```

**task4 你的 CPG（`cpg_rl_paper_colab.ipynb`）——真振盪器，對齊論文：**
```
振幅(二階)：r̈ = a(a/4·(μ−r) − ṙ),  a=50            ← 與論文同形式
相位：      θ̇ᵢ = 2π·ωᵢ + W_coup·Σⱼ r̄ⱼ·sin(θⱼ−θᵢ−Φᵢⱼ)  ← W_coup=8 硬編碼 trot
腳掌：      dx = −D_step·fx·cosθ,  fx=2(rx−1)−1
            dy =  D_step·fy·cosθ                    ← 用獨立的 rx,ry 兩振幅
            dz = g_c·sinθ (擺動), g_p·sinθ (站立)
```

### 三個最關鍵的差異（挑這三個講）

**① task3 你的 CPG 根本不是真 CPG——是「照時鐘擺腿」。**
相位是 `freq·t`，沒有內部狀態、不會演化、不看回饋。學術上真正的 CPG（論文那種）是「一組有狀態、會互相耦合的非線性振盪器」。所以 task3 叫「CPG」是借用名詞，實質是 open-loop 步態產生器。**task4 才升級成論文定義下的真振盪器**（有 r̈ 二階動力學、有 θ 狀態、有耦合）。

**② 你 task4 的 CPG 跟論文的 CPG 幾乎同構，只有兩處刻意偏離：**
- **側向做法不同**：論文用「一個方向角 φ（由動作 ψ 控制）旋轉整條腳掌軌跡」；你用「兩個獨立的直角振幅 rx、ry」。維度都是每腿 3 個、精神一致，但你的做法跟 task3 的數值 Jacobian 天然對接、好寫對。
- **耦合處理相反**：論文**移除耦合(wij=0)**，賭 RL 自己把四腿協調成 trot（成功了，論文亮點）；你**硬編碼 W_coup=8 鎖 trot**，換取 Colab 有限算力下更快更穩收斂。你**另做了 W_coup=0 忠實版**保留論文路線。

**③ 三者「智能程度」遞進：**
task3＝參數全人工死調、不看回饋 → 論文/task4＝振盪器骨架固定、關鍵參數（振幅/頻率）交給 RL 依即時狀態調。你的 task4 站在論文肩膀上，把「你原本的 IK+PD」接到「論文的振盪器核心」上。

**一句話**：task3 的「CPG」是照時鐘擺腿的開迴路產生器、非學術定義的 CPG；task4 才把核心換成論文那種有狀態、二階動力學的真振盪器，且與論文幾乎同構——只在「側向用兩直角振幅而非一方向角」與「硬鎖 trot 耦合而非讓 RL 自學」兩處刻意簡化，後者另留了完全照論文的無耦合版。

## 3. 模型原理 / 訓練 / 輸入輸出

### 3-1 一步的資料流（每 0.02 秒＝50Hz）
```
① 感測器讀狀態 → ② 組 76 維觀測 → ③ 策略網路 → ④ 輸出 12 維動作(每腿 μx,μy,ω)
→ ⑤ CPG 振盪器演化振幅+相位 → ⑥ 換算 4 腳掌目標位置(含抬腳) → ⑦ 逆運動學→12 關節角
→ ⑧ 軟體 PD→12 馬達力矩 → ⑨ 物理前進一步 → 回 ①
```
**重點**：網路只做 ③④（下高階旋鈕），⑤⑥⑦⑧ 是寫死的可解釋數學＝CPG 的安全骨架。所以動作永遠平順。

**④→⑤→⑥ 具體數值走一遍**（以左前腳 FL 為例，看 RL 的一個輸出如何變成腳掌位置）：

先列振盪器方程式（每腿一組）：
```
振幅(二階，讓 r 平滑收斂到 RL 給的目標 μ)：  r̈ = a·(a/4·(μ−r) − ṙ),  a=50
相位(時鐘指針往前轉)：                        θ̇ = 2π·ω + 耦合項
腳掌偏移(把振幅+相位換成空間位置)：
    fx = 2(rx−1)/(2−1) − 1
    dx = −D_step·fx·cos θ        (D_step=0.12 常數)
    dz = g_c·sin θ  若 sinθ>0    (g_c=0.08 常數；擺動相強制抬腳)
```

**④ RL 輸出**（FL 腳，經 tanh 縮放後）：μx=1.8, μy=1.5, **ω=2.0 Hz**。當下 rx=1.5, ṙx=0, θ=0。

**⑤ 振盪器演化一個控制步(dt=0.02s)**：
- 相位：`θ ← 0 + 2π·ω·dt = 2π(2.0)(0.02) = 0.251 rad`
- 振幅(子步 h=0.005)：`ṙx ← 50·(12.5·(1.8−1.5)−0)·0.005 = 0.938`，`rx ← 1.5+0.938·0.005 = 1.505`；跑完 4 子步 rx≈1.52，之後約 0.1s 內平滑爬到目標 1.8。
  → **二階動力學的意義：RL 給「目標振幅」，振盪器保證平滑逼近、不會瞬跳。**

**⑥ 換成腳掌偏移**（待 rx 收斂到 1.8）：
- `fx = 2(1.8−1)−1 = 0.6`
- `dx = −0.12·0.6·cos(0.251) = −0.070 m`（腳掌後移 7cm＝推進）
- `dz = 0.08·sin(0.251) = 0.020 m`（sinθ>0 是擺動相，抬腳 2cm）

於是這一步 FL 腳掌相對站姿要偏移 **(dx=−7cm, dz=+2cm)**，再進 ⑦ 逆運動學變成三顆關節角。
**RL 只決定了 μ、ω（腳擺多大、多快）；實際腳掌軌跡與抬腳高度是振盪器結構自動長出來的。**

### 3-2 輸入（觀測 Observation：76 維）= 狗的感官
| 內容 | 維度 | 意義 |
|---|---|---|
| 重力方向(身體座標) | 3 | 身體歪不歪、往哪歪（姿態） |
| 身體線速度 | 3 | 往哪、多快 |
| 角速度(陀螺儀) | 3 | 轉多快 |
| 12 關節角(減站姿基準) | 12 | 每腿彎成怎樣 |
| 12 關節角速度 | 12 | 每關節轉多快 |
| 指令 cmd | 3 | 要它做什麼：前進/側移/轉向速度 |
| 上一步動作 | 12 | 記得上步指令(連貫防抖) |
| 四腳觸地布林 | 4 | 每腳有沒有踩地 |
| CPG rx,ṙx,ry,ṙy | 16 | 振盪器振幅多大、變多快 |
| CPG sin(θ),cos(θ) | 8 | 相位指向哪(sin/cos 避免 360→0 跳變) |

- 餵 CPG 狀態給網路：網路要知道「振盪器在循環哪階段」才能決策（必要設計）。
- 指令 cmd＝方向盤：`[0.6,0,0]` 就直走 0.6m/s。訓練時隨機給各種指令→學出通用聽指令策略。

### 3-3 輸出（動作 Action：12 維）＝把純 CPG 的手調常數變成 RL 預測變數

| 旋鈕 | 範圍 | 意義 | 純 CPG(task3)怎麼給 | CPG-RL 怎麼給 |
|---|---|---|---|---|
| μx 前後振幅 | 1~2 | 前後跨多大步 | 常數 `stride`=**0.32**，四腿共用 | **RL 每步逐腿預測**(4 值) |
| μy 側向振幅 | 1~2 | 側向擺多少(平衡/轉彎) | ❌ 不存在(腳只在 x-z 平面) | **RL 每步逐腿預測**(4 值，全新) |
| ω 頻率 | 0~4.5 Hz | 擺多快(步頻) | 常數 `freq`=**2.6**，四腿共用 | **RL 每步逐腿預測**(4 值) |

**核心對照——我們具體把哪些「常數」變成「模型變數」**：純 CPG 其實沒有 12 個獨立參數，它只有 **2 個全腿共用的手調常數**：步頻 `freq=2.6`、步幅 `stride=0.32`（`go2_gait.py:86`：`ph = freq*t + 相位偏移`、`stride_leg = stride*v_cmd`）。CPG-RL 做三件事：
1. 步頻 `freq`(1 個常數) → **ω**(4 個逐腿、RL 每 20ms 預測)
2. 步幅 `stride`(1 個常數) → **μx**(4 個逐腿、RL 每 20ms 預測)
3. 新增純 CPG 沒有的側向能力 → **μy**(4 個逐腿、RL 預測)
→ 合計 4+4+4=12 維動作。

**反過來，這些原本是常數、CPG-RL 裡「刻意仍是常數」（沒交給 RL）**：

| 參數 | 純 CPG | CPG-RL | 為何不交給 RL |
|---|---|---|---|
| 抬腳高度 | `lift`=0.12 | `G_C`=0.08 | **故意鎖死**＝結構性解決拖地：RL 改不了抬腳，腿一擺就強制抬 8cm |
| 站立佔比 | `duty`=0.60 | 由 `sinθ` 正負自動切一半 | 步態骨架，不需 RL 動 |
| 步幅總尺度 | 含在 stride | `D_STEP`=0.12 | μx 只在此尺度內調整 |
| trot 相位偏移 | `LEG_PHASE`(0/0.5) | `PHASE_OFFSET`(0,π,π,0) | 寫死鎖 trot |

**不是輸出關節角度**，是輸出振盪器旋鈕。關節角由後面 CPG+IK 算。這是 CPG-RL 好訓練的根本（動作空間小、每個動作都保證合理走路）。

### 3-3-1 那 12 個參數逐一對應到什麼物理表現（被問「步長/頻率」時翻這頁）

> 常見誤解：「12 個是不是步伐長度跟頻率？」答：**對了 2/3**。實際是「前後步幅 + 側向 + 步頻」，而且是**每條腿獨立各一組**，不是全狗共用。

**12 = 4 條腿 × 每腿 3 個。** `act_to_cmd()`（`inference/local_infer_paper.py:55-60`）把 12 維動作 `reshape(4,3)`，三個 column 就是三類旋鈕：

| RL 輸出 | 動作 index（FL,FR,RL,RR）| 範圍 | 物理表現 | 對應純 CPG 的什麼 |
|---|---|---|---|---|
| **μx 前後振幅** | 0, 3, 6, 9 | 1~2 | **步伐長度**（前後跨多遠）| task3 常數 `stride`=0.32 |
| **μy 側向振幅** | 1, 4, 7, 10 | 1~2 | **側向擺動**（平衡/轉彎微調）| ❌ 純 CPG 沒有，全新 |
| **ω 頻率** | 2, 5, 8, 11 | 0~4.5 Hz | **踏步頻率**（擺多快、步頻）| task3 常數 `freq`=2.6 |

所以「步長 + 頻率」= μx（4 個）+ ω（4 個）＝ 8 個；剩下 4 個是純 CPG 沒有的側向 μy。

**三個精確細節（避免誤解）：**

**① μ 不是「步長公尺數」，是振盪器的『目標振幅』。**
RL 輸出 μx 後不會立刻變步長，而是餵給二階振盪器讓振幅 `rx` **平滑收斂**到 μx（`cpg_step` `local_infer_paper.py:47`：`rxd += A_CONV*(A_CONV/4*(mux-rx)-rxd)*h`），收斂後才在 `joint_targets`（line 65-67）換成腳掌位移：
```
fx = 2(rx−1)/(2−1) − 1          # μx=2 → fx=1(最大步)；μx=1 → fx=−1(最小)
dx = −D_STEP · fx · cos(θ)      # D_STEP=0.12 是步長的「最大尺度」上限
```
→ **RL 只在 D_STEP=0.12 這個上限內，用 μx 調「這一步用幾成步長」**。μx 越大 → rx 越大 → fx 越大 → dx 前後位移越大 → 步子越大，但經振盪器平滑化、不瞬跳。

**② ω 是相位前進速度，直接就是步頻。**
`cpg_step`（`local_infer_paper.py:51`）：`θ ← θ + 2π·ω·h + 耦合項`。ω 越大相位指針轉越快 → 抬腳/踩地循環越快 → 步頻越高。範圍 0~4.5 表示 RL 可讓某腿完全不動（ω=0）到快踏（4.5 Hz）。

**③ 有 4 個東西 RL「碰不到」——刻意鎖死（本版跟論文通則的差異點）：**

| 鎖死的參數 | 值 | 為何不給 RL |
|---|---|---|
| 抬腳高度 `G_C` | 0.08 | **結構性根除拖地**——腿一擺就強制抬 8cm，RL 想貼地偷懶也做不到 |
| 步長尺度 `D_STEP` | 0.12 | μx 只在此上限內調 |
| trot 相位偏移 `_PO` | (0,π,π,0) | 寫死鎖對角小跑步態 |
| 腿間耦合 `W_COUP` | 8.0 | 硬鎖 trot（論文版設 0 讓 RL 自學；本專案另有 nocoup 版）|

> 注意：一般 CPG-RL 文獻裡「每腿第三個參數」常是相位/抬腳；**但本專案把第三個給了側向 μy，並把抬腳高度與步態都鎖死**（見 §4-2）。所以「腳抬多高、什麼步態」在本版**不是** RL 調的。

**一句話**：RL 每 20ms 逐腿輸出「前後跨多大（μx）、側向偏多少（μy）、踏多快（ω）」共 4×3 個高階旋鈕；而「抬多高、什麼步態」被結構鎖死，不歸 RL 管。

### 4-1 觀測維度：論文不定固定值（full/med/min 三種）→ 我們用「full」實作成 76 維

### 4-2 第三個動作旋鈕：論文用 ψ（軌跡朝向）→ 我們用 μy（側向振幅）

| | 論文 | 我們 |
|---|---|---|
| 每腿 3 旋鈕 | μ(振幅)、ω(頻率)、**ψ(把整條腳掌軌跡轉一個朝向角 φ)** | μx(前後振幅)、**μy(側向振幅)**、ω(頻率) |
| 腳掌 x,y | `x=−dstep(r−1)cosθ·cosφ`、`y=−dstep(r−1)cosθ·sinφ` | x 由 μx 給、y 由 μy 獨立給 |

- **目的**：都是為了讓腳掌能在 2D 平面移動（不只前後、能側向），達成全向移動與轉彎。
- **為何這樣選**：我們的逆運動學沿用 task3 風格的**逐腿 3×3 數值 Jacobian**（直接把「腳掌 xyz 偏移」線性映射到關節角）。用 μx、μy 當「前後、側向兩個獨立的直角座標振幅」，跟這個 IK 是天然對接的——我直接得到 dx、dy 餵進 Jacobian 即可，**容易寫對、容易驗證**。論文的 ψ 是「把軌跡整條旋轉一個角度」，需要多算三角函數且較難直觀確認正負，對接我們的數值 IK 較繞。
- **代價**：維度、精神（每腿兩振幅+一頻率）都對齊論文，但轉彎的「純度」略遜——論文用一個角度乾淨地轉整條軌跡；我們靠 μx/μy 組合出方向。實務上我們的轉向/直線主要靠**外掛羅盤 P 控制**（task3 沿用），步態層的側向能力夠用即可，所以這個簡化不影響結果。

### 4-3 腿間耦合：論文 wij=0（讓 RL 自己學協調）→ 我們硬編碼 trot 耦合（W_COUP=8）

| | 論文 | 我們（主變體）|
|---|---|---|
| 耦合 | **移除**(wij=0)，四腿獨立，靠 RL 學出 trot | **硬編碼** Kuramoto 耦合 W_COUP=8，鎖定 trot |

- **目的**：讓四條腿協調成對角小跑(trot)。
- **為何這樣選**：論文的「無耦合、讓 RL 自己協調」較難訓、較不穩，需要較多算力與調參才收斂；我們在 **Colab 免費 GPU** 的算力限制下，硬編碼 trot 耦合能**更快收斂、更穩、保證步態正確**，把 RL 的工作進一步縮小到「調振幅/頻率」。
- **代價**：步態被鎖死在 trot，學不了步態轉換(walk↔trot↔gallop)——這正是論文那個漂亮發現（步態能自己長出來）我們沒複現的地方。
- **補償**：我們**另外做了一個忠實版** `cpg_rl_paper_nocoup_colab.ipynb`（W_COUP=0，完全照論文讓 RL 自己協調），保留這條路；推論端用 `--w_coup 0/8` 對應。所以兩種都在，主推穩定的耦合版。

### 4-4 獎勵函數：追蹤項形式照論文，項目與權重自訂

論文的獎勵（6 項，權重都乘 dt=0.01）：
```
線速度追蹤 x：f(vx−vx*)          權重 0.75dt
線速度追蹤 y：f(vy−vy*)          權重 0.75dt
轉向追蹤   ：f(ωz−ωz*)          權重 0.5dt
z 速度懲罰 ：−vz²               權重 2dt
roll/pitch 角速度懲罰：−‖ωxy‖²   權重 0.05dt
work(能耗)：−|τ·(q̇t−q̇t−1)|     權重 0.001dt
其中 f(x)=exp(−‖x‖²/0.25)
```
我們的獎勵：
```
reward = 1.5·r_lin + 0.8·r_yaw − 1.0·upright − 0.5·height_pen − 0.05·act_rate + 0.05
r_lin = exp(−((vx−cmdx)²+(vy−cmdy)²)/0.25)      # x,y 合併成一項
r_yaw = exp(−((ωz−cmdz)²)/0.25)
```

逐項說明：

| 項目 | 論文 | 我們 | 目的與為何這樣選 |
|---|---|---|---|
| 速度追蹤形式 | `exp(−·/0.25)` | **同** | 直接沿用論文——這是主獎勵，形式與 0.25 都照抄，確保「追指令速度」這個核心行為對齊論文。|
| x/y 線速度 | 分兩項 | **合併一項** | 我們的 `r_lin` 把 x、y 誤差平方和塞進同一個 exp。目的：少一個要調的權重；我們主要走直線，x/y 分開調沒必要。|
| z 速度懲罰 | −vz²，2dt | **不做** | 我們用「高度偏離懲罰」取代（見下），直接管高度比管 z 速度更直觀。|
| roll/pitch 角速度懲罰 | −‖ωxy‖² | **改成姿態傾斜** −1.0·upright | `upright=grav_x²+grav_y²`（重力在身體座標的水平分量），直接懲罰「身體歪掉的角度」而非「歪掉的速度」。理由：傾斜量已在觀測裡、算起來簡單，且直接壓「別東倒西歪」比壓角速度更貼近我們要的「身體放平」。|
| 高度偏離 | ❌ 無 | ✅ −0.5·(h−0.30)² | **新增**。目的：把身高鎖在 Go2 站姿 0.30m，防止策略學成「蹲低省力」或塌下去。CPG-RL 若不管高度容易越走越低。|
| 能耗(work) | −0.001·|τ·Δq̇| | **改成動作平滑** −0.05·act_rate | `act_rate=‖動作−上一動作‖²`。理由：work 要抓力矩×關節速度變化、較複雜；CPG 本來就給平順動作，用「動作別忽大忽小」當省電/防抖的代理指標，簡單且夠用。|
| 存活 bonus | ❌ 論文沒列 | ✅ +0.05/步 | **新增**。每活一步加一點，鼓勵「別提早跌倒終止」，是 PPO 常見穩定訓練的小技巧。|

- **總目的**：保留論文「追速度」的核心，其餘懲罰換成**在我們環境裡好實作、好調、又直接對應想要行為**（身體放平、身高穩、動作順、別跌倒）的版本。
- **為何敢改**：論文自己也強調「因為 CPG 保證動作平順，獎勵可以很簡單」。我們就是照這個精神，用最少、最直觀的項把狗訓起來，而不是逐係數複製論文（論文係數是為 Isaac Gym+A1 調的，換到 MJX+Go2 本來就要重調）。

#### 為何不直接照抄論文的 reward？

不是論文 reward 較差，而是「照抄係數在我們平台上不會重現論文行為，且有些項較難算或沒必要」。五個原因：

1. **Reward 係數不可跨平台照搬（最主要）**：論文權重是為 Isaac Gym(PhysX)+A1+dt=0.01 調的，效果跟物理引擎尺度、機器人質量/力矩、控制頻率(我們 dt=0.02 差一倍)、PPO advantage normalization 全綁死。換到 MJX+Go2+50Hz，數字意義就變了——**反正都要重調，「照抄」根本不存在**。
2. **有些項較難算/較貴**：能耗項 `−|τ·Δq̇|` 要讀關節力矩，我們訓練端是位置伺服、力矩在致動器內部不好乾淨取出 → 改用 `act_rate` 當代理；z/roll-pitch 速度懲罰 → 改成直接懲罰狀態(傾斜、身高)，更直觀且量已在觀測裡。
3. **刻意簡化好在有限算力快收斂**：Colab 免費 GPU、2048 環境(論文專用 3070、4096)，獎勵地形越平滑越好找。合併 x/y、拿掉 work、加明確身高項與存活 bonus，讓「站起來走直」更易被找到。
4. **任務較窄**：我們主要要「照速度走直、別倒、不拖地、耐操」，轉向靠外掛羅盤不靠步態；論文要全向+步態分析+真機+觀測消融。裁剪獎勵貼合窄目標。
5. **最關鍵那項其實照抄了**：速度追蹤的 `exp(−·/0.25)`(含 0.25)直接沿用，因為它定義了「照指令速度走」這個共享核心行為；差異全在輔助/正則化項——那本就是「依平台調」的部分。

- **但書**：論文的 **work 能耗懲罰**（步態省電/自然）與 z/roll-pitch 速度懲罰是好東西；**未來要往真機 sim-to-real 或步態自然度/省電**走時，值得把它們加回並在我們環境重調。目前不加，是因當前目標(平地走穩、抗擾、不拖地)用更精簡獎勵就達成了。

## 5. 三分鐘濃縮版

1. **問題**：task3 CPG「照節拍器擺腿、不看回饋」，被推/變滑就垮，還拖地。
2. **方法**：改用論文 CPG-RL。CPG 出平順骨架，RL 每 20ms 依身體狀態調骨架旋鈕。骨架寫死、應變交給 AI。
3. **輸入**：76 維（姿態、速度、關節、觸地、指令、振盪器狀態）。
4. **輸出**：12 維（每腿 前後/側向振幅 + 頻率），**不是直接控馬達**，關節角靠 IK 算。
5. **訓練**：Colab GPU 用 PPO 讓 2048 隻虛擬狗試錯上億步，簡單獎勵(走對速度/別跌/別抖)自己學會走；加大量干擾耐操。訓一次、本機 CPU 永久推論。
6. **成果**：走 10m 偏 2cm、腳抬不拖地、扛側推、背 26kg 還走。比純 CPG 全面更強，又保留 CPG 可解釋+平順的優點。
