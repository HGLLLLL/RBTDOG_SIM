# 讓機器狗走路：Model-Based + Learning-Based 混合方法教學

> 對象：已經有「RL 片面基礎」、但沒接觸過機器人控制細節的你。
> 目的：搞懂目前把「傳統控制（含你現在用的 CPG）」和「學習（RL）」結合起來的 hybrid 方法有哪些、原理是什麼、各自優缺點，以及你該從哪一條路開始走。
> 讀法：從頭讀。每一節都盡量白話，先講直覺再講細節。看不懂的名詞，先往下看，最後有名詞表。

---

## 0. 先講結論（給沒耐心的你）

你現在用 **CPG（Central Pattern Generator，中樞模式產生器）** 讓狗走路，這是純 model-based（靠人設計的數學規則）。它的問題是：**走得穩，但笨**——遇到沒設計過的地形、外力、打滑就容易垮，而且要手動調參數很痛苦。

純 learning-based（end-to-end RL，讓神經網路直接輸出關節指令）則相反：**很會適應，但難訓練、容易學出鬼畜動作、sim-to-real（模擬到真機）容易爆炸**。

**Hybrid（混合）方法的核心想法**就是一句話：

> 讓「傳統控制」提供一個「已經大致對的骨架 / 先驗知識」，再讓「RL」只負責去「修正、調變、補強」這個骨架。

這樣 RL 不用從零學「怎麼站起來、怎麼擺腿」，只要學「如何在既有的好動作上做微調」，於是**訓練更快、更穩、更容易上真機**。

主流做法有四大類，本教學會逐一講清楚：

| 類別 | 一句話說明 | 跟你現在的 CPG 關係 |
|---|---|---|
| **A. CPG + RL** | RL 不直接控關節，而是去「調節 CPG 這組振盪器」的頻率、振幅 | **最接近你現況，建議首選** |
| **B. Residual RL（殘差學習）** | 傳統控制器先出一個指令，RL 只學一個「修正量」加上去 | 通用、好懂、好落地 |
| **C. MPC + RL** | 把 RL 和 MPC（模型預測控制）分層或混合使用 | 較進階，運算較重 |
| **D. 參考軌跡引導 / 模仿** | 用模型或動物動作產生「參考動作」，RL 去模仿它 | 概念好懂，工程量中等 |

## 1. 打底：三個世界觀

在講 hybrid 之前，必須先讓你清楚「model-based」和「learning-based」到底在講什麼，以及它們各自的痛點。Hybrid 存在的理由，就是為了同時吃到兩邊的好處。

### 1.1 Model-Based（模型基礎 / 傳統控制）

**核心信念**：我懂物理，我可以用數學把「狗該怎麼動」寫出來。

工程師事先寫好一組數學規則 / 方程式，描述：
- 腳該按什麼節奏擺（步態 gait）
- 身體重心該怎麼移動
- 每個關節該轉到什麼角度或出多少力矩（torque）

你現在的 **CPG 就屬於這一類**。CPG 的靈感來自生物的脊髓：動物走路時，不是大腦每一步都精算，而是脊髓裡有一組會自己「震盪」的神經迴路，產生規律的節奏訊號，四條腿就跟著這個節奏擺動。CPG 在程式裡就是**一組「耦合振盪器（coupled oscillators）」**——幾個會週期性上下擺動的數學函數，彼此之間有相位關係（比如對角腿同步、相鄰腿錯開），這樣就自然產生 trot（對角小跑）、walk、gallop 等步態。

另一個常見的 model-based 方法是 **MPC（Model Predictive Control，模型預測控制）**：它每一瞬間都用一個「機器人動力學模型」去預測「未來 0.5 秒我如果這樣出力，身體會怎麼動」，然後解一個最佳化問題，挑出最好的當下動作，下一時刻再重算。波士頓動力、MIT Cheetah 早期都大量用這套。

**優點**
- **可解釋**：每個行為都有物理意義，出事你查得出原因。
- **穩定、可預測**：在設計範圍內表現一致。
- **不用大量資料 / 訓練**：寫好方程式就能動。
- **安全**：可以硬性加入約束（例如「關節絕不超過某角度」）。

**缺點**
- **不會臨機應變**：只在你「設計過的情況」表現好。遇到沒想到的地形、被推一把、腳打滑，模型假設崩掉就垮。
- **調參地獄**：CPG / MPC 都有一堆參數（振幅、頻率、增益、權重…），靠人手動試，換個地形又要重調。
- **模型誤差**：真實世界永遠比你的方程式複雜（摩擦力、馬達延遲、零件鬆動…），模型和現實有落差就會出錯。

### 1.2 Learning-Based（學習基礎 / 純 RL）

**核心信念**：我不用完全懂物理，我讓狗自己在模擬器裡摔幾百萬次，自己學會走。

這就是 **end-to-end RL（端到端強化學習）**：一個神經網路（policy，策略網路）直接吃感測器資料（身體姿態、關節角度、速度…），直接吐出 12 個關節該做什麼（角度或力矩）。透過**獎勵函數（reward）**告訴它「往前走+分、跌倒-分、抖動-分」，它在模擬器裡跑幾千個平行環境、摔個幾億步，最後學出一個很強的走路策略。這就是 Isaac Gym / MuJoCo 上「幾分鐘訓練出會走的狗」那類 demo。

> 你已經有 RL 基礎，這裡幫你對齊詞彙：
> - **policy（策略）**：那個做決定的神經網路。
> - **observation（觀測）**：policy 的輸入（狗看到/感覺到的東西）。
> - **action（動作）**：policy 的輸出（要下給馬達的指令）。
> - **reward（獎勵）**：評分，RL 的唯一學習訊號。
> - **sim-to-real**：在模擬器學好後，搬到真實機器人身上還能不能動。這是機器人 RL 最大的坎。

**優點**
- **超強適應力 / 泛化**：可以學會處理各種地形、外力、打滑，表現常常屌打傳統方法。
- **不用精確模型**：不用你把物理寫對。
- **自動最佳化**：獎勵設好，它自己找出你想都想不到的高效動作。

**缺點**
- **難訓練**：獎勵函數（reward shaping）非常難調，設不好就學出「原地抽搐」「用頭滑行」這種鑽漏洞的鬼畜行為。
- **黑箱、不可解釋**：出事你不知道為什麼。
- **樣本效率低**：要摔幾億步。
- **sim-to-real gap**：模擬器裡完美，上真機因為物理差異直接暴走。
- **不安全**：探索過程什麼奇怪動作都做得出來，難加硬約束。

### 1.3 為什麼要 Hybrid？——把兩張好牌合起來打

看到這你應該有感覺了：兩邊的優點和缺點幾乎是**互補**的。

- Model-based 缺「適應力」，正好 learning-based 有。
- Learning-based 缺「穩定、安全、可解釋、好訓練」，正好 model-based 有。

**Hybrid 的哲學**：不要讓 RL 從一張白紙開始學走路（太難、太危險），而是先給它一個「傳統控制產生的、大致正確的動作」當底稿，RL 只要負責在這底稿上「加工」。

打個比方：
- 純 RL＝叫一個從沒走過路的人，蒙眼在懸崖邊自己摸索怎麼走，摔死幾百萬次才學會。
- Hybrid＝先給他一副「會自動邁步的骨架外骨骼（＝CPG/MPC）」，他只要學「什麼時候要多用點力、什麼時候身體要側一點」來應付路況。學得又快又安全。

這帶來的好處（研究論文反覆驗證的）：
1. **訓練更快**（sample efficiency 高，收斂快）。
2. **獎勵函數可以更簡單**（因為骨架已經保證基本動作合理，你不用靠 reward 去逼出「像走路的樣子」）。
3. **sim-to-real 更順**（動作本來就在合理範圍內，不會暴衝）。
4. **更穩、更安全、保留一定可解釋性**。

## 2. 四大類 Hybrid 方法（本教學的主菜）

以下每一類都用同一套格式介紹：**直覺 → 運作方式（RL 的 action/observation 是什麼）→ 優缺點 → 代表研究**。
建議你特別讀懂 **A（CPG+RL）**，因為它跟你手上的東西無縫接軌。

---

### 🅰️ 類別 A：CPG + RL（RL 調變 CPG）

> **這是離你最近、最推薦你先做的路線。** 你已經有 CPG 了，這條路等於「在你現有的 CPG 上面接一顆 RL 大腦」。

#### 直覺

你現在的 CPG 是**固定參數**的：頻率、振幅都是你手調死的，所以狗只會用固定節奏走，不會因應狀況變快變慢、變高抬腿。

CPG+RL 的想法很優雅：**CPG 繼續負責產生規律節奏（保證動作平順、協調），但「振盪器的參數」不再由人手調，而是交給 RL 即時去調。** RL 變成 CPG 的「指揮」，CPG 變成 RL 的「肌肉節奏產生器」。

#### 運作方式

回憶一下 CPG 的數學：每條腿（或每個關節）掛一個振盪器，狀態通常是「相位 φ」和「振幅 r」，它們隨時間演化的微分方程大致長這樣（Hopf oscillator 為例，你不用背，看懂角色就好）：

- **頻率 ω**：控制腳擺多快（步頻）。
- **振幅 r**：控制腳擺多大（步幅 / 抬腿高度）。
- **相位耦合**：控制四條腿之間的協調關係（決定 trot / walk / gallop）。

在純 CPG，ω 和 r 都是常數。在 **CPG-RL**：

- **RL 的 action（輸出）** ＝ 每個振盪器的**目標頻率 ω、目標振幅 r**（以及有時候相位偏移）。也就是說 RL 不直接控關節角度，而是「調旋鈕」——告訴 CPG「現在給我走快一點、抬高一點」。
- **CPG** 收到這些參數，透過它的微分方程平滑地產生出實際的關節目標角度，再送給馬達（通常配一個 PD 控制器去追這個角度）。
- **RL 的 observation（輸入）** 可以很精簡：身體姿態/速度、指令速度、加上**振盪器自身的狀態（相位、振幅）**，甚至只要**腳有沒有觸地的布林值（contact booleans）**就能運作得不錯。

關鍵在於：因為 CPG 保證了輸出永遠是「平滑、週期、四腿協調」的訊號，RL 探索的空間被大幅縮小到「合理動作」裡，不會亂抽搐。

#### 優缺點

**優點**
- 幾乎是你現況的直接升級，改動最小。
- 訓練快、獎勵函數可以很簡單。
- Sim-to-real 表現好——代表論文 CPG-RL 訓練後直接上 Unitree A1 真機，甚至能扛下相當於自身體重 115% 的額外負載、抵抗訓練中沒見過的外力干擾。
- 動作自然、平順（因為底層還是振盪器）。

**缺點**
- 上限受 CPG 結構限制：非常劇烈、非週期性的動作（例如跳過大坑、爬非常崎嶇的地形）可能超出 CPG 表達能力。
- 你得先有一個設計得還可以的 CPG（你已經有了 ✅）。

#### 代表研究
- **CPG-RL（Bellegarda & Ijspeert, 2022）**：這條路線的經典起手式，RL 調變振盪器的振幅與頻率，成功 sim-to-real 到 Unitree A1。論文：arXiv:2211.00458。
- **Visual CPG-RL（2023）**：再加上視覺（外部感知 exteroception），讓狗能看著地形調 CPG，避障、上下階梯。arXiv:2212.14400。
- **HRL-CPG（Nature Sci. Reports, 2025）**：階層式 RL + CPG，走各種地形。

### 🅱️ 類別 B：Residual RL（殘差強化學習）

> 最通用、最好懂、最好落地的一種 hybrid。「Residual＝殘差＝差額」，你可以想成「RL 只學那個修正量」。

#### 直覺

想像一個已經寫好的傳統控制器（可以是 CPG、也可以是 MPC，甚至一個簡單的步態產生器），它會針對每個狀況輸出一個「基準動作」`a_base`。這個基準通常「大致對，但不完美」。

**Residual RL 的做法**：不要丟掉這個基準，也不要讓 RL 重學。讓 RL 只學一個小小的「修正量」`a_res`，最後真正下給馬達的是：

```
最終動作 = a_base（傳統控制器給的）＋ a_res（RL 學的修正量）
```

RL 的工作從「學會走路」降級成「學會在基準上補一點點」——這任務簡單太多了。剛開始訓練時，RL 還沒學到東西，`a_res ≈ 0`，於是**狗一開始就已經會用傳統控制器走路了**（不會像純 RL 一開始只會癱在地上），然後 RL 逐步學會補強：哪裡打滑了補一點、被推了頂一下、地形斜了偏一點。

#### 運作方式

- **base controller**：你的 CPG / MPC / 步態產生器，輸出 `a_base`（可以是關節目標角度或力矩）。
- **RL 的 action** ＝ 殘差 `a_res`（跟 `a_base` 同維度的一個小修正向量，通常會限制它的大小，避免 RL 亂搞蓋過基準）。
- **RL 的 observation** ＝ 一般的本體感測（姿態、關節、速度、指令），有時也把 `a_base` 一起餵給 RL（讓它知道基準想幹嘛）。
- **合成**：`a = a_base + a_res` → 送馬達。

一個進階版是 **Residual MPC**：base 用 GPU 平行化的 MPC，RL 在「力矩層級」上加殘差，兼顧 MPC 的可解釋 / 約束處理，和 RL 的適應力，能 zero-shot（不用重訓）適應沒見過的步態和崎嶇地形。

#### 優缺點

**優點**
- **概念極簡、實作直接**：包一層在你現有控制器外面即可。
- **訓練起點就是可用的**：第一步就會走，安全性高。
- **保留 base controller 的優點**（穩定、約束、可解釋）。
- Base 換誰都行（CPG、MPC、PD…），很通用。

**缺點**
- 效果上限跟 base controller 品質、和「殘差允許多大」有關。殘差限太小 → 學不到東西；限太大 → 退化成純 RL、失去 base 的保護。
- 需要 base 和 RL 兩套東西同時跑，系統稍微複雜一點。

#### 代表研究
- **Residual MPC（arXiv:2510.12717）**：MPC + RL 在力矩層融合，樣本效率、可追蹤速度範圍都更好。
- **Residual Policy Learning for Perceptive Quadruped Control（arXiv:2410.03076）**：用可微分模擬器做殘差策略學習。

### 🅲️ 類別 C：MPC + RL（分層 / 混合）

> 比較進階、運算較重，但概念上很有代表性。適合之後想追求高性能時了解。

#### 直覺

MPC 很強但有個死穴：它要「往未來預測很多步再最佳化」，**預測越遠、計算量爆炸式增長**，即時跑不動。而且它依賴一個準確的動力學模型。

MPC + RL 的想法是讓兩者分工，常見兩種架構：

**(1) 分層（hierarchical）**：
- **上層＝RL（慢、負責決策）**：決定「高階指令」，例如目標速度、步態選擇、落腳點（foot placement）、身體要往哪偏。
- **下層＝MPC / model-based（快、負責執行）**：接到上層指令後，用模型算出精準的關節力矩去實現它。

好處：RL 只需在「抽象決策層」學習（狀態空間小、學得快、安全），底層由可靠的 model-based 保證執行品質。

**(2) 融合 / 補強 MPC 的計算**：
- 用 RL 學一個「價值函數（Q-function / value function）」當作 MPC 的「尾端成本（tail cost）」。白話說：MPC 只往前算短短幾步（省算力），剩下更遠的未來「值多少分」由 RL 學好的網路一把估出來。這樣就避開了 MPC「預測遠 = 計算爆炸」的死穴。

#### 運作方式（以分層為例）
- **RL observation**：高階狀態（身體速度、地形資訊、指令）。
- **RL action**：高階指令（目標速度向量、步態、落腳點、身體姿態目標…），**不是**直接的關節指令。
- **MPC**：吃 RL 給的高階目標 + 機器人動力學模型 → 解最佳化 → 輸出關節力矩 → 馬達。

#### 優缺點

**優點**
- 兼顧 MPC 的精準/可加約束，與 RL 的適應/決策彈性。
- 分層讓每一層任務單純，好訓練、好除錯。
- 可解決 MPC 的計算瓶頸（用 RL 估遠期成本）。

**缺點**
- **系統最複雜**：要同時維護 MPC 求解器和 RL，還要協調兩層的介面與時序。
- MPC 本身要有機器人的動力學模型，建模與調校成本高。
- 即時運算負擔重（MPC 求解要夠快）。

#### 代表研究
- **Combining MPC and predictive RL for stable quadrupedal locomotion（arXiv:2307.07752）**：用 RL 的 Q-function 當 MPC 的 tail cost，緩解計算複雜度。
- **Hybrid Control: MPC + DRL（IEEE, 2024）**。
- **Benchmarking MPC vs RL in MuJoCo（arXiv:2501.16590）**：如果你想比較純 MPC / 純 RL / 混合在 MuJoCo（你正在用的模擬器）裡的表現，這篇很值得看。

### 🅳️ 類別 D：參考軌跡引導 / 模仿學習（Motion Priors、Teacher-Student）

> 概念很好懂：「先弄出一套標準答案動作，再讓 RL 去模仿它。」

#### 直覺

純 RL 難訓練，很大原因是「它不知道好動作長怎樣，只能靠 reward 慢慢猜」。那如果我們**先給它一份『參考動作』當範本**呢？

這份參考動作（reference trajectory / motion prior）可以來自：
- **一個簡化的物理模型**（reduced-order model，例如把狗簡化成一個會彈跳的質點+彈簧，算出重心該怎麼動）——這是 model-based 的部分；
- 或**真實動物的動作捕捉資料**（motion capture，例如錄真狗走路）；
- 或你現有的 **CPG / MPC** 直接生成的軌跡。

然後 RL 的獎勵裡多一項：「你越像這份參考動作，加越多分」。RL 於是在「模仿範本」和「達成任務（往前走、別跌倒）」之間取得平衡，學出既自然又能適應的動作。

#### 幾個常見招式（名詞先混個臉熟）
- **Imitation / reference tracking**：reward 直接算「和參考軌跡的差距」，越小越好。
- **AMP（Adversarial Motion Priors，對抗式動作先驗）**：不用逐幀比對，而是訓一個「鑑別器」去分辨「這動作像不像參考動作庫」，RL 想騙過鑑別器就得動得自然。動作更靈活、不會死板照抄。
- **Teacher-Student（師生 / 特權學習 privileged learning）**：
  - **Teacher（老師）**：在模擬器裡訓練，允許它「作弊」看到現實中拿不到的資訊（精確地形高度、摩擦係數、外力…這些叫 privileged / 特權資訊），因此能學得又快又好。
  - **Student（學生）**：只能看到真機上拿得到的感測器（本體感測 + 相機），透過模仿老師的行為，把老師的能力「蒸餾（distill）」過來。
  - 這招是現在四足 sim-to-real 的主流之一（ETH ANYmal 那條線就是這樣）。
- **ROM-GRL**：用 reduced-order model 產生「動力學上合理」的參考步態，再蒸餾進高維控制器——典型的「model-based 產生範本 + learning 放大」。

#### 優缺點

**優點**
- 有範本引導，訓練快、動作自然、不易鑽漏洞。
- Teacher-student 讓 sim-to-real 非常穩健。
- 參考來源彈性（模型 / 動捕 / 你的 CPG 都行）。

**缺點**
- 需要先取得 / 產生一份夠好的參考動作（多一道工序）。
- 動作品質有時受參考動作侷限（照抄範本的天花板）；AMP 可緩解。
- Teacher-student 是兩階段訓練，pipeline 較長。

#### 代表研究
- **Adversarial Motion Priors on a Quadruped（arXiv:2407.02282）**。
- **ROM-Guided RL（arXiv:2509.19023）**：reduced-order model 引導、免動捕。
- **Concurrent Teacher-Student RL for Legged Locomotion（arXiv:2405.10830）**。

## 3. 四大類一次看懂（比較表）

| 面向 | A. CPG+RL | B. Residual RL | C. MPC+RL | D. 參考軌跡/模仿 |
|---|---|---|---|---|
| RL 實際在學什麼 | 調 CPG 的頻率/振幅 | 學基準動作的**修正量** | 高階決策 or 遠期成本估計 | 模仿參考動作 |
| RL 的 action | 振盪器參數 (ω, r) | 殘差 `a_res` | 高階指令 / value | 關節指令（含模仿獎勵） |
| 需要的先備元件 | 一個 CPG（你有✅） | 任一 base 控制器 | 動力學模型 + MPC | 一份參考動作來源 |
| 訓練難度 | 低–中 | 低 | 高 | 中 |
| 運算負擔（跑起來） | 低 | 低 | 高（MPC 即時求解） | 低（訓練後） |
| Sim-to-real 友善度 | 高 | 高 | 中–高 | 高（尤其 teacher-student） |
| 系統複雜度 | 低 | 低–中 | 高 | 中 |
| 對你（現有 CPG）的接軌 | **最直接** | 直接（拿 CPG 當 base） | 需另建 MPC | 可拿 CPG 生範本 |

## 4. 給你的實作路線建議

你現在的狀態：**MuJoCo 模擬、有一套 CPG 走路、RL 只懂片面基礎、沒 MuJoCo/機器人控制實戰經驗。**

我的建議是**照難度階梯往上爬**，不要一開始就挑 MPC+RL：

### 第一步（強烈建議先做）：CPG-RL 或 Residual-on-CPG
兩個都能直接沿用你手上的 CPG，差別只是「RL 動的東西」不同：
- **CPG-RL**：RL 輸出 = CPG 的頻率/振幅。動作最平順、最像你現在的框架的延伸。
- **Residual-on-CPG**：CPG 照常輸出關節目標，RL 只加一個小修正量。實作最直觀，第一步就能走。

先做哪個都行。如果你想「改動最小、概念最連續」→ 選 CPG-RL；如果你想「最快看到 RL 補強效果、除錯最單純」→ 選 Residual RL。

### 第二步：加入地形 / 感知
基本框架跑通後，再把地形資訊（高度圖或相機）加進 observation，往崎嶇地形挑戰（參考 Visual CPG-RL）。

### 第三步（進階）：teacher-student 或 MPC+RL
等你對 RL 訓練、sim-to-real、獎勵設計都熟了，再考慮這些較重的架構去衝性能上限。

### 實作前的檢查清單
- [ ] 確認你的 MuJoCo 環境能穩定跑現有 CPG（這是 base）。
- [ ] 選一個 RL 函式庫。四足常用 **Isaac Gym / Isaac Lab**（大規模平行、超快），純 MuJoCo 也可搭 **Stable-Baselines3** 或 **rsl_rl** 起步。
- [ ] 先設一個**最簡單的獎勵**：追蹤指令速度 +、跌倒/翻覆 −、能量/抖動小幅 −。hybrid 的好處就是獎勵可以很簡單。
- [ ] 決定 action：CPG-RL→振盪器參數；Residual→殘差（記得**限制殘差大小**）。
- [ ] 先在平地訓練跑通整條 pipeline，再逐步加難度（domain randomization、地形、外力）。

## 5. 名詞表（隨時回來查）

- **CPG（中樞模式產生器）**：一組會週期震盪的數學單元（耦合振盪器），產生規律步態節奏。你現在用的東西。
- **MPC（模型預測控制）**：每一刻用動力學模型預測未來、解最佳化、挑當下最佳動作的傳統控制法。
- **Model-based**：靠人設計的物理模型/方程式來控制（CPG、MPC 都是）。
- **Learning-based / RL**：靠試錯 + 獎勵，讓神經網路自己學控制。
- **End-to-end RL**：policy 直接從感測輸入吐關節指令，中間沒有傳統控制。
- **Policy（策略）**：做決策的神經網路。
- **Observation / Action / Reward**：RL 的輸入 / 輸出 / 評分。
- **Residual（殘差）**：修正量、差額。Residual RL＝只學「加在基準上的修正」。
- **Sim-to-real**：模擬器學好後搬到真機還能不能動；機器人 RL 最大難關。
- **Sim-to-real gap**：模擬與現實的物理差異造成的落差。
- **Domain randomization（領域隨機化）**：訓練時故意亂調摩擦、質量、延遲等參數，逼 policy 學得更耐操，縮小 sim-to-real gap。
- **Privileged / Teacher-Student**：老師在模擬裡看「作弊資訊」學得好，學生只用真機感測器模仿老師（蒸餾）。
- **Motion prior / Reference trajectory**：給 RL 當範本的參考動作。
- **AMP（對抗式動作先驗）**：用鑑別器讓學到的動作「像」參考動作庫，不必逐幀照抄。
- **Reduced-order model（降階模型）**：把機器人簡化成簡單力學模型（如彈簧質點），用來快速產生合理參考動作。
- **Foot placement（落腳點）**：腳下一步該踩哪，是很多控制器的關鍵決策量。
- **PD 控制器**：一個簡單的低階控制器，負責讓馬達把關節「追到」目標角度。
