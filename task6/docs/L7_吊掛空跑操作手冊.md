# L7 吊掛空跑操作手冊 —— walk_stable 步態部署 D1 EDU 實機

**用途**：上機當下對著做。不是教學文件，判準不寫理由的長篇解釋（背景見
`docs/superpowers/specs/2026-08-11-d1-walk-stable-hanging-deploy-design.md`）。
**範圍**：`task6/realbot/L7_gait_shm.py` 吊掛空跑（腳離地）驗證追蹤誤差。**不是**落地行走。

---

## 0. 這台機器的現況（每次上機前先確認沒變）

- **右後腿（SHM `leg2` = RR）整條馬達已從 CAN 失聯**，全程零增益、不驅動。
  詳見 `task6/docs/報修報告_右後輪馬達故障_2026-08-11.md`。所有 L7 指令的 `--skip-legs`
  **預設就是 `2`** —— 不用手動加，但要知道少的是哪一條腿。
- **機器開機後約 3 分鐘就會閃紅燈並 disable 全部 16 顆馬達**，且無法自行恢復，只能斷電重開。
  **每次上機的操作窗口約 3 分鐘。** 這是預設用 `--time-scale 0.25` 搭 `--secs 5`（單次執行約
  20 秒）的原因 —— 一次開機扣掉連線、預檢時間，做得完一到兩關，不要貪心一次跑完整個階梯。
- 上述兩點若某次開機情況不同（例如撐得比 3 分鐘久，或 RR 忽然又有訊號），**先當異常處理，
  不要當作故障已修好** —— 除非已收到原廠回覆確認維修完成。

---

## 1. 上機前檢查清單（逐項打勾，缺一不跑）

- [ ] **1. 狗吊起來，四腳離地**，用手撥動確認完全不觸地（含輪子）
- [ ] **2. RR（右後腿）垂下來不會撞到吊具、其他腿、或地面**
      —— RR 全程零增益，會被重力拉到機構限位附近垂下（模型估 `hip ≈ −60°`、
      `knee ≈ +79°`），這個姿勢比站姿低很多，比其他三條腿看起來鬆垮很多，是正常現象，
      **但要親眼確認它垂下來的路徑不會卡到東西**
- [ ] **3. `mc_ctrl` 已 SIGSTOP**：`sudo kill -STOP $(pgrep mc_ctrl)`
      （停 `mc_ctrl` 後遙控器與原廠保護全失效，這是後面所有關卡能寫入 SHM 的前提）
- [ ] **4. `estop.sh` 開在另一個終端，隨手可按**：`sudo ~/estop.sh`
      **⚠️ 已知缺口**：`estop.sh` 目前的 `pkill` pattern 寫死抓 `L4_standup_shm.py`，
      **不會匹配 `L7_gait_shm.py`**。也就是說對著 L7 按 `estop.sh`，`mc_ctrl` 會解凍，
      但 L7 的行程可能還在跑、繼續舉旗，兩邊同時寫 SHM。**在修好這個腳本之前，跑 L7 時
      真正的緊急停止是另開一個終端手動下：
      `sudo pkill -f L7_gait_shm.py && sudo kill -CONT $(pgrep mc_ctrl)`
      **把這行指令準備好、跟 `estop.sh` 一樣隨手可按**，不要只依賴 `estop.sh`。
- [ ] **5. 車載電腦有 numpy**：`python3 -c "import numpy; print(numpy.__version__)"`
      （車上沒有 torch/onnx，L7 推論全程純 numpy）
- [ ] **6. 軌跡檔已複製到狗上，且 `calib_hash` 與狗上的 `calib_map` 一致**
      —— npz 的 `meta.calib_hash` 對不上狗上 `calib_map.CALIB` 就會被 L7 拒跑，這是刻意的
      （防止改了校正卻拿舊軌跡去跑）；不一致就重新用最新的 `calib_map.py` 跑一次
      `gait_export.py --export` 再複製過去

## 2. 上機前待辦：先重驗 L4（只做一次，之後跳過）

這次改動把 `L4_standup_shm.py` 的 SHM 骨架抽到共用的 `shm_common.py`（給 L4/L7 共用，
避免 SHM 結構定義存在兩份、欄位順序漂掉沒人發現）。dry-run 輸出已確認逐字元不變，
但**這是離線驗證，不能取代實機驗證**。在跑任何 L7 關卡之前，必須先用實機重跑一次
L4 的趴下／站立，確認行為沒被改壞：

```bash
sudo python3 L4_standup_shm.py --sequence lie,stand --confirm --skip-legs 2
```

通過條件：動作與重構前一致（平順接住、平順站起、無異常力矩中止）。這一步過了才進第 3 節。
只需在**這次改動後的第一次上機**做一次，之後的上機不用重跑。

## 3. 四道關卡與往下走的條件

**任一關不過就停在該關，不准跳級往下走。** 這句話尤其是對 G1 講的（見 3.2）。

| 關卡 | 指令 | 通過條件 |
|---|---|---|
| **G0** 離線 | `pytest task6/tests -q` + `python3 gait_export.py --export <path>` | 全綠、npz 產出 |
| **G1** jog | `sudo python3 L7_gait_shm.py --mode jog --jog-leg 0 --jog-joint <abad\|hip\|knee> --confirm` | 方向與 MJCF 正向定義一致 |
| **G2** leg | `sudo python3 L7_gait_shm.py --mode leg --only-leg 1 --traj ../weights/gait_walk_stable.npz --time-scale 0.25 --secs 5 --confirm` | 不中止 |
| **G3** gait | `sudo python3 L7_gait_shm.py --mode gait --skip-legs 2 --traj ../weights/gait_walk_stable.npz --time-scale 0.25 --secs 5 --confirm` | 不中止 |
| **G3-live** | 同 G3 加 `--source live` | 不中止，且追蹤誤差與同一倍速的 `--source file` 數字一致 |

⚠️ `--mode leg` 與 `--mode gait` 的 `--traj` **是必填的**，漏了會直接被 argparse 擋下來
（`error: --mode leg/gait 需要 --traj`）。路徑是相對於你執行指令的位置。

`--source file`（預設）是播放 `gait_export.py` 寫死的軌跡檔；`--source live` 是狗上自己
即時算 CPG + IK。兩者在任何倍速下都應該送出相同的指令，所以 G3-live 是對「狗上算得對不
對、算得夠不夠快」的獨立驗證 —— **特別看 500 Hz 週期超時率有沒有比 file 模式高**，超時
造成的軌跡失真不要誤讀成追蹤誤差。

**`--time-scale` 對兩個模式都有效**，所以 G3-live 也照 0.25× → 0.5× → 1.0× 的階梯走。
（CPG 一律在未縮放的 50 Hz 網格上積分，時間縮放純粹是播放層的事，兩模式共用同一層。）

G0 是離線步驟，可以在開發機做完，上機前確認過就好，不佔 3 分鐘窗口。

### 3.1 G1：單關節微動驗號（人眼比對）

G1 要對 `leg0`（= FR，右前）的 abad / hip / knee **三軸各跑一次**，不能只測一軸就往下走：

```bash
sudo python3 L7_gait_shm.py --mode jog --jog-leg 0 --jog-joint abad --confirm
sudo python3 L7_gait_shm.py --mode jog --jog-leg 0 --jog-joint hip  --confirm
sudo python3 L7_gait_shm.py --mode jog --jog-leg 0 --jog-joint knee --confirm
```

MJCF 正向定義（人眼比對用）：

| 軸 | 正向 |
|---|---|
| `abad` | 外張 |
| `hip` | 後擺 |
| `knee` | 伸直 |

每一軸跑完，肉眼看腿的擺動方向是否對得上表格，**同時**對照 state 讀數雙確認（不要只靠肉眼）。

**hip 是這一關的重點**，因為 `calib_map.py` 檔頭明寫 hip 的號是「暫定」（`CALIB` 裡每條腿
的 `hip` sign 都還沒吊掛驗證過）。abad / knee 的號信心較高，但既然三軸都要跑，就三軸都認真看。

### 3.2 G1 為什麼是硬性關卡，不能跳

號如果反了，腿會**往反方向甩到限位**——而這件事離線檢驗完全看不出來，因為反過來的數字本身
仍然完全正常（`sign=-1` 只是把角度鏡射，數值範圍、單位都合理，五項離線檢驗一項都不會報錯）。
唯一能抓到反號的地方就是這裡：人親眼看腿往哪邊動。**所以 G1 沒過，不准往下跑 G2/G3，
沒有例外。**

**號驗錯了怎麼辦**：

1. 停在 G1，不要繼續
2. 改 `task6/realbot/calib_map.py` 裡 `CALIB` 對應項的 `sign`（例如 `leg0.hip` 的
   `(-1, -1.166)` 改成 `(+1, -1.166)`）
3. 重跑 `python3 gait_export.py --export <path>` 產新的 npz
   —— **`calib_hash` 會變**，狗上舊的 npz 會被 L7 拒絕，這是刻意的行為，不是 bug
4. 把新 npz 複製到狗上，重跑 G1

### 3.3 G2 / G3：倍速階梯

**每一關都先 `--time-scale 0.25`，過了才 0.5，再 1.0。每一級跑完用 `--analyze` 看追蹤誤差
再決定要不要往上加一級**，不要三級一次排隊跑（力矩／速度門檻是隨 `time_scale` 查表的，
上一級沒過，門檻設定對下一級沒有意義）：

```bash
python3 gait_export.py --analyze <statelog路徑>
```

G2 只驅動 `--only-leg 1`（= FL，左前）。選 FL 是因為它在模擬裡離地量最大（76.6 mm），
最容易看出追蹤差異，同時把風險限制在單腿。**不要因為省事換成別的腿。**

G3 是三腿同步（`--skip-legs 2`，RR 自動排除）。`--secs 5` 是配合 3 分鐘窗口的快速判斷；
若同一次開機還有餘裕、且 0.25×/0.5× 都已通過，可以在最後一級加 `--secs 20` 對齊模擬的
20 秒統計窗口做正式紀錄，但**不要為了湊 20 秒犧牲關卡順序或跳過中間的誤差檢查**。

## 4. 每一級的模擬預測值（原廠增益 kp=20 / kd=0.7）

從 npz 的 `meta.air_sim` 表抄。實機量到的誤差要跟這一欄比：

| 倍速 | 力矩峰值 | 誤差峰值 | 誤差 RMS | 速度峰值 |
|---|---|---|---|---|
| 0.25× | 2.33 N·m | 10.89° | 2.33° | 3.62 rad/s |
| 0.50× | 5.28 N·m | 23.30° | 5.02° | 7.47 rad/s |
| 1.00× | 10.18 N·m | 39.20° | 9.30° | 12.96 rad/s |

**判讀方式**：

- **實機誤差顯著大於預測** → 代表實機比模型軟：增益沒真的生效（例如 `--kp/--kd` 沒吃到、
  或原廠站立值跟 SHM 實際寫入不一致），或馬達到了速度上限撞牆（呼應 §5 的「實機馬達速度
  上限未知」）。先查增益有沒有真的寫進 SHM，再查速度上限。
- **實機誤差顯著小於預測** → **先別高興**，代表軌跡很可能沒有真的送出去（例如卡在某個
  guard、或寫入的其實是零/舊值）。先確認 state log 裡的指令角真的隨時間變化、跟 npz 對得
  上，再相信這個「表現超預期」的數字。

門檻表由 `gait_export` 匯出時算好寫進 npz 的 `meta`，L7 直接查表；查不到對應的
`(kp, kd, time_scale)` 組合會拒跑，這不是 bug，是刻意設計成「門檻不能用猜的」。

## 5. 收尾

任何一次上機結束（不論成功、中止、還是被 estop）：

```bash
sudo kill -CONT $(pgrep mc_ctrl)
```

解凍運控，恢復原廠控制。**每次離開狗之前務必確認這一步做過**——`mc_ctrl` 沒解凍的話，
下次遙控器不會有反應，容易誤判成又是硬體故障。

## 6. 已知限制（照抄設計文件 §11，一字不改判讀，不要淡化）

1. **吊掛結果不能外推到落地。** 空中沒有地面反作用力，`kp=20` 在空中夠，不代表承重時夠。
2. **上機跑的是 `G_C=0.110`，不是影片版的 `0.12`**（膝關節限位餘裕從 0.65° 提到 3.95°）。
   看到的動作跟 `cpg_walk_stable_d1.mp4` 不會完全一樣，這是刻意調整過的結果，不是誤跑錯參數。
3. **實機馬達速度上限未知，1.0× 可能達不到。** `--time-scale` 是緩解，不是解答。
4. **1.0× 的預測誤差峰值 39.20°，實機動作會與影片有明顯差異。** 影片本身是 kp=80 伺服濾過
   的版本（RMS 5.88°），實機用原廠站立值 kp=20 只會更鈍。**這是預期內的，不是失敗。**
