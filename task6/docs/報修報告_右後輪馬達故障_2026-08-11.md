# D1 EDU（輪足版）報修報告 — 右後輪馬達開機後數分鐘失效

**提報日期**：2026-08-11
**問題等級**：機器無法連續使用超過約 3 分鐘，目前已無法進行任何開發工作

---

## 一句話摘要

**右後腿（leg2）的輪馬達在每次開機後約 3 分鐘進入 `ready=0`（未啟用）狀態，導致運控將全部 16 顆馬達 disable、機器閃紅燈並整隻失去控制；僅能靠斷電重開暫時恢復，且故障範圍正在擴大。**

## 2. 症狀

1. 開機後機器運作正常，可用遙控器正常站立、行走
2. 約 2～21 分鐘後（多數集中在 **3～4 分鐘**），機器**突然閃紅燈**
3. 同時**全部 16 顆馬達失去出力**，機器整隻軟掉、失去控制
4. 此狀態**無法自行恢復**，僅能斷電重新開機
5. 重開後恢復正常，然後再次重複上述循環

**與操作無關**：無論機器是靜置不動，或正在被遙控行走，都會發生。已在完全靜置（passive 狀態、所有指令增益為 0、實測力矩約 0.00 N·m）的情況下重複觀察到。

## 3. 故障定位

### 3.1 直接原因：leg2 的輪馬達 `ready=0`

透過唯讀讀取 `/dev/shm/spline_shm` 的 state 區，以 10 Hz 連續記錄 16 顆馬達狀態（累積超過 19,000 筆樣本），發現：

**紅燈亮起時，16 顆馬達中只有 leg2（右後腿）的馬達異常，其餘 12～15 顆完全正常。**

以其中一次觀察為例（開機後 768 秒，紅燈閃爍中）：

```
關節        ready  溫度  電壓        關節        ready  溫度  電壓
FR.abad      ✅   47°C  44V         FL.abad      ✅   47°C  44V
FR.hip       ✅   46°C  44V         FL.hip       ✅   44°C  44V
FR.knee      ✅   42°C  44V         FL.knee      ✅   43°C  44V
FR.foot      ✅   30°C  44V         FL.foot      ✅   31°C  44V

RR.abad      ✅   46°C  44V         RL.abad      ✅   46°C  44V
RR.hip       ✅   43°C  44V         RL.hip       ✅   44°C  44V
RR.knee      ✅   44°C  44V         RL.knee      ✅   44°C  44V
RR.foot      ❌   29°C  44V  ←唯一   RL.foot      ✅   30°C  44V
```

在原始位元組層級，異常馬達與正常馬達的差異**只有一個 bit**：

```
FR.foot  flags = 0x002A1E01     →  01 1E 2A 00  （ready=1, 30°C, 42V）
RR.foot  flags = 0x002A1D00     →  00 1D 2A 00  （ready=0, 29°C, 42V）
                                    ↑↑
                              只有 bit0（ready）不同
```

### 3.2 初期狀態（8/11 上午）：該馬達並未斷線，僅拒絕啟用

在 11:40～12:26 這段 41 分鐘的連續記錄（24,390 筆有效樣本）中，異常的 `RR.foot` **仍在正常通訊**：

- 溫度**恆定回報 29°C**（41 分鐘內只出現這一個值）、母線電壓 42～44V
- **編碼器完全正常**：在 `ready=0` 狀態下用手轉動該輪，位置讀數完整追蹤了 **314°（5.483 rad）** 的轉動，同時其他三顆輪子的讀數變動小於 0.015 rad（僅雜訊）
- 五個保護位（過壓 / 過流 / 過溫 / 超速 / 雙編碼器故障）**全部為 0**
- 該期間**只有這一顆**馬達 `ready != 1`，其餘 15 顆全程正常

作為對照：**真正從 CAN 失聯**的節點，其溫度與電壓欄位會被歸零（讀到 `0°C / 0V`）。當時的 `RR.foot` 不屬於此情況。

**初期結論：通訊、編碼器、溫度感測、電壓感測皆正常，異常僅在於「馬達拒絕進入 ready / 啟用狀態」，且未回報任何原因。**

### 3.3 惡化後狀態（8/11 下午）：通訊變成間歇且資料損壞

同日下午（機器時鐘 14:30 以後）狀況明顯惡化。以 3 秒間隔取樣 30 秒的實測結果：

```
時間    RR.foot            對照：FR.foot / FL.foot / RL.foot
  0s     0°C /  0V  *          26°C / 47V   26°C / 48V   26°C / 47V
  3s     0°C / 48V  *          （三顆全程完全不變）
  6s    95°C / 48V  *
  9s     0°C /  0V  *
 12s     0°C / 48V  *
 15s    95°C / 48V  *
 18s    28°C / 48V  *
 21s    95°C / 48V  *
 24s     0°C / 48V  *
 27s     0°C /  0V  *
 30s    44°C / 48V  *
                              * = ready=0
```

**溫度欄位在 3 秒內於 0 / 28 / 44 / 95°C 之間跳動**，而其他三顆輪馬達在同一時間完全穩定（26°C / 47～48V 一動不動）。實體馬達不可能在數秒內產生如此溫度變化，因此這**不是真實溫度，而是該節點的資料時而送達、時而缺失或損壞**。

**惡化前後對比：**

| | 上午（11:40～12:26） | 下午（14:30 後） |
|---|---|---|
| `RR.foot` 溫度讀值 | **恆定 29°C**（單一值） | 0 / 28 / 44 / 95 之間亂跳 |
| `RR.foot` 電壓讀值 | 42～44V（穩定） | 0V 與 48V 交替 |
| `RR.abad / hip / knee` | ✅ 全部正常 | ❌ **全部 `0°C / 0V`，已完全從 CAN 失聯** |
| 存活馬達 | 15 / 16 | **12 / 16** |

**惡化後結論：右後腿的通訊已從「單一顆馬達拒絕啟用」惡化為「整條腿三顆完全失聯 + 第四顆間歇性通訊損壞」。此模式（單一分支、間歇性、資料損壞、逐日惡化）符合該腿線束或該馬達驅動器的電氣性故障。**

### 3.3 溫度正常，但驅動板溫度無法量測

故障發生時該馬達溫度為 **29°C**，是該腿四顆馬達中最低的一顆，且長時間穩定不變。SoC 各溫度感測點也全部正常（42～45°C）。

但我們**無法排除驅動板電子元件過熱**——`spline_shm` 回報的應是馬達繞組溫度，驅動板上功率元件的溫度並未透過此介面暴露。而「通電數分鐘後才發生、必須斷電才能恢復」的行為特徵，與此假說相符。

**惡化是在同一天之內發生的**，且方向明確：從單一顆馬達的乾淨 `ready=0`（資料完好），變成整條腿失聯加資料損壞。先前 abad 一直是存活的。

**建議原廠一併評估：此惡化速率是否代表線束或驅動器有持續損壞的風險，機器在維修前是否應該停止通電。**
