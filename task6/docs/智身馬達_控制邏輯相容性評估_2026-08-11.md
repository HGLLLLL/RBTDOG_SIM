# 智身科技關節模組 — 控制邏輯相容性評估

**評估日期**：2026-08-11
**更新日期**：2026-08-12 —— 改用 .rar 內的新版規格書（見下），並新增第五章「單獨測試單顆馬達」
**評估問題**：智身的這批馬達，能不能用我們現在在 D1 EDU（輪足版）上使用的控制方式與邏輯來驅動？
與現有馬達相比，有沒有**根本上的不同**？
**評估依據**：`智身馬達/` 資料夾內的 `程序示例.pdf`、三份型號規格圖（P65 / P85MAX-S / W190-S），
以及我們 2026-08-10～11 在 D1 EDU 實機上取得的實測資料。

> **⚠️ 規格書有兩個版本，以 .rar 內的為準。**
> 資料夾裡散落的三份 PDF（`P65-…20260423`、`P85MAX-S…20260410`、`W190-S…20260410`）
> 是**舊版**；同資料夾的三個 .rar 壓縮檔裡各有一份**新版**（`…20260710`、`…20260713`），
> 除了規格數字更新，還多了**接線／線束圖**與效率 map。本文第二章已改用新版數字。
> 初版（2026-08-11）引用的是舊版，數字偏低。

---

## 結論

**沒有根本上的不同。控制邏輯是同一套，可以照搬。**

三句話摘要：

1. **控制律完全相同** —— 兩者都是「位置 + 速度 + 剛度 + 阻尼 + 前饋力矩」五參數阻抗控制，
   力矩合成公式一字不差。這是 MIT Mini Cheetah 血統的關節模組通用作法。
2. **狀態回授與故障碼排列也相同** —— 故障位 bit 0～5 逐位對應，智身多一個 bit6。
3. **主要差別是「尺寸級距」與「我們站在哪一層」** —— 馬達本身沒有本質差異，
   但在 D1 EDU 上我們是站在原廠抽象層之後，而這批馬達是「裸」的。
   **這是機器人整合架構的差別，不是馬達的差別。**

## 一、控制邏輯對照：沒有根本不同

### 1.1 下行指令：完全相同的五參數

| 智身（`程序示例.pdf`） | D1 EDU（`/dev/shm/spline_shm`） | 是否相同 |
|---|---|---|
| `val_sb_p` 位置值 | `p_des` | ✅ |
| `val_sb_v` 速度值 | `v_des` | ✅ |
| `val_sb_kp` KP 值 | `kp` | ✅ |
| `val_sb_kd` KD 值 | `kd` | ✅ |
| `val_sb_t` 力矩 | `t_ff` | ✅ |

兩者都對應同一條力矩合成公式：

```
t = kp × (p_des − p) + kd × (v_des − v) + t_ff
```

> 這條公式我們已在 D1 EDU 實機驗證過（預測 vs 實測平均差約 0.01 N·m）。
> 智身的文件雖未明列公式，但參數集合與命名完全一致，屬同一控制範式。

**意義**：我們現有的 policy 輸出、增益選擇邏輯、動作規劃（內插、維持、卸力），
在參數層面**不需要任何改寫**。

### 1.2 上行狀態：相同的資料集合

| 智身 `data_frame2value()` | D1 EDU `JointState` |
|---|---|
| `position` | `p` |
| `speed` | `v` |
| `torque` | `t` |
| `motorTemperature` | 打包在 `flags` bit 8–15 |
| `motorFaultRecv` | `flags` bit 0–6 |
| `motorVoltageRecv` | 打包在 `flags` bit 16–23 |

### 1.3 故障位：bit 0–5 逐位相同

| bit | 智身 | D1 EDU | 對應 |
|---|---|---|---|
| 0 | `motorEnableRecv` 使能／失能 | `ready` | ✅ |
| 1 | 过压故障 | 過壓 | ✅ |
| 2 | 过流故障 | 過流 | ✅ |
| 3 | 过温故障 | 過溫 | ✅ |
| 4 | 过速故障 | 超速 | ✅ |
| 5 | 双编码故障 | 雙編碼器故障 | ✅ |
| 6 | **预驱故障**（閘極驅動器） | — | ⚠️ 智身多這一個 |

六位完全對齊，是判定「同一協定家族」最強的證據。

> **附帶發現**：智身多的 bit6「预驱故障」，我們現有的診斷工具（`L5_faultwatch.py`、
> `L4_standup_shm.py`）沒有解碼。已回頭檢查 2026-08-11 右後輪故障當下抓到的原始
> flags（`0x002A1D00`），該位為 0，所以不是那次故障的成因；但建議補上，日後診斷用得到。

## 二、規格對照：確實「只是比較大」

數字取自 .rar 內新版規格書（2026-07-10 / 07-13）：

| 型號 | 額定扭矩 | 峰值／堵轉扭矩 | 最大轉速 | 質量 | 減速比 | 背隙 | 防護 | 工作電壓（標稱） | 定位 |
|---|---|---|---|---|---|---|---|---|---|
| **P85MAX-S** | 52 N·m | 220 N·m | 160 rpm | 1010 g | 39 | ≤20′ | IP67 | 24–72 V（60） | 大關節（hip / knee） |
| **P65** | 12 N·m | 45 N·m | 300 空載 / 280 負載 rpm | 562 g | 17 | ≤20′ | IP54 | 24–60 V（48） | 小關節（abad） |
| **W190-S** | 11.16 N·m | 35 N·m | 1100 rpm | 1238 g | 6 | ≤25′ | IP67 | 24–72 V（60） | 輪子（Ø192 mm 帶胎紋） |

共通：CAN-FD 通訊、行星減速。

> **銘牌數字變大不是產品改版，是標稱電壓改了。** 新版 P85MAX-S 的 T-n 曲線標 @60 V 時，
> 峰值仍是 180 N·m、額定 43 N·m，與舊版一致；銘牌的 52 / 220 是 72 V 下的值。
> W190-S 同理（@60 V 曲線為額定 8、峰值 28）。P65 兩版都以 48 V 標稱，故無此落差。
> **選型與力矩餘裕計算請認明電壓**，以下沿用 @60 V（P65 @48 V）的保守值。

新版另補充：
- **效率 map** —— P85MAX-S 最高 75.3%（43.7 N·m @130 rpm）、W190-S 最高 76.8%（6.5 N·m @600 rpm）
- **T-i 曲線** —— 三型皆有，但橫軸是 **q 軸電流 Iq，不是母線電流**，不能直接拿來選電源（見 §5）
- **接線／線束圖** —— 見 §5.1，這是相對初版最重要的新增
- P85MAX-S 動態負載：徑向 53.7 N·m / 5.84 kN、軸向 143.2 N·m / 25.5 kN；編碼器為雙絕對值

**這是一套完整的輪足機器狗套件**（每腿 3 關節 + 1 輪），與 D1 EDU 同架構。

### 尺寸級距：明顯大於 D1 EDU

以我們在 D1 EDU 實機量到的需求對照：

| 情境 | 實測關節力矩 |
|---|---|
| 吊掛（腿只撐自己 3.46 kg） | knee 1.71、abad 1.92–2.69、hip 0.59 N·m |
| **落地站立**（承載 20.56 kg 機身，原廠實測） | **abad 7.6–9.0、knee 4.3–5.2、hip ≤1.5 N·m** |

- P85MAX-S 額定 43 N·m（@60 V）→ 相對 D1 EDU 的需求有 **5–9 倍餘裕**
- P65 額定 12 N·m 給 abad 也相當寬裕

**單腿馬達質量**：0.562 + 1.01 + 1.01 + 1.238 = **3.82 kg**
對照 D1 EDU 整條腿（含結構件）僅 **3.46 kg** —— 也就是**光馬達就比 D1 EDU 的完整腿還重**。
（初版按舊版規格算為 3.88 kg，改用新版質量後為 3.82 kg，結論不變。）

→ 這批馬達的設計目標是比 D1 EDU 明顯更大的機器（粗估 2–4 倍體重）。
用在同尺寸的狗上會過規格：更重、更貴，而且腿變重會直接吃掉動態性能
（D1 EDU 現況腿已佔全機質量的 67%）。**這是選型問題，不是相容性問題。**

## 三、真正需要注意的差異（但不是馬達的差異）

以下三點常被誤認為「馬達不同」，實際上是**整合架構的位置不同**：

### 3.1 我們現在站在原廠抽象層之後

| | D1 EDU（現況） | 裸馬達 |
|---|---|---|
| 我們寫入的目標 | 共享記憶體（一道 store 指令） | CAN-FD 匯流排 |
| 誰負責 CAN 收發與組幀 | 原廠 `spline_daemon` | 整合者自行實作 |
| 資料型別 | 直接寫 float | 需 float↔uint16 線性打包 |
| 1 kHz 控制迴圈 | 原廠已建好，綁在隔離核心 | 需自行建立 |
| 安全 watchdog | daemon 內建（停止送幀即自動癱軟） | **需確認是否內建，見 §4** |

**D1 EDU 的馬達本身也是 CAN 馬達**（實機日誌可見 `spline_board` 回報的 `CAN BUS ERR`），
只是原廠提供了 `spline_board` 韌體 + `spline_daemon` 這層橋接。
**所以差別不在馬達，而在於有沒有現成的橋接層可用。**

### 3.2 線上資料格式不同，但語意相同

智身走 CAN-FD，每欄以 16-bit 整數線性映射傳送（`float_to_uint`）；
D1 EDU 在共享記憶體層已經是 float。**這是編解碼細節，不影響控制語意。**

### 3.3 溫度偏移：兩邊都對，只是層級不同

智身文件寫 `motorTemperature = pData[8] - 40`。
D1 EDU 的 SHM 讀到的**已經是實際攝氏度**（實測腿關節 42–47 °C、輪子 29–31 °C，合理），
因為 `spline_daemon` 已代為換算。

> 我們原本的 `L0_shm_probe.cpp` 把 CAN 層的 −40 慣例抄到了 SHM 層，等於減兩次，
> 會顯示成 2–7 °C 這種不合理數值。已於 2026-08-11 修正（commit `cd7c8cf`）。
> **這正好說明：同一個協定家族在不同抽象層會有不同的呈現，比對時要注意層級。**

## 四、尚未確認的事項（採用決策層級）

就「能不能用」這個問題本身，只有一項需要在採用前確認：

> **⚠️ 馬達端是否內建通訊逾時保護。** D1 EDU 的 `spline_daemon` 有 watchdog，
> 上位機一停止送幀，馬達指令會自動歸零而癱軟。若智身馬達在斷訊後會**維持最後一筆指令**，
> 則安全機制必須由整合者自行實作 —— 這是控制架構上的實質差異，也是唯一一項會
> 改變「照搬」結論的變數。

其餘缺漏（參數上下限、使能指令、CAN ID 與匯流排參數、上電流程）都屬**動手層級**，
不影響相容性判斷，但會直接擋住台架測試。**完整清單見第五章。**

## 五、若要「單獨測試單顆馬達」，還差哪些資訊

**情境**：馬達還沒裝上機構，想先在桌面／台架上單獨接一顆，確認它會按指令轉、
讀得到位置與溫度。**不使用狗的車載電腦。**

### 5.0 先講結論：這件事在智身馬達上做得到，在 D1 EDU 上做不到

| | D1 EDU | 智身 |
|---|---|---|
| 馬達怎麼接 | CAN 被 `spline_board` 韌體 + `spline_daemon` 封住，只露出共享記憶體 | **裸 CAN-FD 直出** |
| 能否用筆電單獨驅動一顆 | ❌ 必須透過車載電腦 | ✅ 筆電 + USB-CAN-FD 轉接器即可 |

馬達本身不認識「狗的電腦」，它只認 CAN 幀，誰送都一樣。
而且**台架測試不需要 1 kHz 硬即時**（那是整機走路才需要的），
Python + SocketCAN 就足夠 —— §3.1 提到的即時性難點在這個情境下不成立。

### 5.1 已經具備的（不用再問）

| 項目 | 來源 |
|---|---|
| 下行幀格式：CAN-FD、frame ID `0`、DLC 64 B（32×uint16），每顆佔 5 欄，`motor_index = (did−1)×5+1`，一幀最多 6 顆 | `程序示例.pdf` |
| 欄位順序與空閒值：`p, v, kp, kd, t` = `0x7FFF, 0x7FFF, 0x0000, 0x0000, 0x7FFF`（`0x7FFF` 為 16-bit 中點 → p/v/t 為對稱範圍，kp/kd 由 0 起算） | 同上 |
| 編解碼公式 `float_to_uint` / `uint_to_float`（16-bit 線性映射） | 同上 |
| 回覆幀：長度 12 B，`position`／`speed`／`torque`（uint16 小端）+ 溫度（`pData[8]−40`）+ 故障位元組 + 電壓位元組 | 同上 |
| 故障位 bit 0–6 定義 | 同上，見 §1.3 |
| **接線定義** ← 2026-08-12 新增 | .rar 內新版規格書 |

**接線（新版規格書提供）**：

- **P85MAX-S / W190-S** —— 防水端子（圖名 `P85_防水端子和线束`，兩型共用）：
  `VBUS`(紅)、`GND`(黑)、`CAN_H`(綠)、`CAN_L`(白)；16AWG×2C + 26AWG×1P 屏蔽線，
  OD 7.3、灰色、長 250 mm（可依需求改長度）、2×M3 鎖固、線束耐溫 105 °C
- **P65** —— 規格書第 2 頁圖名直接就是 **「P65_单独测试线」**：
  `VBUS`(紅)、`GND`(黑)、`CAN-H`(紅)、`CAN-L`(黑)；UL3135 18AWG 矽膠電源線 +
  UL10064 26AWG 訊號線，長 200±10 mm、端頭沾錫 5 mm

> **廠商本身就有為「單顆馬達單獨測試」設計的料件。** 這代表台架單測是原廠預期中的流程，
> 向廠商索取時可直接報這個品名（「P65 单独测试线」），不必自己描述需求。
> P85MAX-S / W190-S 是否也有對應的裸線測試版本，需一併確認。

### 5.2 缺 A 級：沒有就發不出有效指令（阻斷）

| # | 缺什麼 | 為什麼卡死 |
|---|---|---|
| A1 | **各參數上下限**：`p_max/p_min`、`v_max/v_min`、`kp/kd/t` 的範圍，以及各欄位元寬是否都是 16 | `float_to_uint` 的分母就是 `x_max − x_min`。範例全部以 `self.sb_p_max` 這類變數帶過，**一個數字都沒有** → 連第一幀都組不出來 |
| A2 | **使能／失能指令格式**（另含零點設定、控制模式切換） | 回覆幀明明在解 `motorEnableRecv`，代表有使能狀態機，但**怎麼讓它使能完全沒寫**。不使能就是不轉，而且不報錯 |
| A3 | **CAN ID 分配**：`did` 從哪來、出廠預設 ID、怎麼修改；接收端 `motion_no` 的定義 | 範例中 `if can_id == motion_no` 的 `motion_no` 未定義；不知道 ID 就收不到也送不對 |
| A4 | **CAN-FD 匯流排參數**：仲裁段／資料段鮑率、取樣點、是否啟用 BRS | 時序對不上就完全不通，且現象只是「一片沉默」，無法區分是接線錯、時序錯還是沒使能 |
| A5 | **`dl[0]` 與 `dl[31]` 兩欄的定義** | 幀首尾各多一個 uint16，範例填 0 但沒解釋（模式字？校驗？） |

> **A1 不能用業界慣例猜。** MIT Mini Cheetah 系的常見值是 P ±12.5 rad、V ±45 rad/s、
> KP 0–500、KD 0–5、T ±18 N·m，但 P85MAX-S 峰值 180–220 N·m 是慣例值的十倍，
> 範圍必然被改過。若 KP 實際範圍是 0–5000 而按 0–500 打包，下 `kp=20` 馬達收到的是 `kp=200`
> —— 十倍剛度接在 180 N·m 的東西上，台架會直接跳起來，而且不會有溫和的預警。

### 5.3 缺 B 級：沒有就不該通電（安全）

| # | 缺什麼 | 風險 |
|---|---|---|
| B1 | **斷訊逾時保護**（＝§4 那一項） | 台架單測時按 Ctrl+C 停程式，若馬達維持最後一筆力矩不放，人就站在旁邊 |
| B2 | **上電初始化流程**、首次通訊前的預設狀態 | 上電當下是否已使能？是否會帶著上次的指令？ |
| B3 | **保護門檻與安全上限**：過流／過溫閾值、限速、是否有內建力矩鉗位 | 決定我們自己要不要再包一層限幅 |
| B4 | **緊急停止／卸力指令** | 出事時要能一鍵癱軟；不能只靠斷電（斷電對編碼器與煞停行為的影響也未知） |

### 5.4 缺 C 級：有會快很多（便利）

| # | 缺什麼 | 用途 |
|---|---|---|
| C1 | **原廠上位機調試軟體**（Windows GUI） | 這類關節模組廠商多半配一套（USB-CAN 轉接器 + 調參／試轉介面）。**有的話連程式都不用寫**，插上去就能單顆試轉、設零點、看溫度 —— 這是最快的路徑，應優先問 |
| C2 | **測試線品名／圖號**，以及 P85MAX-S / W190-S 是否也有裸線測試版 | 直接下單，不用自製 |
| C3 | **廠商驗證過的 USB-CAN-FD 轉接器型號** | 避開時序／韌體相容性踩坑 |
| C4 | **額定／峰值母線電流** | 選電源供應器用。規格書的 T-i 曲線橫軸是 **q 軸電流 Iq**（P85MAX-S 約 97 A 對應 180 N·m），**不等於母線電流**，不能直接拿來挑電源 |

### 5.5 硬體：不必等廠商，現在就能準備

| 品項 | 規格 | 備註 |
|---|---|---|
| USB-to-CAN-FD 轉接器 | 需支援 CAN-FD（非傳統 CAN） | Linux 下走 SocketCAN 最省事；型號建議先問廠商（C3） |
| 可調直流電源 | P65 → 48 V；P85MAX-S / W190-S → 60 V | 電流待 C4 確認後再定，勿只按 T-i 曲線估 |
| 終端電阻 | 120 Ω × 2（匯流排兩端） | 少了會通訊不穩 |
| 台架固定夾具 | **P85MAX-S 堵轉 220 N·m** | 必須確實鎖死，這個力矩會把沒固定好的東西甩飛 |

### 5.6 一句話

**接線已經知道怎麼接，幀長什麼樣也知道，但幀裡要填什麼數字不知道，
而且不知道怎麼叫它使能。** 缺的是 A 級五項 + B 級四項，
其中 **A1（參數上下限）和 A2（使能指令）是硬阻斷**，沒有這兩項連轉都轉不起來。
這些一定在廠商的完整 CAN 協定手冊裡（參數範圍表、指令碼表、CAN ID 分配表），
只是目前給我們的三份文件都不含 —— `程序示例.pdf` 的體裁是「回傳值怎麼解讀」，
本來就不涵蓋「怎麼讓它動」。

---

## 六、給決策者的一句話

**這批馬達與 D1 EDU 現有馬達屬於同一控制範式，控制邏輯可以直接沿用，
不存在需要改變控制架構的根本差異。主要差別是尺寸級距偏大，以及缺少現成的
上位橋接層——後者是整合工作量的問題，不是相容性的問題。**

唯一需要在採用前確認的技術風險，是 §4 的斷訊保護行為。

**若只是想先單獨測一顆馬達**（尚未組裝），這件事本身可行 —— 但目前手上的文件還不足以
發出第一幀有效指令，必須先向廠商取得 §5.2 的 A 級五項與 §5.3 的 B 級四項。
