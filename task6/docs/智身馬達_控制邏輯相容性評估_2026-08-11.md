# 智身科技關節模組 — 控制邏輯相容性評估

**評估日期**：2026-08-11
**評估問題**：智身的這批馬達，能不能用我們現在在 D1 EDU（輪足版）上使用的控制方式與邏輯來驅動？
與現有馬達相比，有沒有**根本上的不同**？
**評估依據**：`智身馬達/` 資料夾內的 `程序示例.pdf`、三份型號規格圖（P65 / P85MAX-S / W190-S），
以及我們 2026-08-10～11 在 D1 EDU 實機上取得的實測資料。

---

## 結論

**沒有根本上的不同。控制邏輯是同一套，可以照搬。**

三句話摘要：

1. **控制律完全相同** —— 兩者都是「位置 + 速度 + 剛度 + 阻尼 + 前饋力矩」五參數阻抗控制，
   力矩合成公式一字不差。這是 MIT Mini Cheetah 血統的關節模組通用作法。
2. **狀態回授與故障碼排列也相同** —— 故障位 bit 0～5 逐位對應，智身多一個 bit6。
3. **主要差別是「尺寸級距」與「我們站在哪一層」** —— 馬達本身沒有本質差異，
   但在 D1 EDU 上我們是站在原廠抽象層之後，而這批馬達是「裸」的。
   **這是機器人整合架構的差別，不是馬達的差別。**

---

## 一、控制邏輯對照：沒有根本不同

### 1.1 下行指令：完全相同的五參數

| 智身（`程序示例.pdf`） | D1 EDU（`/dev/shm/spline_shm`） | 是否相同 |
|---|---|---|
| `val_sb_p` 位置值 | `p_des` | ✅ |
| `val_sb_v` 速度值 | `v_des` | ✅ |
| `val_sb_kp` KP 值 | `kp` | ✅ |
| `val_sb_kd` KD 值 | `kd` | ✅ |
| `val_sb_t` 力矩 | `t_ff` | ✅ |

兩者都對應同一條力矩合成公式：

```
t = kp × (p_des − p) + kd × (v_des − v) + t_ff
```

> 這條公式我們已在 D1 EDU 實機驗證過（預測 vs 實測平均差約 0.01 N·m）。
> 智身的文件雖未明列公式，但參數集合與命名完全一致，屬同一控制範式。

**意義**：我們現有的 policy 輸出、增益選擇邏輯、動作規劃（內插、維持、卸力），
在參數層面**不需要任何改寫**。

### 1.2 上行狀態：相同的資料集合

| 智身 `data_frame2value()` | D1 EDU `JointState` |
|---|---|
| `position` | `p` |
| `speed` | `v` |
| `torque` | `t` |
| `motorTemperature` | 打包在 `flags` bit 8–15 |
| `motorFaultRecv` | `flags` bit 0–6 |
| `motorVoltageRecv` | 打包在 `flags` bit 16–23 |

### 1.3 故障位：bit 0–5 逐位相同

| bit | 智身 | D1 EDU | 對應 |
|---|---|---|---|
| 0 | `motorEnableRecv` 使能／失能 | `ready` | ✅ |
| 1 | 过压故障 | 過壓 | ✅ |
| 2 | 过流故障 | 過流 | ✅ |
| 3 | 过温故障 | 過溫 | ✅ |
| 4 | 过速故障 | 超速 | ✅ |
| 5 | 双编码故障 | 雙編碼器故障 | ✅ |
| 6 | **预驱故障**（閘極驅動器） | — | ⚠️ 智身多這一個 |

六位完全對齊，是判定「同一協定家族」最強的證據。

> **附帶發現**：智身多的 bit6「预驱故障」，我們現有的診斷工具（`L5_faultwatch.py`、
> `L4_standup_shm.py`）沒有解碼。已回頭檢查 2026-08-11 右後輪故障當下抓到的原始
> flags（`0x002A1D00`），該位為 0，所以不是那次故障的成因；但建議補上，日後診斷用得到。

## 二、規格對照：確實「只是比較大」

| 型號 | 額定扭矩 | 峰值扭矩 | 最大轉速 | 質量 | 防護 | 定位 |
|---|---|---|---|---|---|---|
| **P85MAX-S** | 43 N·m | 180 N·m | 145–160 rpm | 1010 g | IP67 | 大關節（hip / knee） |
| **P65** | 11.5 N·m | 48 N·m | 268–280 rpm | 520 g | IP54 | 小關節（abad） |
| **W190-S** | 8.7 N·m | 28.68 N·m | 950–1050 rpm | 1340 g | IP67 | 輪子（Ø192 mm 帶胎紋） |

共通：CAN-FD 通訊、24–60 V、行星減速、背隙 ≤20 arcmin。P65 力矩常數 0.0874 N·m/A。

**這是一套完整的輪足機器狗套件**（每腿 3 關節 + 1 輪），與 D1 EDU 同架構。

### 尺寸級距：明顯大於 D1 EDU

以我們在 D1 EDU 實機量到的需求對照：

| 情境 | 實測關節力矩 |
|---|---|
| 吊掛（腿只撐自己 3.46 kg） | knee 1.71、abad 1.92–2.69、hip 0.59 N·m |
| **落地站立**（承載 20.56 kg 機身，原廠實測） | **abad 7.6–9.0、knee 4.3–5.2、hip ≤1.5 N·m** |

- P85MAX-S 額定 43 N·m → 相對 D1 EDU 的需求有 **5–9 倍餘裕**
- P65 額定 11.5 N·m 給 abad 也相當寬裕

**單腿馬達質量**：0.52 + 1.01 + 1.01 + 1.34 = **3.88 kg**
對照 D1 EDU 整條腿（含結構件）僅 **3.46 kg** —— 也就是**光馬達就比 D1 EDU 的完整腿還重**。

→ 這批馬達的設計目標是比 D1 EDU 明顯更大的機器（粗估 2–4 倍體重）。
用在同尺寸的狗上會過規格：更重、更貴，而且腿變重會直接吃掉動態性能
（D1 EDU 現況腿已佔全機質量的 67%）。**這是選型問題，不是相容性問題。**

## 三、真正需要注意的差異（但不是馬達的差異）

以下三點常被誤認為「馬達不同」，實際上是**整合架構的位置不同**：

### 3.1 我們現在站在原廠抽象層之後

| | D1 EDU（現況） | 裸馬達 |
|---|---|---|
| 我們寫入的目標 | 共享記憶體（一道 store 指令） | CAN-FD 匯流排 |
| 誰負責 CAN 收發與組幀 | 原廠 `spline_daemon` | 整合者自行實作 |
| 資料型別 | 直接寫 float | 需 float↔uint16 線性打包 |
| 1 kHz 控制迴圈 | 原廠已建好，綁在隔離核心 | 需自行建立 |
| 安全 watchdog | daemon 內建（停止送幀即自動癱軟） | **需確認是否內建，見 §4** |

**D1 EDU 的馬達本身也是 CAN 馬達**（實機日誌可見 `spline_board` 回報的 `CAN BUS ERR`），
只是原廠提供了 `spline_board` 韌體 + `spline_daemon` 這層橋接。
**所以差別不在馬達，而在於有沒有現成的橋接層可用。**

### 3.2 線上資料格式不同，但語意相同

智身走 CAN-FD，每欄以 16-bit 整數線性映射傳送（`float_to_uint`）；
D1 EDU 在共享記憶體層已經是 float。**這是編解碼細節，不影響控制語意。**

### 3.3 溫度偏移：兩邊都對，只是層級不同

智身文件寫 `motorTemperature = pData[8] - 40`。
D1 EDU 的 SHM 讀到的**已經是實際攝氏度**（實測腿關節 42–47 °C、輪子 29–31 °C，合理），
因為 `spline_daemon` 已代為換算。

> 我們原本的 `L0_shm_probe.cpp` 把 CAN 層的 −40 慣例抄到了 SHM 層，等於減兩次，
> 會顯示成 2–7 °C 這種不合理數值。已於 2026-08-11 修正（commit `cd7c8cf`）。
> **這正好說明：同一個協定家族在不同抽象層會有不同的呈現，比對時要注意層級。**

## 四、尚未確認的事項（建議向廠商索取）

以下資訊不在現有文件中。**其中第 3 項具安全意義，建議優先確認。**

1. **各參數的上下限**（`p_max/p_min`、`v_max/v_min`、`kp/kd/t` 範圍）
   —— `float_to_uint` 的線性映射需要，範例程式中以 `self.sb_p_max` 等變數帶過，未給數值
2. **使能／失能、零點設定、控制模式切換**的指令格式 —— 文件完全未涵蓋
3. **⚠️ 馬達端是否內建通訊逾時保護** —— D1 EDU 的 daemon 有 watchdog，
   上位機一停止送幀，馬達指令會自動歸零而癱軟。若智身馬達在斷訊後會**維持最後一筆指令**，
   則安全機制必須由整合者自行實作，這是控制架構上的實質差異
4. **CAN ID 分配方式與匯流排參數**（鮑率、CAN-FD 時序）
5. **上電初始化流程**

---

## 五、給決策者的一句話

**這批馬達與 D1 EDU 現有馬達屬於同一控制範式，控制邏輯可以直接沿用，
不存在需要改變控制架構的根本差異。主要差別是尺寸級距偏大，以及缺少現成的
上位橋接層——後者是整合工作量的問題，不是相容性的問題。**

唯一需要在採用前確認的技術風險，是 §4 第 3 項的斷訊保護行為。
