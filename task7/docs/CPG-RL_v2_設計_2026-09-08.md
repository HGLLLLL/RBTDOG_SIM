## 0. 三句話

> 基準換成實機走過的 **`A_kp250_walk`**（LS / kp250 / abad60 / kd2），動作加 **body sway (x,y)** 直攻搖擺根因

## 3. Colab 流程

1. 本機：`git push origin main`（notebook 用 `--depth 1` clone `main`，沒 push 的它看不到）
2. Colab 開 `task7/notebooks/cpg_rl_max_colab.ipynb`，執行階段選 GPU，**全部執行**
3. 第 3 格印 clone 到的 commit —— 要對得上本機 `git log -1`
4. 第 5 格「基準校準」：基準動作 500 步不能 done；`tau_pk` 平均要 < 58、`err_pk` < 0.45；
   `roll`/`exec_f`/`exec_r` 與本機 G0 同量級
5. 第 6 格第一個 eval 印實測步率與「60M 約幾分」—— 超過 3 小時就把 `TIMESTEPS` 砍到 40M 重跑
6. 訓練中看：`roll` 要往下、`exec f/r` 往 1 靠、`tau_pk` 一路 < 58、`len` 維持 1000
7. 下載 `cpg_rl_max_v2_params.pkl` → `task7/weights/`
8. 本機驗收：
   ```
   conda run --no-capture-output -n rbtdog python task7/inference/local_infer_max.py \
       --params task7/weights/cpg_rl_max_v2_params.pkl --secs 60 --perturb 12 --compare --video
   # 再跑 --secs 180 --perturb 12 ；--wz 0.3 --secs 20 ；--wz -0.3 --secs 20 ；--vx 0.30 --secs 20
   ```
   G3–G7 一次印完；**G7 ❌ → 不上機**，回 `rl_env_max.py` 調權重重訓。

## 5. 風險（spec §9 摘要）

- RL 版 sway 沒上過機；G7 是唯一守門員。
- 模擬 z 方向順從性高估 1.8×；G4 的 60% 是模擬內相對值，實機要再驗。
- 基準已貼近力矩護欄（55.7 vs 58）→ policy 若學不到比基準更省力的走法，護欄項會常態小額扣分；
  校準格印出來後若基準常態 > 58，把 `TAU_BAR` 調到 62（仍 ×1.2 < 75，需同步放寬 G7 的說法）——**先看數字再決定**。
- 狗上推論尚未實作（另開 spec）。

## 6. v2.1（2026-09-08 下午，訓練中即時修正）

v2 跑到 23M 步：航向/速度/俯仰都學到（yawerr 0.53→0.10、vxerr 0.20→0.06、pitch −42%），
**但第一目標 roll 只降 12%**（2.34°→2.06°）。原因用 `diag/rl_calibrate.py` 量出來：
基準動作上 **roll＋roll rate 兩項只佔正項 2.7%**（W_ROLL=20 在 roll 2.3° 時每步只扣 0.03 分），policy 有理由忽略。

| 佔正項 | v2 | **v2.1** |
|---|---|---|
| roll + roll rate | 2.7% | **18%** |
| pitch + pitch rate | 1.5% | 6.6% |
| exec | 30% | 43%（σ 30→50 mm；指令對上時正項變大，約 30%）|
| 護欄（taubar / errbar） | 0 | 0（基準不碰）|

權重：`W_ROLL 20→150、W_ROLLRATE 0.05→0.5、W_PITCH 20→100、W_PITCHRATE 0.05→0.3、W_EXEC 1→1.5、EXEC_SIGMA 0.03→0.05`；
護欄、終止、隨機化、動作空間全部不動。

實作：`rl_env_max.PRESETS["v2.1"]`、`MaxCpgEnv(preset=…)`（預設 `"v2"`，舊 notebook 行為不變）；
metrics 多了每一項 reward 的 `t_*`，`diag/rl_calibrate.py` 印佔比；
測試 `test_v2_1_reward_shares_on_baseline` 把「roll 兩項 10–25%、pitch 3–15%、exec ≤50%、護欄 ≈0」釘成會失敗的條件；
新 notebook **`notebooks/cpg_rl_max_v2_1_colab.ipynb`**（校準格同樣斷言佔比與訓練模型增益 = KP3_A），權重 `cpg_rl_max_v2_1_params.pkl`。
兩個 notebook 可平行跑；v2 權重仍拿回來跑 G3–G7 當對照。

### 6.1 v2 權重回來的 G3–G7（60 s × 12 擾動，原始網格模型；`outputs/cpg_rl_max_v2.mp4`）

| 關卡 | v2 | 基準 | 判定 |
|---|---|---|---|
| G3 跌倒 | 0/12 | 0/12 | ✅ |
| G4 roll 峰值／std | 4.06° / 2.09° | 3.88° / 2.57° | ❌ 峰值沒降（std −19%）|
| G5 執行率 前／後 | 0.79 / 1.13 | 0.88 / 1.47 | ❌ 後腳過衝修一半，前腳退 |
| **G6 60 s 偏航** | **+48°** | +4.4° | ❌ **比開迴路差 10 倍** |
| G7 護欄 | 56.6×1.2 = 67.9、誤差 0.322 | 66.8 / 0.295 | ✅（貼線）|

速度追蹤 0.15→0.14、俯仰週期 4.2°→2.8°、彈跳持平。**同權重在 MJX 訓練模型上偏航 +45° → 不是 sim2sim 落差，是 policy 本身漂。**

根因：偏航核 `exp(−(wz−cmd)²/0.05)`（σ ≈ 13°/s）對 0.8°/s 的漂移只掉 0.4%，reward 看不見；
而瞬時 wz 被 1.4 Hz 步態振盪（std 0.64 rad/s！）淹沒，核寬收窄也沒用。
量了基準的 wz EMA 分布（1 s：±0.07、2 s：±0.036、4 s：±0.018、8 s：±0.009 rad/s）後定案：
**4 s EMA（α 0.005）＋ σ²=0.0005 ＋ W_YAW 1.5** → 基準 r_yaw 0.60、漂 0.8°/s 掉到 ≈0.40（差 0.3 分/步 ≈ 正項 10%）。
8 s 對比更好但轉彎指令要等 8 s 才有分，20 s episode 太慢。

v2.1 定版佔比（固定指令 vx 0.15 / wz 0，`rl_calibrate.py`）：**yaw 28%、exec 34%、roll+rate 14%、pitch+rate 5%、vx 13.5%**；護欄 0。
v2.1 改的鍵：`W_ROLL 150 / W_ROLLRATE 0.5 / W_PITCH 100 / W_PITCHRATE 0.3 / W_EXEC 1.5 / EXEC_SIGMA 0.05 / W_YAW 1.5 / YAW_SIG2 0.0005 / YAW_EMA 0.005`。

## 7. v2 為什麼比開迴路差、v2.2 怎麼改（2026-09-08 晚；文獻 + 數據）

使用者看影片：前後腳明顯不對稱、前腳沒往前踏、後腳步也小，整體比開迴路差。

**文獻**（[CPG-RL, Bellegarda & Ijspeert 2022](https://arxiv.org/pdf/2211.00458)）：同架構，reward 只有六項——
x/y 速度追蹤與偏航率追蹤（核 `exp(−‖x‖²/0.25)`，σ=0.5 m/s，極軟）、−v_z²、−‖ω_roll,pitch‖²（只罰**角速度**）、−功；
權重 0.75/0.75/0.5/2/0.05/0.001·dt。**沒有** roll 角度罰項、足端追蹤、對稱項、力矩上限。
他們觀察到 policy 自己把前腳軌跡移到髖後方、站立相加振幅推進——前後不對稱是學出來的正常行為。
對稱性文獻（[Abdolhosseini 2019](https://hungyuling.com/project/2019-SymmetricRL.pdf)）：對稱靠資料鏡像／網路結構，罰項幾乎無效（我們的 t_sym 全程 0.0% 印證）。

**v2 的四個根因（只有一個跟 roll 有關，而且不是主因）**：

| # | 根因 | 證據 |
|---|---|---|
| a | 速度指令逼縮步：基準 0.34 m/s、指令 0.05–0.35、驗收 0.15、核 σ=0.14 | ω 用到 0.48、四腿步幅全縮 |
| b | 執行率獎勵漏洞：獎勵「追上自己出的目標」，縮 mu_x 就更好追 | v1 mu_x→1.47；v2 前腳自走 16–20 mm |
| c | 對稱項量錯量（追蹤誤差差恆 0） | t_sym 0.0% |
| d | roll 罰項只佔 2.7%，不是縮步原因；但 v2.1 拉到 14% 會讓 a/b/c 更有動機「小步少晃」 | 校準 |

**v2.2（使用者選方案 A：mu_x 固定）**：spec 附錄 A。動作 10 維、指令 0.15–0.40（驗收 0.30）、速度核 σ²=0.1、
**真執行率**（擺動結束時 世界系足端相對機身前跨 ÷ 指令前跨；與 `Trace.exec_rate` 同量，env 基準 前 0.86／後 1.53 vs Trace 0.88／1.47）、
對稱＝前後執行率差²、姿態溫和（校準：roll 角 4.0%＋率 3.7%、pitch 2.6%＋1.7%、exec 19%、sym 12%、vx 37%、yaw 24%、護欄 0）。
G4 改成峰值降 ≥30% 且 std 不升；G5 在 vx 0.30 判。
notebook `cpg_rl_max_v2_2_colab.ipynb`、權重 `cpg_rl_max_v2_2_params.pkl`、驗收 `local_infer_max --preset v2.2`。
`obs_max` 同時支援 10/14 維 layout，v2/v2.1 權重仍可驗。

### 7.1 v2.1 訓練中的觀察 → v2.2 補瞬時偏航核（2026-09-08 晚）

v2.1 @16M：roll 4.42→**1.25°**（env 基準 2.35，−47%；v2 同步數 2.06）——roll 權重 14% 有效。

基準上佔正項 3.3%。v2.1 preset 不變。
