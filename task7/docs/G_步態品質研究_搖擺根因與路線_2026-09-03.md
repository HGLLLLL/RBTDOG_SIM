# G：步態品質研究 —— 搖擺根因、四條路線的證據與代價（2026-09-03）

> 起因：使用者判斷「晃動幅度與姿態都太差、嚴重左偏,就算跑完意義也不大;
> model-based 應該是很穩定的東西」。本文回答:為什麼會晃、文獻怎麼做、
> 我們試了什麼(含否定結果)、剩下哪些路。

---

## 0. 三句話

> **搖擺不是動力學混亂,是確定性的「柔性腿承重效應」**——實機資料顯示機身傾斜與
> 「哪條腿在擺動」逐步同步(fr 擺→roll +7.3°、br 擺→pitch −5.9°)。
> **模擬其實忠實**:先前「模擬低估搖擺」是比錯條件(模擬端用 0.0325 的 z_sag、
> 實機用 0.075)——同組態下模擬 13.9° vs 實機 ±7~11°,對上了。
> **開迴路的地板 ≈ ±5°**(kp250);要到「看起來穩」,必須加姿態回授——
> 文獻上每台古典 model-based 四足都有這一層,它不是 RL。

---

## 1. 搖擺的完整因果鏈(全部有數據)

```
kp=120 位置伺服軟(靜態撓度 72mm)
  ├─→ z_sag 補償必須設 0.075 → 擺動指令幅度大 → 垂直動量大    〔主驅動源〕
  ├─→ 每抬一腿,承重重分配 × 柔度 → 機身向確定方向傾 5~9°      〔逐步搖擺〕
  └─→ 擺動追蹤落後 0.6 rad(設計值) → emax 誤殺(已修)
傾斜左右不對稱(右腿擺傾 +7°、左腿擺只 −1°)
  └─→ 持續的不對稱載荷 → ★ 嚴重左偏的來源(合理推定)
```

文獻對照:靜態 crawl 的教科書結構是「swing 時機身不動、movebase 時四腳著地移質心」
([intermittent crawl](https://www.researchgate.net/figure/a-Crawl-gait-and-b-intermittent-crawl-gait_fig5_224503398));
姿態穩定靠「stance controller 守機身姿態」
([survey](https://www.frontiersin.org/journals/mechanical-engineering/articles/10.3389/fmech.2024.1448681/full))。
我們的 CPG 把移質心/抬腿/推進全部同時連續做,且**沒有任何機構在守姿態**。

## 2. 今天做過的實驗(含三個重要的否定結果)

| 實驗 | 結果 |
|---|---|
| 逐腿承重前饋(靜態 4 腳)| ❌ **方向錯**:55mm 橫移自然只傾 1.6°(輪子自我卸載,M7 的 10.8× 機制),補償反推到 5.1° |
| 逐腿承重前饋(靜態 3 腳)| ❌ **方向也錯**:CoM 在右、抬左後腿,機身竟**左傾** 8.4° —— 輪足平台的傾斜不服從垂直彈簧模型,**解析式前饋在這台推不出正確方向** |
| 間歇 crawl 原型(分段停走)| ❌ 三腳平衡傾斜 ~8° 主導,不加姿態回授不會比 CPG 好,且慢 10 倍(0.03 m/s)|
| 姿態 P 調平(模擬,步態頻率)| ❌ 無效:kp120 腿追蹤延遲讓修正晚到,1.4 Hz 下等於反相 |
| **kp 250(髖膝)+ kd 2** | ✅ roll 13.9→**10.6°**、pitch 10.6→**6.8°**、彈跳 41.8→**23.8mm**(z_sag 減半 = 主驅動源減半)|
| 降 ω(1.0/0.8)| ❌ 偏航爆掉(+50~77°),搖擺沒少 |

## 3. 四條路線

| | 內容 | 預期 | 代價/風險 | 狀態 |
|---|---|---|---|---|
| **A. kp250 步態** | 髖膝 250、kd 2、ABAD 60、LS、z_sag 0.036 | 搖擺 −30%、誤差減半(emax 回 0.6 也行)| 觸地衝擊變硬(trip14 舊資料 kp250 膝 80,但那是 DS+拖腳+舊 trim)| **可立即上機驗** |
| **B. 姿態調平回授** | IMU roll/pitch → 足端 z 修正(古典控制,非 RL)| 這是「看起來穩」的正解;文獻每台都有 | 需要控制設計(P 已證無效,要相位超前或配合慢步態);**需使用者解除 IMU 禁令**(先前禁的是轉向,調平是另一件事)| 設計未開始 |
| **C. 接受 ±6° 地板** | emax 0.8 跑完現有步態 | 能走、能收資料 | 就是使用者說「意義不大」的那個 | 隨時可跑 |
| **D. RL 線** | 原廠同款(閉迴路策略)| 平順的最終解 | 重訓(增益現在才定案)、上機風險層級不同 | 既有規劃 |

**建議**:A 先上(一趟便宜,把開迴路做到頂),同時決定 B 的 IMU 問題——
**A+B 才是 model-based 該有的樣子**;D 是之後的事。左偏在 A 應會減輕
(不對稱傾斜變小),徹底解仍需航向回授(另一個 IMU 問題,分開決定)。

## 4. 修正的舊結論

1. ~~「模擬低估搖擺 1.7×」~~ → **比錯條件**。模擬端用實機 z_sag(0.075)與實機增益後,
   搖擺 13.9° ≈ 實機。模擬可信,可離線迭代。
2. ~~「z_sag 只是撓度補償」~~ → 它的**幅度本身是搖擺主驅動源**(kp120 要 75mm 深擺動)。
   這是 kp250 路線最有力的論據:z_sag 減半、驅動源減半。
3. 逐腿承重前饋、純 P 調平:兩個直覺方案都被否定,**證據都在本文 §2**——
   下次有人再提,先讀否定實驗。

## 5. 路線 A 實機驗證結果（17:00 / 17:01 兩趟,全流程零中止）

| | kp120（15:53）| **kp250 路線 A** | 模擬預測 |
|---|---|---|---|
| 流程 | 中止於 GAIT 2.3s | **✅ 完整走完 ×2**（站→走→停→趴）| — |
| GAIT roll 全距 | ~18° | **6.2 / 7.4°** | ~10.6° |
| GAIT pitch 全距 | ~13° | **4.7 / 5.1°** | 6.8° |
| 膝峰值 | 75~83（超門檻）| **59.5 / 57.7** | 51.3×1.14=**58** ← 幾乎命中 |
| 髖峰值 | — | 46.7 / 46.2（門檻 50 的 93%⚠️）| — |
| 最大追蹤誤差 | 0.62（撞門檻）| **0.28**（門檻 0.6）| 設計落後 0.3 |
| 傾斜不對稱（左偏源）| 右腿擺 +7° vs 左 −1° | **+3° vs 0°（減半）** | — |

- **kp250 的模擬→實機比值 ×1.14 二度驗證**（59.5/51.3=1.16）——這條線的預測能力恢復了。
- 搖擺比 kp120 小 **2~2.5 倍**,使用者體感一致。開迴路地板大致就在這裡（roll ~7°）。
- ⚠️ 新的最緊關節是**髖**（93% 門檻）,不是膝 —— 走更快/更久前先盯它。
- 左偏簽名減半但仍偏右傾 → 殘餘左偏預期仍在,徹底解要航向回授（IMU 決策仍開放）。
- RT 迴圈三修正生效：停頓 45→20ms、舊幀 32/4 次被吸收、零假中止。
