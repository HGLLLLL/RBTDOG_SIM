## 0. 一句話結論

**30 個感測欄位全部可用，慣例與 MJCF 一致，沒有任何一項需要改 obs 定義。**
訓練端要吃進去的東西只有四個數字組：致動器延遲 **+15 ms**、`joint_vel` 雜訊 **0.15–0.45 rad/s**、
gyro 偏置/雜訊 **~0.01 / 0.001 rad/s**、IMU 姿態偏置 **pitch −1.2°**（可修可隨機化）。
狗上有 numpy，policy 前向 **0.14 ms**。

### 2.1 眼睛對照：跳舞七步全部吻合（roll / pitch / yaw 三軸正負各自獨立驗到）

| 使用者看到 | 資料 | 定案 |
|---|---|---|
| 一、前半俯身 | 10.5–11.5 s pitch **+17.8°** | **+pitch = 頭低** |
| 二、後半俯身 | 12–13 s pitch −18.2° | ✓ |
| 三、水平左轉 | yaw +3→+16°，gyro_z +0.28 | **+yaw / +gyro_z = 左轉** |
| 四、水平右轉 | yaw → −15°，gyro_z −0.61 | ✓ |
| 五、前半往左下 | pitch +14° ＋ yaw +20°（前半往左擺） | pitch＋yaw 的組合動作 |
| 六、前半往右下 | pitch +14° ＋ yaw −26° | ✓ |
| 七、先左 roll＋右轉，再右 roll＋左轉 | 22.0 s roll **−7.7°**＋gyro_z −0.24；23.0 s roll **+7.2°**＋gyro_z +0.26 | **+roll = 右側低** |

### 2.2 IMU 姿態偏置 pitch −1.24°：是真的，不是地板或綁帶

兩個**互相獨立**的參考都看到同一個數字、同一方向：
- 跳舞（站著）：quat vs 腿 FK（四輪平面）→ pitch −1.24°
- 平放與 9/2 `stand_idle`：quat vs **自己的加速度計** → pitch 差 1.45° / 1.35°

綁帶或地板把機身墊歪，兩個感測器一起歪，**差值不變**，所以解釋不了。剩下的另類解釋
（地板剛好斜 1.2° 且加速度計剛好偏 0.2 m/s²）要兩天、兩種姿勢都巧合，不採信。
判定：IMU 姿態估計相對機身有固定 pitch −1.2° / roll +0.6° 偏置。
**處置**：訓練時加 ±3° 的常數姿態偏置隨機化即可吃掉；若要精修，在 `real_obs` 對 quat 套一個固定修正
（尚未做，等訓練前決定）。

**順帶解掉 8/26 的懸案**：吊掛時「IMU roll +7.1° vs 力矩反推 +2.5°」——IMU 安裝偏置只有 0.6°，
所以那 7° 是狗當時真的歪著掛（與當天「腿沒有真的自由懸掛」的結論一致），不是 IMU 錯。

## 3. 走路工況（trip17 兩趟 M9 log 回放對照，`obs_compare.py`）

模擬側用錄到的 `des / kp / kd` 逐筆驅動 MuJoCo（不重跑 CPG、免對齊），兩趟數字一致。
完整逐欄表：`outputs/obs_compare_table_trip17.md`。

| 欄位 | 實機 vs 模擬 | 給訓練的數字 |
|---|---|---|
| **des→q 延遲**（髖/膝） | 實機 **30–35 ms**，模擬 10–25 ms；joint_pos 實/模 lag 中位 12.5 ms | **致動器加 ~15 ms 延遲**（50 Hz policy ≈ 1 步）。trip14 原廠增益下也是 +16 ms → 與 kp 無關 |
| `joint_pos` | 相關 0.88–0.97；範圍差 <0.05 rad | 雜訊 **0.0005–0.002 rad**（量化 0.00038） |
| `joint_vel` | 峰值 ±10–13 rad/s，兩邊同量級；相關 0.55–0.85 | 雜訊 **ABAD 0.18–0.21、HIP 0.15–0.26、KNEE 0.41–0.44 rad/s**；>25 Hz 能量 2–20%（ABAD 最高）|
| `gravity` x/y | 相關 0.84 / 0.87，幅度 ±0.08 吻合，lag 0–5 ms | 雜訊 <0.0005（受 0.01° 存檔精度限制，是下界） |
| `gyro` x/y | 幅度 ±1.5 / ±1.3 rad/s，相關 0.69 / 0.76（由 roll/pitch 微分） | 範圍可用；雜訊用 §2 的 0.001 |
| `gyro` z | **M9 log 拿不到**；模擬 std 0.56、±1.2 rad/s | 範圍取模擬值 |
| ABAD 站立相平均角 | 實/模差 ~0.05 rad | ABAD 側向力矩模擬不準（已知 10×）的另一面 → ABAD 加大隨機化 |

★ **`joint_vel` 欄位的性質要記**：driver 有濾波。500 Hz 原廠資料裡它比角度差分乾淨（倍率 0.10）、
200 Hz 步態資料裡略髒（倍率 0.7–1.5）、>25 Hz 能量 2–20%；代價是落後 12–20 ms。
舊筆記「velocity 雜訊 47%」是**輪子低速**的觀察，腿關節在動作中不是這樣。
policy 用它沒問題，但模擬端要加雜訊＋一步延遲。

## 5. 訓練端要吃的清單（寫進 `obs_noise_model_trip17.json` + `imu_check.json`）

1. 致動器延遲：**15 ms**（模擬 200 Hz 內迴圈延 3 步，或 policy 50 Hz 延 1 步）—— 兩個 kp 都量到，穩
2. obs 雜訊 std：joint_pos 0.001、joint_vel **0.2（ABAD/HIP）/ 0.4（KNEE）**、gyro 0.002、gravity 0.005（取保守）
3. obs 常數偏置隨機化：gyro ±0.02 rad/s、姿態 ±3°（含實測 pitch −1.2°）
4. `joint_vel` 額外一步延遲（driver 濾波）
5. ABAD 動力學隨機化加大（side-load 模擬不準）
6. 走路時 gyro_z 範圍 ±1.2 rad/s（模擬值）—— 正規化用

## 6. 沒做／做不到的，老實列

- 走路時**原始** gyro（尤其 z）沒有實機值 → 若之後有走路趟，`M6 walk --record --hz 200` 側錄一次即可補（操作卡 §2 保留）。
- gravity 雜訊是存檔精度的下界，不是實測。
- 更新率是 500 Hz 錄製的下界（真值可能 1 kHz，同 joint_state）；對 50 Hz policy 無差別。
- IMU 偏置的修正尚未寫進 `real_obs`。
