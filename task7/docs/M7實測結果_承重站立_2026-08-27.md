## 2. ★ 我們的峰值只有原廠的 0.62×，而原因是好的

原廠的 42.45 **是真的**（12 個峰值逐一用 `kp·|err|+kd·|v|` 驗過，比值 0.82–0.98，
原廠自己的感測尖峰率 0.11%）。但拆開來看：

```
原廠峰值 42.45 @ t=9.05s（br3_knee）
   追蹤誤差 0.1878 rad × kp 250 = 46.96   ← 94%
   關節速度 0.618 rad/s × kd 5  =  3.09
```

**42.45 有 94% 來自「命令跑太快、腿跟不上」，不是「撐起 41 kg 需要 42 N·m」。**

原廠命令 1.050 rad/s、我們 0.800（慢 24%）→ 腿跟得上 → 峰值低 38%，**站到同樣的高度**。

→ **力矩門檻照 42.45×1.5 訂其實偏寬**，真正的靜態需求接近 27。

## 3. ★★ 當天最貴的教訓：吊帶高度會讓整趟測試變成無效

**第一趟吊帶掛在 314 mm（比 crouch 的 292 高）** → 狗掛在空中抬腿，
`HOLD_crouch` 膝力矩只有 **3.67 N·m**（原廠 27.3–29.8，僅 **13%**）。

⚠️ **而即時畫面每一個欄位都很漂亮** —— 誤差小、力矩低、傾角平，
因為腿確實很輕鬆。**看螢幕永遠看不出來。**

調到 243 mm 之後才拉到 22.0（78%）。

### 規則

**吊帶高度 H = 機身的下限。** 吊帶是繩子，只能往上拉：
機身低於 H → 吊帶撐；高於 H → 吊帶鬆、馬達全責。

| | 機身離地 |
|---|---|
| 趴姿（洩力） | ~106 mm |
| 輪子剛好離地 | 151 mm |
| **crouch** | **292 mm** ← **H 必須低於這個** |
| stand | 542 mm |

實務上限抓 **260 mm**（扣掉織帶伸長）。實際採用 **243 mm**。

### 判讀只能靠「和原廠實測值比」

`eval_m7.py` 的核心檢查就是這一條：
`HOLD_crouch` 膝力矩 < 原廠 27.3 的七成（19.1）→ **擋下，不准做 T2**。

M7 現在也會在**乾跑**就擋下「起點比第一個路徑點還高」
（膝越彎機身越低 —— 起點的膝比 crouch 還直就是被吊起來了）。

| | 我們 | 原廠 |

| 實測落點 | ∓1.2513~1.2578 | ∓1.2151~1.2250 |
| 追蹤誤差 | 0.051–0.058 | 0.034–0.041 |
| 膝穩態力矩 | 12.7–14.4 | 8.3–10.3 |

**膝命令越彎 → 力矩越大。** 要對齊原廠（長時間站立省馬達發熱）就把
`coord.POSES["stand"]` 的膝改成 ∓1.177。

### 每一趟跑完都要解凍

`mc_ctrl` 凍結實測只支持到 **38.1 秒**，而收檔＋評估要好幾分鐘。
T2 開始時 M7 會自己重新凍結，**保持凍結沒有任何好處**。

程式不自動解凍的理由：`mc_ctrl` 恢復後會繼續下指令去**它凍結前的姿勢**。
順利跑完時狗已回到 `q_lie`（＝凍結前的位置），解凍是空操作；
**中止時狗可能停在半站**，那時解凍 = 41 kg 在 kp=250 下突跳。
程式分不出這兩種情況，所以交給人判斷。
