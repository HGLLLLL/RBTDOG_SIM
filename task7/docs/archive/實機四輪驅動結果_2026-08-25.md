## 4. ⚠️ 我的量測程式有兩個 bug（都已修）

### 4.1 沒有處理角度包裹（wrap）

**輪關節的角度讀數是包裹在 [−π, π] 的。** run3 轉得快、超過半圈，於是：

```
右前輪讀數：2.9150 → -2.5282 → -1.6764 → ... → -1.9877
腳本算的 dp = 末 − 初 = -4.9027 rad   ← 錯，連方向都反了
解纏後真實值           = +7.6637 rad   ← 對
```

被汙染的數字（run3 原本印的）：

| 輪子 | 錯的速度 | 錯的摩擦 | 解纏後正確值 |
|---|---|---|---|
| 右前 | −0.4077 | 1.8116 | **+0.8515 rad/s、0.123 N·m** |
| 左後 | +0.2094 | 0.8859 | **+0.8364 rad/s、0.145 N·m** |
| 右後 | −0.6882 | 2.2322 | **+0.8418 rad/s、0.137 N·m** |

**三顆其實都是正轉、速度一致、摩擦與低速那兩輪吻合。**

佐證：run3 的**平均力矩** 0.1265 / 0.1440 / 0.1306 從頭到尾都是對的
（力矩不受角度包裹影響），而且與 run1/run2 一致 —— 早該注意到「摩擦 1.6 N·m
但平均力矩只有 0.13 N·m」自相矛盾。

**修法**：`shm_io.wrap_pi()`，逐筆把角度差折回 (−π, π] 再累加。
200 Hz 取樣下要 |v| > 628 rad/s 才會誤判，安全。

### 4.2 `velocity` 欄位的尖峰造成誤中止

run3 的右後輪在 4.1 秒被中止：`速度 4.282 超過 3.0`。
但由角度算的真實速度全程只有 0.84 rad/s —— **那是 `velocity` 欄位在角度包裹瞬間噴出的假尖峰**。

（這與 M2 已經發現的「`velocity` 欄位變異 47% vs 角度差分 9%」是同一件事的延伸。）

**修法**：
- 保護改用**解纏角度差分**算的速度（wrap-safe），並要求視窗至少橫跨 20 ms
  才採信（否則迴圈剛啟動時 Δt 趨近 0，算出來會爆掉 —— 這個在模擬裡實際重現過）
- `velocity` 欄位的檢查保留，但改成**連續 5 筆超標**才中止，避免單一尖峰誤殺

兩支腳本（M2、M3）都已修，並用「會包裹的模擬輪子」在本機端到端驗證：
模擬轉 2.4 rad（跨越 ±π 多次），解纏後算出 +2.4040 rad ✅
