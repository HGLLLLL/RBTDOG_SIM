## 2. ★ 兩個原本不確定的事，現在確定了

### 2.1 遙控器的站姿是 `stand`，不是 `rl_default`

實機的設定檔 `zg_wheels-user-parameters.yaml` **只有 `*_default_pos`（hip ±0.8 / knee ∓1.5）**，
`*_stand_pos` / `*_liedown_pos` 那兩個區塊在實機檔案裡被刪掉了，只存在於 MATRiX 模擬版那份。

但實測顯示：

- 站立 → 對上 **`stand`（hip ±0.6 / knee ∓1.2）** ← 只在模擬版設定檔裡
- 匍匐 → 對上 **`liedown`（hip ±1.4 / knee ∓2.4）** ← 同樣只在模擬版

→ **那兩組姿勢實機確實在用，只是不在那個設定檔裡**（多半編進 `mc_ctrl` 或別處）。
模擬版那份設定檔的參考價值比先前認定的更高。

⚠️ 這也修正了我先前的推論：我曾說「走路的名目站姿是 RL 預設姿，因為它的 MJCF 機身高度
0.4914 m 對上原廠 `body_height: 0.48`」。**遙控器的站立並不是那一組。**
`rl_default` 可能是 RL 策略跑起來之後的站姿，與遙控器的靜態站立不同 —— **尚未釐清**。

### 2.2 「後腿往後彎」就是「後腿與前腿同號」——推論正確

`stand_knee_back` 反推出來：

| | 前腿 | 後腿 |
|---|---|---|
| hip | +0.545 / +0.547 | **+0.587 / +0.583** ← 與前腿同號 |
| knee | −1.181 / −1.169 | **−1.251 / −1.232** ← 與前腿同號 |

而 `stand_knee_front`（預設）的後腿是 hip −0.55 / knee +1.23，與前腿**反號**。

→ 我用 `_flip_rear()` 推的那組候選是對的。**膝關節姿態切換 = 只翻後兩腿的 hip 與 knee 號**，
前腿完全不動（實測前腿兩種模式差 < 0.03 rad）。

### 2.3 四元數順序 = `xyzw`（定論）

用加速度計獨立交叉驗證（重力方向給出的 roll/pitch 應與四元數解出的一致）：

| 姿勢 | 加速度算 roll/pitch | xyzw 解 | wxyz 解 |
|---|---|---|---|
| crawl | 0.04 / 0.31 | **0.58 / −1.13** | −17.82 / 1.13 |
| lie | 0.86 / −1.39 | **1.41 / −2.79** | −21.41 / 2.79 |
| stand_back | −0.32 / −1.68 | **0.26 / −3.12** | −14.80 / 3.12 |
| stand_front | 0.44 / −0.63 | **1.00 / −2.12** | −10.80 / 2.12 |

**xyzw 四戰全勝（4/4）**，wxyz 的 roll 每次都差了 11–21°。
先前是靠「取樣時剛好水平」推定的，現在有四個獨立姿勢佐證，可以當定論。
（與 D1 EDU 的 `imu_shm` 一致。）

## 4. `lie_knee_front` 為什麼對不上

它不是「文件裡的 liedown」，而是**四肢完全收攏、膝關節頂在機構限位上的癱平姿勢**：

| | 實測控制器角 | liedown 文件值 |
|---|---|---|
| abad | ±0.45 ~ ±0.55 | 0 |
| hip | ±1.15 ~ ±1.20 | ±1.40 |
| knee | **±2.80** | ±2.40 |

**knee 的 ±2.80 正好是機構限位。** 三個關節（fl3/fr3/br3）反推後落在 −2.7998 / −2.8013 / +2.8024，
超出 MJCF 的 ±2.791 僅 0.009–0.011 rad，但**與 URDF 的 ±2.801 幾乎完全吻合**。

→ 這其實是個附帶收穫：**URDF 的 knee 限位 ±2.801 才是準的，MJCF 的 ±2.791 略緊 0.01 rad。**

而 abad 張到 ±0.5（文件寫 0）也符合「趴平時腳向外攤開」的直覺。
所以這個姿勢是真實存在、只是沒被記載，**不是資料有問題**。

## 5. ⚠️ 我在分析過程中犯的錯（第七次）

第一版分析我拿**馬達座標系**的角度直接去比 **URDF/MJCF 的限位**，
得出「實機行程比 URDF 寬」的結論，還列了 8 個「超限」項目。

**那兩個是不同座標系**，差一個 offset（abad 0.523 / hip 2.443 / knee 2.803）。
換算到控制器座標系後，48 個角度裡有 45 個落在限位內，
剩下 3 個超出 0.01 rad ——那是膝關節頂在機械停點上，不是超限。

教訓與前六次同源：**比較兩個量之前，先確認它們在同一個座標系／單位。**

## 7. ★ 控制器座標系 == MJCF 座標系（已驗證）

### 方法：四輪共面

**實機站在平地上，四個輪子的接地點必然共面。**
把實測馬達角用 V1 換算成控制器角，再直接餵進 MJCF 做正向運動學 ——
若兩個座標系同框，四個輪心高度應該幾乎相同；若不同框，腿的角度會全錯、輪子會散開。

| 姿勢 | FR | FL | BR | BL | **全距** | 機身離地 |
|---|---|---|---|---|---|---|
| `stand_knee_front` | 0.5627 | 0.5607 | 0.5671 | 0.5638 | **6.5 mm** | 0.535 m |
| `stand_knee_back` | 0.5551 | 0.5568 | 0.5667 | 0.5697 | **14.6 mm** | 0.541 m |
| `crawl` | 0.8401 | 0.8375 | 0.8259 | 0.8260 | **14.3 mm** | 0.270 m |
| `lie_knee_front` | 0.9751 | 0.9694 | 0.9839 | 0.9770 | **14.5 mm** | 0.127 m |

腿長 0.26 + 0.28 = 0.54 m，全距只有 6–15 mm。

### 對照組（沒有對照就不知道 6.5 mm 算不算好）

| 做法 | 四輪高度全距 |
|---|---|
| **V1 換算** | **6.5 mm** ★ |
| V3 換算 | 4.6 mm ★ |
| V2 換算 | 320 mm ❌ |
| V4 換算 | 473 mm ❌ |
| **完全不換算**（生馬達角當 MJCF 角） | **118.5 mm** ❌ |

→ 座標系**確實同框**：不換算會差 118 mm，換算後降到 6.5 mm。

### 殘差 6.5 mm 的來源：伺服追蹤誤差，不是座標系問題

| 膝關節誤差 | 足端高度變化 |
|---|---|
| 1° | 4.9 mm |
| **2°** | **9.8 mm** |
| 3° | 14.7 mm |

實測 RMS 殘差 **2.02°**（§1）→ 預期約 9.8 mm。
觀察到的 6.5 mm **完全落在這個範圍內**，不需要用「座標系有偏差」來解釋。

### ⚠️ 但共面性單獨無法區分 V1 與 V3

V3 也給出 4.6 mm 的共面性。原因：V1 與 V3 差 `2·offset/sign`，
而 offset 在四條腿上是左右＋前後鏡像的，所以 V3 等於對每條腿加一個**對稱**的常數偏移
—— 四輪仍然共面，只是整個姿勢變形。

**決定性證據要三項一起看**：

| 判準 | V1 | V3 |
|---|---|---|
| ① 對文件姿勢的 RMS 殘差 | **0.0353 rad（2.02°）** | 未進前 8 名（> 1.9 rad） |
| ② MJCF 機構限位 | **0/12 超限** | **12/12 超限**（hip −4.31、knee +4.40） |
| ③ 四輪共面 | 6.5 mm | 4.6 mm（**無鑑別力**） |

→ **V1 由 ① ② 決定性勝出。③ 只證明「座標系同框」，不證明是哪一個換算式。**

（這是「多印一個可以互相對照的量」的正面例子 —— 如果只看共面性，會誤以為 V3 也對。）

## 8. 附帶量到的：遙控器站姿的機身高度

MJCF 正向運動學算出來，`stand_knee_front` 的機身離地約 **0.535 m**。

對照：原廠設定檔的 `body_height: 0.48`，而 `rl_default` 姿勢算出來是 0.491 m。
→ **遙控器的站立比「走路名目站姿」高約 45 mm**，兩者確實是不同的姿勢。

⚠️ 這 0.535 m 是**模擬正向運動學**的值，沒有實機量尺佐證。
要更準可以現場用尺量地面到機身底板，但目前的用途（確認座標系同框）不需要那個精度。
