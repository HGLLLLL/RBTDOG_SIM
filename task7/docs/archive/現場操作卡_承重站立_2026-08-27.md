## 0. 開始前：一頁的心智模型

| | M5（吊掛） | **M7（承重）** |
|---|---|---|
| 狗在哪 | 吊在空中 | **趴在地上** |
| 腿有沒有承重 | 沒有 | **有，41 kg** |
| **中止的意思** | 切純阻尼＝**放手** | **凍結目標角、維持增益＝原地撐住** |
| 放手的後果 | 腿垂下來，沒事 | **狗從 0.5 m 塌下來** |

★ **兩支的中止語意是相反的。不要憑 M5 的直覺操作 M7。**

⚠️ **軟體保證不了「程式整個死掉」那條路**：controller 500 ms 收不到心跳就清零 →
狗塌下來。**吊帶是唯一的安全網。**

## 1. 物理前置（少一項就不要跑）

- [ ] 狗**趴在地上**，16 顆洩力
- [ ] **吊帶高度：掛在 200–260 mm** ← 見下面的說明

### ★ 吊帶要掛多高

**規則：吊帶的高度 H ＝ 機身的「下限」。** 吊帶是繩子，只能往上拉、不能往下推。
機身**低於 H** → 吊帶繃緊、吊帶在撐；機身**高於 H** → 吊帶鬆弛、**馬達全責**。

| | 機身離地 |
|---|---|
| 趴姿（洩力） | ~106 mm（肚子、膝蓋、輪子都在地上） |
| 輪子剛好離地 | 151 mm |
| **crouch** | **292 mm** ← **H 必須低於這個** |
| stand | 542 mm |

| 吊帶 H | 趴 | crouch | stand | 程式死掉時的落差 |
|---|---|---|---|---|
| ~106（貼著趴姿） | 鬆 | **馬達** | **馬達** | 436 mm |
| **200–260（建議）** | 吊帶撐 | **馬達** | **馬達** | **342 → 282 mm** |
| >292 | 趴不下去 | ⚠️ 吊帶撐 | 馬達 | crouch 白測 |

⚠️ **H 越過 292 就等於 crouch 那段沒測到。** 扣掉織帶會伸長，**上限抓 260**。

掛在 200–260 的代價：狗不再從「肚子貼地、膝頂 ±2.80」開始，
**趴→crouch 那段的承重測不到**（原廠峰值 35.41）。但真正的峰值 **42.45 在 crouch→stand**，
那段完全測得到 —— 撐得住 42.45 就撐得住 35.41，資訊損失不大。

★ 掛好之後有個肉眼確認：**T1 的 `GO_crouch` 時狗會從吊帶上「浮起來」，吊帶明顯變鬆。**
數字上的確認在 §4.5。
- [ ] 地面**淨空、平坦**、四周無人
      ⚠️ 地面斜度會放大「輪子滑走」，實驗室地板 2° 就足以讓狗慢慢溜走
- [ ] 兩個終端機：一個跑測試，一個**先打好** `sudo ~/estop_max.sh` 不要按 Enter
- [ ] 右後輪的狀態確認過（先前 `ready=0` 那顆）—— 若又閃紅燈就停手

## 3. T0 —— 乾跑（不寫入、不凍結、不需 sudo）

```bash
python3 M7_standup.py --to crouch
```

### ★★ 這一步你要看三樣東西

**(1) 膝模式 —— 最重要**

看「趴平(實測)」那一欄：

```
關節              趴平(實測)     crouch          限位
fl3_knee_pitch      -2.8009     -2.4000   ← 前腿
fr3_knee_pitch      -2.8009     -2.4000   ← 前腿
bl3_knee_pitch      +2.7967     +2.4000   ← 後腿
br3_knee_pitch      +2.8009     +2.4000   ← 後腿
```

**`bl3`/`br3` 必須和 `fl3`/`fr3` 反號**（一負一正）＝ 後腿往前彎，原廠預設。

**同號＝狗現在是 knee_back，先用 M5 喬回來再跑 M7。**
（新版 M7 會自己擋下來，但你自己要看得懂它在擋什麼。）

**(2) 命令速度表**

```
         區段     最大位移     峰值命令速度         哪個關節
      RAMP_UP    0.000 rad        0.00 rad/s
    GO_crouch    0.593 rad        0.62 rad/s     bl1_hip_roll
  HOLD_crouch    0.000 rad        0.00 rad/s
      ...
✅ 所有區段的命令速度都在 2.0 rad/s 以內
```

正常趴姿最大位移約 **0.4–0.6 rad**。若看到 **5.2 rad / 5.4 rad/s** 就是 knee_back。

**(3) 起點超限警告**

膝頂在機械停點 ±2.80、MJCF 限位 ±2.791 → 會警告「略微超出」，**這是預期的**。
超出量 > 0.05 rad 才是問題（M7 會自己拒跑）。

## 4. T1 —— 趴 ↔ crouch（先做這個）

```bash
sudo python3 M7_standup.py --to crouch --confirm
```

**為什麼先做 crouch**：不是因為力矩比較小（35.4 vs 42.45，幾乎一樣），
而是**塌下來的高度低**（0.29 m vs 0.51 m）。

### 跑的時候盯什麼

| 欄位 | 正常值 | 不對勁 |
|---|---|---|
| `最大\|誤差\|` | < 0.05 rad（膝 ~0.04） | > 0.2 就是有東西卡住 |
| `最大\|τ\|` | 爬到 30 上下 | 逼近 65（膝門檻）就準備按 estop |
| `roll` / `pitch` | ±5° 內 | 單向持續變大＝要翻了 |
| `↳ 輪子鎖定於 HOLD_crouch` | 到位時會印一行 | 沒印＝鎖輪沒生效 |

### 跑完之後

狗會**自己坐回趴姿、自己把 kp 降到 0**（`--to crouch` 的完整時序是
`RAMP_UP 2s → GO_crouch 1.5s → HOLD_crouch 4s → BACK_LIE 1.5s → RAMP_DOWN 2s`，共 11 秒）。
那個「按 Enter 決定要不要坐回去」的提示**只有中止時或加 `--stay` 才會出現**。

### ★ 跑完一定要解凍（每一趟都要，不是最後才做）

程式結束後 **`mc_ctrl` 仍在凍結中**，畫面會印出：

```
⏸ mc_ctrl 仍在凍結中（PID xxxx）。確認狗安全後交還控制權：
      sudo kill -CONT xxxx
```

**順序是「先看狗，再解凍」**：

1. **看狗** —— 趴好了嗎？腿有沒有卡住？吊帶有沒有纏到？人退開。
2. 解凍：`sudo kill -CONT <PID>`
3. 複查：`python3 M0_probe.py` → 16 顆應回到 `kp=kd=tau=0`

**為什麼程式不自動解凍**：`mc_ctrl` 恢復後會繼續下指令去**它凍結前的姿勢**。
順利跑完時狗已經回到 `q_lie`（就是凍結前的位置），解凍是空操作；
但**中止時狗可能停在 crouch 或半站**，那時解凍 = 41 kg 在 kp=250 下突跳。
程式分不出這兩種情況，所以交給你判斷。

⚠️ **不要為了省事而讓它一直凍著。** 實測支持的凍結時長只到 **38.1 秒**
（`docs/實機四輪驅動結果_2026-08-25.md` §5，`--max-freeze` 上限 90 秒），
而收檔＋評估要好幾分鐘 —— 遠超過測過的範圍。
**T2 開始時 M7 會自己重新凍結**，保持凍結沒有任何好處。

## 4.5 ★★ 回收資料 → 評估能不能做 T2

**這一步不能跳過，也不要靠肉眼看終端機。**
有兩件事**只看即時列印是看不出來的**：吊帶有沒有偷偷承重、力矩用掉幾成。

### (0) 先解凍再收檔

收檔＋評估要好幾分鐘，**不要讓 `mc_ctrl` 凍著等你**（見 §4 末）。
確認狗趴好、人退開之後：

```bash
sudo kill -CONT <畫面印的 PID>
python3 M0_probe.py          # 16 顆應回到 kp=kd=tau=0
```

### (1) 收檔（在你的電腦上，不是狗上）

```bash
bash task7/realbot/pull_from_dog.sh trip8 'M7_*'
```

⚠️ 若印「scp 失敗 / 權限不足」（M7 是用 sudo 跑的）：

```bash
ssh robot@192.168.234.1 'sudo chown -R robot:robot ~/m_logs'
```
然後重收。

### (2) 評估

```bash
python3 task7/inference/eval_m7.py task7/logs/m_logs_trip8/M7_*.json
```

它會自動抓最新那個檔，檢查五件事，最後給 **可以 / 不可以** 的結論
（離開碼 0 = 可以往下做）：

| 檢查 | 擋下來的條件 |
|---|---|
| 有沒有中止 | `aborted` 為真 |
| 峰值力矩 | 任一關節用掉 **> 80%** 門檻 |
| **★ 吊帶有沒有承重** | `HOLD_crouch` 膝力矩 **< 原廠 27.3 的七成**（19.1） |
| 追蹤誤差 | `HOLD_crouch` 期間 **> 0.10 rad** |
| 起始膝模式 | 前後膝**同號**（knee_back） |

### ✅ 放行的樣子

```
✅ 序列完整跑完，沒有中止
...
膝平均 28.50 N·m　原廠實測 27.3–29.8
✅ 與原廠同量級 → 腿確實在承重，吊帶是鬆的
✅ 前後反號（後腿往前彎，原廠預設）
✅ **可以做下一步**（峰值最多用掉 62%）
   → T2：sudo python3 M7_standup.py --to stand --confirm
```

### ❌ 最容易踩到的一種：吊帶偷偷承重

```
膝平均 12.00 N·m　原廠實測 27.3–29.8
❌ **不要做下一步。** 原因：
   - ★ HOLD_crouch 膝力矩只有 12.0，原廠是 27.3–29.8
     → **吊帶在幫忙承重，腿沒有真的吃到載重**
```

★ **這種情況下所有即時欄位都會很漂亮**（誤差小、力矩低、傾角平），
因為腿確實很輕鬆 —— 但那代表 T1 根本沒測到承重，**直接做 T2 等於沒暖身就上場**。
處理：**把吊帶調低**（見 §1 的高度說明），重跑 T1。

**評估沒過就不要做 T2。**

## 5. T2 —— 完整站起來 ★★

```bash
sudo python3 M7_standup.py --to stand --confirm
```

**這是今天的目標。** 動作：趴 → crouch → 停 2 秒 → **stand** → 停 4 秒 → 坐回趴姿。

### 已知的力矩包絡（原廠實機做同樣動作）

| 階段 | ABAD | HIP | KNEE |
|---|---|---|---|
| 趴→crouch | 28.15 | 22.70 | 35.41 |
| crouch 停住 | 22.23 | 21.34 | 33.62 |
| **crouch→stand** | 18.26 | 18.99 | **42.45** ← 全程峰值 |
| 站穩 | 1.25 | 3.71 | 11.38 |

M7 門檻是這些 ×1.5：**ABAD 45 / HIP 40 / KNEE 65**，硬上限 120。

★ 峰值出現在**離開 crouch 往上撐**的那一刻，不是站直之後。撐過那一下就穩了。

### 站直之後

輪子會自動 latch 鎖住（印 `↳ 輪子鎖定於 HOLD_stand`）。
鎖定後四輪應該幾乎不動 —— 原廠實測 9 秒內只滾 0.3~2.1 mm。

若要**長時間站著**觀察，加 `--stay`：

```bash
sudo python3 M7_standup.py --to stand --stay --confirm
```

⚠️ `--stay` 腿會**一直承重**。跑完會停下來等你按 Enter 才坐回去。

## 6. 出事的時候

| 狀況 | 做什麼 |
|---|---|
| 程式印「⛔ 中止」 | **狗還撐著，沒有放手。** 讀中止原因與最後 12 筆，決定按 Enter 坐回去 |
| 狗明顯要翻 | 另一個終端機 `sudo ~/estop_max.sh` |
| 狗開始慢慢滑走 | 地面有斜度。停下來換位置，別硬撐 |
| 完全沒反應 / 程式死掉 | **吊帶接住**。500 ms 後馬達清零 |

★ **不要按 Ctrl-C**，除非你確定放手是安全的 —— Ctrl-C 在承重時＝讓狗塌下去。
正確的收尾是等程式問你、然後按 **Enter**（依原路徑慢慢坐回趴姿）。

## 附錄 A：今天為什麼 M7 和昨天不一樣

兩處改動，都是 2026-08-27 從 `M6_20260826_154737.json` 重新挖出來的：

**1. 原廠有增益排程，我們原本不知道**

| 時刻 | ABAD | HIP/KNEE | 腿 kd | 輪 kp |
|---|---|---|---|---|
| 5.98 s | 250 | 250 | 5.0 | 20 |
| **9.99 s** | **60** | **120** | **1.0** | **0** |
| 12.99 s | 250 | 250 | 5.0 | 20 |

站直那一刻原廠**放軟腿 + 放開輪子三秒**（那組就是設定檔的 RL 增益），
後兩輪各滾約 **100 mm**，12.99 s 才收回鎖死。
**遙控器站立時看到的「輪子微幅前後轉」就是這一段。**

**2. 因此 M7 加了「到位後鎖輪」**

M7 原本全程純阻尼、從不鎖。模擬（站穩後 15 秒）：

| | 平地 | **2° 斜坡** |
|---|---|---|
| 不鎖 kd=0.1 | 0.8 mm | **2170 mm** |
| 不鎖 kd=0.5 | 0.8 mm | 411 mm |
| **鎖定 kp=20** | 1.2 mm | **21 mm** |

★ 原本擔心「±π 繞回會爆出 121 N·m」→ **已驗證是 driver 自己解纏**，
所以鎖輪是安全的（`tests/test_m7_standup.py` 逐筆驗過 1328 筆）。

**3. 附帶更正**：`--wheel-kd 0.1` 這個建議**不重要**，模擬顯示移動中的輪 kd
在 0.1~1.0 之間對腿峰值力矩幾乎沒有影響（膝 23.1 vs 23.2）。**用預設 0.5 即可。**
