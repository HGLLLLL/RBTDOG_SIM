# CPG-RL v3.6f 上機（D1 Max、鏡像推論）—— 設計（2026-09-22）

## 目的

把 `weights/cpg_rl_v3_6f_params.pkl`（模擬：左右轉 ±84°/s、左右平移 0.25 m/s、0 摔）跑在狗上，
**鏡像範圍＝原地右轉＋右平移**（使用者 2026-09-22 定，等於驗收表 `eval_cpg_rl_v3_6f_params_mirrorall.md` 那組設定）。
狗上只有 Python 3.10 ＋ numpy 1.21.5，沒有 jax／brax／mujoco。上機前所有驗證在本機做完。

原則沿用 v2.3 上機 spec（`docs/superpowers/specs/2026-09-09-rl-policy-on-dog-design.md`）：
狗端純 numpy、本機測試釘住逐位元、退路一鍵切回、M9 的起身／坐下／護欄／ChatterWatch／`--confirm`／說兩次全部保留。
**與 v2.3 最大的不同：這次沒有「已在實機走過的開迴路基準」可退。** v3 的名目產生器（零動作）本身就是第一次上機，
所以退路是「零動作名目」而不是 A 步態，且零動作要先單獨過關（§4 段 ②③）。

## 範圍

做：v3 產生器的 numpy 移植、88 維 obs、v3 匯出與 24 維推論、鏡像推論、M9 `--v3` 串流（含輪子力矩命令、原廠增益、分關節護欄）、
本機影子跟跑、部署清單、操作卡。
不做：`--turn-weights`（按族換權重）、v3.7 系列的 `LIFT_NONNEG`／前饋／解耦（v3.6f 訓練時沒有，部署也不用）、四向遙控（第一趟每趟固定一個指令）、
IMU 偏置修正（訓練已隨機化）、任何 reward／env 改動（`test_rl_env_v3_golden.py` 釘住 `rl_env_v3` 不動）。

### 1.1 `export_policy_v3.py`

- 權重：同 v2.3 匯出式（`running_statistics` mean/std、`hidden_0..3` kernel/bias），`obs_dim=88`、`act_dim=24`、`preset="v36"`、`layout="v3"`、`src_sha256`。
- **產生器參數快照 `gen_json`**：`DualModeEnv(gains="factory", weights=W36, ref=dict(cyc_amp_rand=False), push=False).ref` 整個 dict（含 `REF_FACTORY` 覆寫、`cyc_turn_sym=True`）
  加上模組常數 `ACT_DIM, QRES_MAX, QRES_SLEW, OMEGA_NOM_SCALE, AMP_SCALE, LIFT_SCALE, SWAY_MAX, SWAY_SLEW, WHEEL_RES, STEP_GAIN_S, PH_SLEW, FOOT_OFF_MAX, TAU_FF, RAMP_STEPS, CTRL_DT`、
  相位表 `PH_TURN_L/PH_LAT_L/PH_TROT/W_LAT_L/W_TURN_L/W_ARC_L/DOM_TURN_L/LAT_WHEEL_L`、幾何 `HIP_XY/FOOT_XY_BODY/SIDE_Y/STANCE_Q12/STANCE_FEET`、限位 `lo12/hi12`。
- **週期表**：`CYC_OFF_SYM (4,100,12)`、`CYC_TAU_SYM (4,100,4)`、`CYC_HZ_SYM (4)`、`CYC_QMEAN (4,12)`（`cyc_recenter=True` 時不用，仍帶）。
- 狗端**不自己算**任何一個常數，全部從 npz 讀；本機測試釘住 npz 內容 == `rl_env_v3` 當下的值（改了 env 忘了重匯出就會紅）。

### 1.2 `gen_v3.py`

純 numpy，函式一對一對應 `rl_env_v3`：`activity, _lat_weight, leg_activity, step_gain, phase_offsets, slew_phase, kin_step_vec, posture_offset, wheel_cmd,
step_pattern, duty_remap, act_split, foot_targets, joint_targets(用 kin.ik，膝分支前 −1 後 +1), _cyc_interp, cycle_offsets, wheel_dead(τ 死區)`。
`Gen.state`：`u_mode, ph4, theta4, amp4, sway2, u4, phi_cyc, qres12, head_err, i`（＝env `info` 裡產生器會用到的那幾個；不含延遲、EMA、reward 用的量）。

`Gen.step(cmd, act, v_wheel_meas, gyro_z)` 的順序**逐行照 `DualModeEnv.step` 第 685–745 行**：
`P=step_pattern → u_mode 斜率 → act·ramp(i) → act_split → om/ph/theta → amp 斜率 → sway 斜率 → lift4 → feet → u4 → cycle_offsets(phi_cyc) → phi_cyc 推進 → delta（非解耦式）→ qres 斜率 → q_des 夾限位 → v_nom → τ_cmd = 1.0·(v_nom − v_meas) + wres + u4·wheel_tau → head_err`。
回傳 `q_des12`（MJCF 腿序、控制器座標系）、`wheel_tau4`（N·m，**未加死區**；死區在 M9 寫入前套，obs 用的 `c["wheel"]` 是未加死區的 τ_cmd，與 env 同）、`c=dict(theta, amp, cyc_abad, cyc_knee, wheel)`。
- 動作介面吃「**這一步要套用的動作**」；延遲是 env 的事，影子測試在外面重現。
- `i=0` 時 `theta=0, amp=0, u_mode=max(P["s"])`（env `reset` 的初值）；`ph` 初值 `P0["ph"]`。
- **零動作、cmd=0 時 `q_des` == `stance_q12`**（`fk∘ik` 恆等；測試釘住 < 1e-9），這就是 M9 的起身目標。

### 1.3 `rl_obs_v3.py`

`build(frame, c, cmd3, last_a24, head_err, s4, s_arc, wheel_v4) -> float32(88)`，排列同 §0 表。
- 關節：`coord.to_ctrl` → MJCF 腿序 → **減 `stance_q12`**（不是 `HOME12`）；速度 ÷`SIGN`。
- 輪速：`joint_state.velocity` 的四顆輪，MJCF 序 (FR, FL, RR, RL)，rad/s；符號要與 MJCF 輪關節同向（M11 用過的 `coord` 輪 side_sign，測試用 `replay` 錄檔驗正負）。
- `c["wheel"]/5`、`sin/cos(c["theta"])`、`c["amp"]`、`c["cyc_abad"]`、`c["cyc_knee"]` 直接來自 `Gen`。
- `mirror_obs(o)`：索引／符號表由 npz 帶（`OBS_MIRROR_IDX/SGN`、`ACT_MIRROR_IDX/SGN`），θ 相位修正照 `rl_env_v3.mirror_obs`（`d=θ0−θ1`，交換後加 d）。
- `is_right(cmd)`：`|wz|>0.1 ? wz<0 : vy<−0.02`（＝`mirror_policy(turn_only=False)`）。

### 1.4 `M9_gait.py --v3`

新旗標：`--v3 PATH.npz`（與 `--policy`／`--traj` 互斥）、`--cmd VX VY WZ`（這趟的固定指令）、`--policy-gain`（沿用：0 ＝零動作名目、1 ＝ policy）、
`--mirror`（預設開；關掉純為對照）、`--emax-abad`／`--emax`（分關節；預設 1.2／0.8 是上限，操作卡用 §3 第 4 項推出的值）、`--wheel-kd 0.1`（步態段）。必須搭 `--interactive`。
`--kp 120 --kp-abad 60 --kd 1.0` 由 npz 的 `gen_json["gains"]` 說兩次（不一致拒跑，同既有格式）。

`V3GaitStream(GaitStream)`，覆寫 `_advance` 與 `_compute`：

```
fr    = read_frame()                            # 關節 12 ＋ 輪 4 ＋ imu_central ＋ tick
obs   = rl_obs_v3.build(fr, self.c, cmd, last_a, gen.head_err, s4, s_arc, v_wheel)
right = is_right(cmd) and mirror
a     = mirror_act(policy.infer(mirror_obs(obs))) if right else policy.infer(obs)
a     = 0 if (fallback or open_loop or gain==0) else gain·a       # 零動作＝名目
q_des, tau, self.c = gen.step(cmd, a, v_wheel, gyro_z)
self.wheel_tau = dead_zone(tau)                  # |τ|<0.13 → 0，否則 τ+0.13·sign
self.last_a = a
```

- **指令時序**：**GAIT_IN 全程 `cmd=(0,0,0)`**（產生器輸出站姿，與 M9 既有的 smoothstep 淡入相容）；
  `InteractivePlan` 進 GAIT 的那一刻呼叫 `V3GaitStream.arm_cmd()`，**再 50 步（1 s）**才切到 `--cmd`；
  Enter 停走 → **指令歸零、同時開始 3 s 淡出**（`_stop_policy` → `set_open_loop` → `_cmd_now()` 回 0）。
  訓練有 `P_SWITCH` 0.4 的回合中切指令，且「站立」是驗收 case，所以切換是訓過的。
- **輪子寫入**（只在 GAIT_IN/GAIT/GAIT_OUT）：每顆 `write_cmd(position=實測, velocity=v_meas, effort=τ, kp=0, kd=0.1)`
  → 驅動器力矩 = 0.1·(v_meas − v) ＋ τ ≈ τ。這是模擬 `wheel_ctrl_tau` 的實機等價（模擬把 τ 折成 `v_meas + τ/kv` 是因為 MJX 只有速度致動器）。
  起身／坐下段維持 `WHEEL_KD_SAFE` 0.5 純阻尼（`wheel_kd_of` 在 v3 模式下**不**用 `min(a.wheel_kd, SAFE)`，改成「步態段 0.1、其餘 0.5」）。
  200 Hz 寫入時腿目標線性內插（既有）；輪的 **`velocity` 欄每個 200 Hz tick 重讀當拍實測**（`v3_wheel_rows` 吃的是這一拍的 `stt[wi]["velocity"]`），
  **只有 `effort` 是零階保持**（50 Hz 算一次 τ，四拍都寫同一個值）。這樣 kd 項才會真的 ≈ 0；`effort` 寫出去前夾在 **±`WHEEL_TAU_MAX`**（npz 從場景的輪致動器 `forcerange` 讀來，±33）。
  輪的 `velocity`（讀）與 `effort`（寫）都是馬達座標，MJCF 序與符號用 `coord` 的輪 side_sign 換算，讀寫用同一張表（測試 §3 第 2 項驗符號）。
- **增益過渡**：起身 250/5.0 → `--kp-shift` 1.5 s 靜止過渡到 60/120/120、kd 1.0（既有機制，設計時就是給 250↔120 用的）。
  ⚠️ 站著換到軟增益機身會再下沉約 36 mm（z_sag 36→72），這是預期的，段 ① 要看到它。
- **護欄**：誤差改分關節（ABAD `--emax-abad` **只在 v3 生效**、髖膝走通用的 `--emax`）；`--vmax 18`；`--tau-total` 開；
  ChatterWatch 沿用（多看四顆輪的 `velocity` 高頻翻轉）＋ **`--wheel-vmax`（v3 專用，預設 30 rad/s）**：
  ChatterWatch 只認正負翻轉，effort 路徑的**單向**失控它一次都不會叫，所以另開一條看四輪實測 |velocity|。
  數值由 §3 第 4 項的影子跟跑輸出 `err_pk`／`knee_v` 峰值 ×1.3 定，寫進操作卡；不超過預設上限。
- **退回**（同 v2.3）：obs NaN／幀沒前進／推論＋產生器 > 10 ms／例外（`exc:*`／`exc_gen:*`）／**產生器輸出 NaN（`gen_nan`）** → 當步零動作；連續 25 步 → 永久零動作；鍵 `o` 永久零動作。
  零動作名目在模擬全速度不倒（v3.7 E9；v3.6f 的名目更保守），但**實機沒驗過**，所以段 ②③ 先單獨跑零動作。
- log 每步：`obs(88)`、`a(24)`、`a_raw(24)`、`q_des(12)`、`tau(4)`、`v_wheel(4)`、`right`、`cmd(3)`、`sat`、原始 imu、ms、退回原因；整趟 `n_clamp`／`n_sat`／`fallback_total`／`open_loop`。

### 1.5 影子跟跑（`tests/test_policy_v3_closed_loop.py`）

MuJoCo（非 MJX）內同一趟：jax 堆疊 `DualModeEnv(gains="factory", weights=W36, ref=dict(cyc_amp_rand=False), push=False)` ＋ `local_infer_v3.load_policy` ＋ `mirror_policy(turn_only=False)` 驅動機器人；

## 2. 決定與理由

1. **鏡像原地右轉＋右平移**（使用者定）：等於 `--mirror --mirror-lat`；驗收表 mirrorall 左右轉 ±84 差 1%、平移 ±0.25 對稱；代價右平移側傾 0.37→0.63°。
2. **輪子走 effort 欄位而不是把 τ 折進 velocity**：SHM 本來就有前饋力矩欄（`D1Max_機器狗資訊.md` §4.2），M11 用過；原廠自己就是 kd 0.1 ＋ 前饋 0.2–0.5。
   `velocity=v_meas` 讓 kd 那項 ≈ 0，行為最貼近模擬的 `wheel_ctrl_tau`。備案（一個旗標）：`--wheel-mode kd1`＝`velocity=v_nom, kd=1.0, effort=wres+u4·τ_cyc+死區前饋`，把外環交給驅動器 1 kHz 做（M11 驗過 kd 1.0 無抖振），若 50 Hz 外環在實機不穩就切這個。
3. **產生器參數與週期表隨 npz 下狗**：狗端零常數，避免「兩份實作各自正常卻走出兩種步態」（v2.3 的坑）。
4. **零動作＝退路**：`gain 0` 不是「跟 A 一樣」而是名目產生器；因此上機順序多兩段（零動作直走、零動作踏步）。
5. **起身目標改為 v3 站姿**（0.52／−1.20）：由 `Gen` 在 `i=0, cmd=0, a=0` 給出，M9 不再讀 `--traj`；`InteractivePlan(q_stand=...)` 直接吃它。
6. **第一趟不做遙控**：每趟一個 `--cmd`，Enter 停。四向遙控（`teleop_cmd` 的 v3 版）等零動作與 policy 都走通再開。
7. **`rl_env_v3` 一個位元不改**（golden）；新增檔案全在 `realbot/` 與 `inference/export_policy_v3.py`。

## 5. 風險

- **零動作名目在實機站不住**（軟增益、原廠週期、41 kg）：模擬只保證模擬；段 ③ 是硬門，倒了就回頭做零動作的實機掃描，policy 不上。
- **輪子力矩路徑**：50 Hz 外環 ＋ 5–7 ms 輪延遲 ＋ `velocity` 欄雜訊；理論上 1.0 N·m 每 rad/s 很溫和，仍列 `--wheel-mode kd1` 備案。承重滾動摩擦與打滑沒量過（K 是空載）。
- **質心方向補償**：模擬質心偏左 1.5 mm 的補償方向實機不一定同向；v3.6f 有 ±5 mm 質心 DR，鏡像讓左右用同一套能力，但仍可能一邊好一邊差。
- **平移滑步**：模擬平移抬腳 5–10 mm 靠側滑，實機地面摩擦不同；可能走不動（不危險）或側傾更大（護欄 `--tilt-max` 在）。
- **護欄誤中止**：軟增益下命令差本來就大，舊 `--emax 0.6` 一起步就會中止；分關節值照 §3 第 4 項定，不憑感覺。
- **推論預算**：產生器（4 次 IK、表內插）＋ MLP 88→256→256→128→48 在 RK3588 估 < 2 ms。三個門講清楚：
  **程式的當步退回門 10 ms**（`V3GaitStream.INFER_BUDGET_MS`，超過記一次 `slow:` 退回）、
  **乾跑的拒跑門也是 10 ms**（同一個常數；`推論 + 產生器 > 10 ms` 直接 `return 1`）、
  **操作卡段 ⓪ 的過關要求 < 5 ms**（保守，不是程式門 —— 留一倍餘裕給實機的排程抖動）。
- **站姿轉換**：起身終點改成 0.52／−1.20，M7/M9 之前起身終點是 home 0.8／−1.5；起身軌跡插值路徑不同，段 ① 看膝力矩包絡（原廠站立 §9.7）。

### 6.4 ABAD 誤差 0.70 的真因（影響操作卡與乾跑檢查）

這是訓練出來的長相（ABAD 幅度＝原廠 ×1.6 補 kp120 撓度），產生器最後一步 `np.clip(q_des, LO12, HI12)`
