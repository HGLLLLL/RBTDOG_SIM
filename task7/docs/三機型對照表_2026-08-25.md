## 1. 車載電腦規格

| | **D1 EDU 輪足** | **D1 Max** | **D1 MaxPro** |
|---|---|---|---|
| 架構 | **單板** | **雙板** | 單板（推定） |
| 主控 | Rockchip **RK3588**<br>（Firefly AIO-3588SJD4） | **RK3588**（運控）<br>+ **NVIDIA Orin NX 16GB**（應用） | **NVIDIA Jetson**（型號未公開） |
| CPU | 4×A76 @2.3GHz + 4×A55 @1.8GHz | RK3588 同左；Orin NX 另計 | — |
| 記憶體 | 7.73 GiB，**無 swap** | 未量測 | — |
| 儲存 | eMMC 64 GB，**無 NVMe** | 未量測 | — |
| AI 算力 | NPU **6 TOPS** (INT8) | **157 TOPS**（Orin NX） | — |
| 作業系統 | Ubuntu 22.04，kernel 5.10 **PREEMPT_RT** | Ubuntu 22.04 | Ubuntu（版本未公開） |
| 中介軟體 | **eCAL**（ROS2 只是橋接層） | **ROS 2 Humble + Zenoh**<br>RK 網域 66 / NX 網域 24 | **ROS 1**（底層 SDK 強制） |
| 開發板政策 | 無明確規定 | 官方明文：**RK3588 勿開發應用**，<br>使用者程式放 Orin NX | — |
| 資料來源 | 【實機】完整盤點 | 【實機】部分 + 【文件】 | 【文件】＋由 SSH 帳號 `jetson` 判定 |

**兩個對部署很關鍵的實測發現（只有 D1 EDU 有，因為只有它盤點到底）：**

- **`cpu7` 被核心隔離給運控獨占**（`isolcpus=7 nohz_full=7`）。我們的推論程式**絕對不能跑在 cpu7**，
  會直接干擾 1 kHz 馬達迴圈。
- 狗上**沒有 PyTorch / ONNX Runtime**，只有 numpy。小型類神經網路用純 numpy 跑一次是微秒級，
  對 50–200 Hz 控制迴圈綽綽有餘，**零安裝零風險**。

⚠️ D1 Max 的同類項目**還沒盤點**（第一、二趟偵察聚焦在控制介面）。

## 3. 能否獨立控制單一顆馬達 ★

這是三台差最多的地方。

| | **D1 EDU 輪足** | **D1 Max** | **D1 MaxPro** |
|---|---|---|---|
| **官方 SDK 支援** | ❌ **明文不提供**<br>（文件白紙黑字寫「ZSL-1w 不提供 LowLevel 接口」） | ❌ 不提供 | ✅ **官方開放** |
| 二進位驗證 | 【二進位】程式庫導出 **0 個** LowLevel 符號 | 【二進位】269 個符號**全部**是高層 API，`strings` 搜不到任何底層字樣 | — |
| **實際上做不做得到** | ✅ **做得到** | ⚠️ **極可能做得到** | ✅ 做得到 |
| 走哪條路 | 板載共享記憶體 `/spline_shm`<br>（繞過 SDK，直接對機上 daemon 溝通） | 板載共享記憶體 **`/dev/shm/joint_cmd`**<br>16 軸 × {角度, 角速度, 力矩, Kp, Kd} | ROS 1 話題 **`rt/lowcmd`**<br>可下 `q_des` / `kp` / `kd` / `tau_ff` |
| **驗證到什麼程度** | ★★★ **實機端到端跑通**<br>位置／速度／力矩**三種控制模式全部驗證成功**，<br>單顆輪子轉起來、單關節位置控制誤差 0.2% | ★★ **介面找到、結構已完整解出**<br>**但寫入尚未測試**（需 root 權限） | ★ **純文件**，我們沒有這台機器 |
| 權限 | 讀免權限；寫需 root | 讀免權限；寫需 root | 一般使用者即可 |
| 風險／代價 | 需凍結原廠運控行程後接管，**全程須吊掛** | 同左（預期） | **無**——官方支援的正規做法 |
| 額外門檻 | 無 | 無 | **必須裝 ROS 1**（Ubuntu 20.04） |

### 白話總結

- **只有 D1 MaxPro 是官方正式開放單顆馬達控制的**，而且介面設計得很標準
  （目標角度、目標角速度、Kp、Kd、前饋力矩），是業界做強化學習部署的標準形式。
  代價是**必須用 ROS 1**，而本專案先前已決定不走 ROS 路線，這點要納入評估。
- **D1 EDU 輪足**官方不給，但我們自己找到了板載共享記憶體這條後門，
  而且**已經在實機上完整驗證過**——單顆馬達的位置、速度、力矩三種控制模式都成功驅動過。
  **這是目前唯一一台我們親手證明「可以控制單一顆馬達」的機器。**
- **D1 Max** 官方同樣不給，但我們已經找到對應的共享記憶體介面、把資料結構完整解出來了
  （16 軸 × 5 個欄位，與機上 `ros2_control` 列出的介面完全對應）。
  **剩下的只有「寫進去會不會被接受」這一步還沒測。** 依 D1 EDU 的經驗，預期可行。

## 4. 給決策用的重點

1. **要做自己的運動控制演算法（RL／CPG），三台都有路，但成熟度差很多。**
   D1 EDU 已驗證可行；D1 Max 差最後一步；MaxPro 有官方支援但要換整套 ROS 1 開發環境。
2. **D1 Max 是目前綜合條件最好的一台**：算力高出一個量級（157 TOPS vs 6 TOPS）、
   感測器最完整（雙光達＋雙相機＋RTK＋超音波）、SDK 功能最豐富，
   而且底層介面**是原廠自己在用的同一條路**（不是我們硬挖出來的旁門）。
3. **待辦的關鍵一步**：在 D1 Max 上驗證共享記憶體的**寫入**。
   做法可沿用 D1 EDU 已驗證過的流程（先寫全零增益，力矩數學上恆為 0，零風險），
   確認機上的常駐程式會接受我們的指令。
4. **動到寫入之前，建議先向原廠確認態度與保固範圍。**
