# 現場提示卡：站姿座標換算驗證

- 對象：D1 Max RK3588（`192.168.234.1`）
- 風險：**零**。全程唯讀、不需 sudo、不碰任何行程、不寫任何指令
- 時間：10–15 分鐘
- 狗的狀態：**用遙控器正常操作即可**，我們只在旁邊讀資料

---

## 為什麼要做這件事

我們讀得到 16 顆馬達的角度，但**不知道它跟控制器／MJCF 的關節角是什麼關係**。

從實機設定檔推出來一條假說：

```
馬達角 = side_sign × 控制器角 + offset
```

目前只驗到「控制器角 = 0」這一個點（馬達洩力時 `joint_cmd` 的 `p_des` 剛好等於 offset，四組全中）。
**斜率完全沒驗過。** 要驗就得讓狗擺出一個已知的非零姿勢 —— 也就是站起來。

⚠️ **這條式子沒確認，之後模擬算出來的關節角就沒辦法換成實機指令。** 是做步態的必要前提。

---

## 步驟

### 0. 部署（在你的電腦）

```bash
nmcli con up d1max-wifi && ping -c3 192.168.234.1
scp task7/realbot/{shm_io.py,M4_pose_capture.py} robot@192.168.234.1:~/
ssh robot@192.168.234.1
```

### 1. 站姿

**用遙控器讓狗站起來，等它完全停穩**（不要有晃動），然後：

```bash
python3 M4_pose_capture.py stand
```

它會取樣 2 秒、平均、然後自動比對四種換算式 × 三組候選姿勢。

### 2. 趴姿

**用遙控器讓狗趴下，停穩**，然後：

```bash
python3 M4_pose_capture.py lie
```

### 3. （有的話）第三個姿勢

遙控器上如果有「高站姿 / 低站姿 / 匍匐」之類的，各擷取一個，名字自己取：

```bash
python3 M4_pose_capture.py high
python3 M4_pose_capture.py crawl
```

**姿勢差異越大越好**，對驗證斜率越有幫助。

### 4. 收工

```bash
exit
scp -r robot@192.168.234.1:~/m_logs ./m_logs_trip6
nmcli con down d1max-wifi && nmcli con up Q500_ForDog
```

## 現場對照表：站姿應該讀到什麼

如果假說成立、而且遙控器的站姿就是設定檔的 **RL 預設姿**（abad 0、hip ±0.8、knee ∓1.5），
`joint_state` 應該讀到這些數字：

| 關節 | 預測馬達角 | | 關節 | 預測馬達角 |
|---|---|---|---|---|
| `fl1_hip_roll` | **−0.523** | | `bl1_hip_roll` | **+0.523** |
| `fl2_hip_pitch` | **+1.643** | | `bl2_hip_pitch` | **−1.643** |
| `fl3_knee_pitch` | **+1.303** | | `bl3_knee_pitch` | **−1.303** |
| `fr1_hip_roll` | **+0.523** | | `br1_hip_roll` | **−0.523** |
| `fr2_hip_pitch` | **−1.643** | | `br2_hip_pitch` | **+1.643** |
| `fr3_knee_pitch` | **−1.303** | | `br3_knee_pitch` | **+1.303** |

**對照重點**：
- `abad`（`*1_hip_roll`）站著跟洩力時**應該一樣**（都是 ±0.523），因為控制器角 = 0
- `hip`（`*2`）從 ±2.443 變成 **±1.643**（差 0.8）
- `knee`（`*3`）從 ±2.803 變成 **±1.303**（差 1.5）

**站起來之後 hip / knee 的讀數有沒有往這個方向移動 0.8 / 1.5，一眼就看得出來。**

⚠️ 遙控器的站姿也可能不是 RL 預設姿。腳本會自動比對另外兩組候選（模擬版的 stand / liedown），
對不上就會直說「沒有任何組合對得上」。**對不上不是失敗，是資訊** —— 表示要用多姿勢直接解。

## 腳本輸出怎麼看

### ① 資料穩不穩

```
最大標準差 0.00312 rad　✅ 夠穩，資料可信
```

**超過 0.01 就重來** —— 代表狗還在晃或伺服在抖，那筆資料不能用。

### ② 換算式比對

```
換算式                          候選姿勢               RMS 殘差(rad)
V1  馬達 = sign×控制 + off       rl_default              0.0234  ★
V1  馬達 = sign×控制 + off       stand                   0.2082
...
最接近：V1 ＋ rl_default　RMS 0.0234 rad（1.34°）
★ 換算式與姿勢對上了。
```

- **RMS < 0.15 rad（≈8.6°）** → 有 ★，算對上了
- RMS 很大 → 會印「沒有任何組合對得上」，並建議再擷取一個姿勢

### ③ IMU 四元數（順帶確認）

```
以 xyzw 解：roll   -0.12°　pitch   -1.61°
以 wxyz 解：roll  -30.60°　pitch   +1.61°
```

**狗站在平地上，正確的那個解 roll/pitch 都要接近 0。**
我們先前是靠「取樣時剛好水平」推定 xyzw，這次是**刻意站平**，可以當定論。

## 卡住了怎麼辦

| 狀況 | 處置 |
|---|---|
| 標準差一直很大 | 等久一點再擷取；或加長 `--secs 5` |
| 印「沒有任何組合對得上」 | **正常**，記下來，多擷取幾個姿勢帶回來 |
| `joint_state` 讀不到 | 確認狗開機完成、`ls -l /dev/shm/` 有那三個檔 |
| 狗閃紅燈 | 停下來，跑 `M_faultwatch.py` 取證，別繼續 |
