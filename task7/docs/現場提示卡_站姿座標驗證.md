# 現場提示卡：站姿座標換算驗證

- 對象：D1 Max RK3588（`192.168.234.1`）
- 風險：**零**。全程唯讀、不需 sudo、不碰任何行程、不寫任何指令
- 時間：10–15 分鐘
- 狗的狀態：**用遙控器正常操作即可**，我們只在旁邊讀資料

---

## 為什麼要做這件事

我們讀得到 16 顆馬達的角度，但**不知道它跟控制器／MJCF 的關節角是什麼關係**。

從實機設定檔推出來一條假說：

```
馬達角 = side_sign × 控制器角 + offset
```

目前只驗到「控制器角 = 0」這一個點（馬達洩力時 `joint_cmd` 的 `p_des` 剛好等於 offset，四組全中）。
**斜率完全沒驗過。** 要驗就得讓狗擺出一個已知的非零姿勢 —— 也就是站起來。

⚠️ **這條式子沒確認，之後模擬算出來的關節角就沒辦法換成實機指令。** 是做步態的必要前提。

---

## 步驟

### 0. 部署（在你的電腦）

```bash
nmcli con up d1max-wifi && ping -c3 192.168.234.1
scp task7/realbot/{shm_io.py,M4_pose_capture.py} robot@192.168.234.1:~/
ssh robot@192.168.234.1
```

### 1. 站姿（預設：後腿往前彎）

**用遙控器讓狗站起來，等它完全停穩**（不要有晃動），然後：

```bash
python3 M4_pose_capture.py stand_knee_front --note "站立鍵，後腿往前彎"
```

它會取樣 2 秒、平均，然後自動比對 **4 種換算式 × 6 組候選姿勢**（3 種文件姿勢 × 2 種膝模式）。

### 1b. 另一種站姿（後腿往後彎）

用遙控器切換膝關節姿態，停穩後：

```bash
python3 M4_pose_capture.py stand_knee_back --note "膝關節切換後，後腿往後彎"
```

### 2. 趴姿

**用遙控器讓狗趴下，停穩**，然後：

```bash
python3 M4_pose_capture.py lie_knee_front --note "趴下鍵"
```

### 3. （有的話）第三個姿勢

遙控器上如果有「高站姿 / 低站姿 / 匍匐」之類的，各擷取一個，名字自己取：

```bash
python3 M4_pose_capture.py high
python3 M4_pose_capture.py crawl
```

**姿勢差異越大越好**，對驗證斜率越有幫助。

### 4. 收工

```bash
exit
scp -r robot@192.168.234.1:~/m_logs ./m_logs_trip6
nmcli con down d1max-wifi && nmcli con up Q500_ForDog
```

## ★★ 這台狗有兩種站姿，兩種都要擷取

**後腿往前彎（預設）** ／ **後腿往後彎**（一般機器狗的樣子）。
官方規格書運動性能欄明載「支持膝關節姿態變換」，機上也有 `/robot_remote/knee_mode` 這個 topic。

**兩種都做**，因為：
1. 姿勢差異很大（後腿 hip 差 1.6 rad、knee 差 3.0 rad）→ 對驗證斜率**極有幫助**
2. 可以確認切換模式時是不是真的只有後腿在變

### 命名與備註（★ 很有幫助，請照做）

檔名用**「動作_膝模式」**，另外用 `--note` 寫下當下的觀察：

```bash
python3 M4_pose_capture.py stand_knee_front \
  --note "遙控器按站立鍵，後腿往前彎，目視偏高"

python3 M4_pose_capture.py stand_knee_back \
  --note "同一個站立鍵，另外按膝關節切換，後腿往後彎"

python3 M4_pose_capture.py lie_knee_front \
  --note "遙控器趴下鍵"
```

`--note` 的內容會**一起存進 json**，事後離線判讀時比檔名有用得多。
值得寫的：按了哪個鍵、後腿朝哪彎、目視高不高、有沒有異狀。

⚠️ 檔名重複會**覆蓋**舊檔（`pose_<label>.json`），所以每個姿勢用不同的名字。

## 現場對照表：兩種站姿應該讀到什麼

假說成立、且姿勢是設定檔的 **RL 預設姿**（abad 0、hip ±0.8、knee ∓1.5）時：

| 關節 | 後腿往前彎（預設） | 後腿往後彎 | 差 |
|---|---|---|---|
| `fl1_hip_roll` | −0.523 | −0.523 | — |
| `fr1_hip_roll` | +0.523 | +0.523 | — |
| `bl1_hip_roll` | +0.523 | +0.523 | — |
| `br1_hip_roll` | −0.523 | −0.523 | — |
| `fl2_hip_pitch` | **+1.643** | +1.643 | — |
| `fr2_hip_pitch` | **−1.643** | −1.643 | — |
| `bl2_hip_pitch` | **−1.643** | **−3.243** | **−1.60** |
| `br2_hip_pitch` | **+1.643** | **+3.243** | **+1.60** |
| `fl3_knee_pitch` | **+1.303** | +1.303 | — |
| `fr3_knee_pitch` | **−1.303** | −1.303 | — |
| `bl3_knee_pitch` | **−1.303** | **−4.303** | **−3.00** |
| `br3_knee_pitch` | **+1.303** | **+4.303** | **+3.00** |

**對照重點（不用比對全部 12 個）**：

- `abad`（`*1`）站著跟洩力時**應該一樣**（都是 ±0.523），而且**兩種站姿也一樣**，因為控制器角 = 0
- **前腿**（`fl* / fr*`）**兩種站姿完全相同** —— 只有後腿在變
- 從洩力到站立：`hip` 從 ±2.443 → ±1.643（差 0.8）、`knee` 從 ±2.803 → ±1.303（差 1.5）
- 切到「後腿往後彎」：**只有後腿**（`bl* / br*`）再變 hip ∓1.6、knee ∓3.0

**站起來後前腿的 hip/knee 有沒有各移動 0.8 / 1.5，切模式時是不是只有後腿在動 —— 這兩件事現場一眼就能看出來。**

⚠️ 「後腿往後彎」那組數字是**推論**（把設定檔的後兩腿翻號算出來的），實機沒驗過。
knee 的 ±4.303 已經超出 URDF 的機構限位 ±2.801 —— 這代表**要嘛那台的限位比 URDF 寬、
要嘛我的推論錯了**。所以這一組對不上很正常，**對不上反而是有用的資訊**。

⚠️ 遙控器的姿勢也可能根本不是 RL 預設姿。腳本會自動比對全部 6 組候選
（3 種文件姿勢 × 2 種膝模式），對不上就直說。**對不上不是失敗，是資訊。**

## 腳本輸出怎麼看

### ① 資料穩不穩

```
最大標準差 0.00312 rad　✅ 夠穩，資料可信
```

**超過 0.01 就重來** —— 代表狗還在晃或伺服在抖，那筆資料不能用。

### ② 換算式比對

```
換算式                          候選姿勢               RMS 殘差(rad)
V1  馬達 = sign×控制 + off       rl_default              0.0234  ★
V1  馬達 = sign×控制 + off       stand                   0.2082
...
最接近：V1 ＋ rl_default　RMS 0.0234 rad（1.34°）
★ 換算式與姿勢對上了。
```

- **RMS < 0.15 rad（≈8.6°）** → 有 ★，算對上了
- RMS 很大 → 會印「沒有任何組合對得上」，並建議再擷取一個姿勢

### ③ IMU 四元數（順帶確認）

```
以 xyzw 解：roll   -0.12°　pitch   -1.61°
以 wxyz 解：roll  -30.60°　pitch   +1.61°
```

**狗站在平地上，正確的那個解 roll/pitch 都要接近 0。**
我們先前是靠「取樣時剛好水平」推定 xyzw，這次是**刻意站平**，可以當定論。

## 卡住了怎麼辦

| 狀況 | 處置 |
|---|---|
| 標準差一直很大 | 等久一點再擷取；或加長 `--secs 5` |
| 印「沒有任何組合對得上」 | **正常**，記下來，多擷取幾個姿勢帶回來 |
| `joint_state` 讀不到 | 確認狗開機完成、`ls -l /dev/shm/` 有那三個檔 |
| 狗閃紅燈 | 停下來，跑 `M_faultwatch.py` 取證，別繼續 |
