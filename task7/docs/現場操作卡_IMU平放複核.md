# 現場操作卡：IMU 平放複核（唯讀，零風險）

**這張卡完全不寫任何東西，只讀 `/dev/shm/imu_central`。狗不需要吊掛。**

- 對象：D1 Max 的 **RK3588**（`192.168.234.1`，帳號 `robot`）
- 物理擺放：**狗趴在地上／平放**，不需要吊帶
- 預計時間：15 分鐘
- 風險：**零**。全程唯讀，不需要 root，不碰 `joint_cmd`，不凍結 `mc_ctrl`
- 這張卡設計成**離線可用** —— 連上狗的 WiFi 就沒有網路

---

## ⚠️ 為什麼要做這件事

CPG-RL 的 68 維 observation 裡，**前 6 維（重力向量 3 ＋ 角速度 3）全部來自
`/dev/shm/imu_central`**。而那塊 SHM 目前的驗證程度是：

| | 狀態 |
|---|---|
| `joint_state`（關節角/角速度） | ★ **實機驗過是 1 kHz 活的串流** |
| **`imu_central`** | ⚠️ **只有 2026-08-25 那一次離線快照解碼過** |

而且**四元數順序 `xyzw` 是推出來的，不是實驗出來的**：
當時的判讀依據是「取樣當下加速度顯示重力在 +Z、x/y ≈ 0，所以機身是水平的，
用 xyzw 解得 roll −0.12° / pitch −1.61°（自洽），用 wxyz 解得 roll −30.6°（矛盾）」。

**那是一次「剛好水平」的巧合取樣，不是刻意做的平放實驗。**

### 錯了會怎樣

四元數順序錯 → 重力向量整個翻掉 → **policy 直接廢掉**。
而且症狀不會是「報錯」，是「狗一站起來就往某個方向倒」，
現場會被誤判成「RL 沒訓練好」而去改訓練，實際上是觀測層讀錯。

★ **這張卡不執行不影響訓練，但不執行就不可以上實機。**

## T0：串流是活的嗎？

**這一階回答的是「`imu_central` 到底是不是活的資料」** ——
如果它是一塊寫死的靜態記憶體，後面三階量到的一切都沒有意義。

```bash
cd ~/rbtdog && python3 - <<'EOF'
import time
import sys
sys.path.insert(0, "task7/realbot")
import shm_io

with shm_io.Shm("imu_central") as s:
    prev = None
    n_same = 0
    for i in range(30):
        v = shm_io.read_imu()          # acc[3], gyro[3], quat[4]（xyzw）
        q = v["quat"]
        norm = sum(x * x for x in q) ** 0.5
        if prev is not None and v == prev:
            n_same += 1
        prev = dict(v)
        print(f"{i:2d}  acc=({v['acc'][0]:+.3f},{v['acc'][1]:+.3f},{v['acc'][2]:+.3f})"
              f"  gyro=({v['gyro'][0]:+.4f},{v['gyro'][1]:+.4f},{v['gyro'][2]:+.4f})"
              f"  |q|={norm:.6f}")
        time.sleep(1.0)
    print(f"\n連續相同的次數：{n_same} / 29")
EOF
```

### 判讀

| 現象 | 判定 |
|---|---|
| `gyro` 三軸都在 ±0.001 附近**微微抖動**、每次都不完全一樣 | ✅ **活的** |
| `\|q\| = 1.000000`（每一筆） | ✅ 是合法的單位四元數 |
| **連續相同次數 ≥ 25** | ❌ **這塊是靜態的**，停在這裡，回報 |
| `\|q\|` 不是 1 | ❌ 欄位位移可能讀錯，停在這裡 |

⚠️ **不要用「數字看起來合理」當判準。** 靜態的快照數字也很合理 ——
判準是「**它會不會變**」。

## T1：平放 —— 兩個獨立來源要互相對得上

**判準是「加速度計」與「四元數」兩個獨立來源交叉驗證，不是「角度看起來接近 0」。**

狗平放，執行：

```bash
cd ~/rbtdog && python3 - <<'EOF'
import math
import sys
sys.path.insert(0, "task7/realbot")
import shm_io


def rpy_from(q, order):
    if order == "xyzw":
        x, y, z, w = q
    else:                       # wxyz
        w, x, y, z = q
    roll = math.atan2(2 * (w * x + y * z), 1 - 2 * (x * x + y * y))
    pitch = math.asin(max(-1.0, min(1.0, 2 * (w * y - z * x))))
    yaw = math.atan2(2 * (w * z + x * y), 1 - 2 * (y * y + z * z))
    return [math.degrees(v) for v in (roll, pitch, yaw)]


v = shm_io.read_imu()
a = v["acc"]
g = math.sqrt(sum(x * x for x in a))
# 加速度計的獨立解（重力方向 → roll/pitch）。與四元數完全無關。
acc_roll = math.degrees(math.atan2(a[1], a[2]))
acc_pitch = math.degrees(math.atan2(-a[0], math.sqrt(a[1] ** 2 + a[2] ** 2)))
print(f"acc = ({a[0]:+.3f}, {a[1]:+.3f}, {a[2]:+.3f})  |a| = {g:.3f} m/s²")
print(f"★ 加速度計解：roll {acc_roll:+7.2f}°   pitch {acc_pitch:+7.2f}°")
for order in ("xyzw", "wxyz"):
    r, p, y = rpy_from(v["quat"], order)
    print(f"  {order} 解：roll {r:+7.2f}°   pitch {p:+7.2f}°   yaw {y:+7.2f}°")
EOF
```

### 記錄表（現場填）

| 量 | 值 |
|---|---|
| `acc` = (x, y, z) | (        ,        ,        ) |
| `\|a\|` | |
| ★ 加速度計解 roll / pitch | / |
| `xyzw` 解 roll / pitch | / |
| `wxyz` 解 roll / pitch | / |

### 判讀

| 判準 | 通過條件 |
|---|---|
| `\|a\|` | **9.7 ~ 9.9 m/s²**。差太多代表尺度或欄位錯了 |
| `acc` 的 z | **正的且接近 9.8**（2026-08-25 量到 +9.886） |
| ★ **哪一個順序的 roll/pitch 與加速度計解吻合到 2° 以內** | 那個才是對的順序 |

⚠️ **平放時 roll/pitch 都接近 0，所以兩種順序可能都「看起來接近 0」。**
這一階單獨**不足以**定案 —— 一定要做 T2、T3。
（2026-08-25 那次之所以能分辨，是因為 `wxyz` 解出 −30.6° 這種明顯矛盾的值，
但那要碰運氣。）

## T2：前傾（pitch）

把狗的**後方墊高約 10 cm**（用書或箱子墊在後腳下），機身明顯前傾。
跑與 T1 完全相同的指令。

| 判準 | 通過條件 |
|---|---|

## 結案判準

**四項全部通過才算定案：**

- [ ] T0：串流是活的（gyro 會抖、`|q| = 1`、連續相同次數 < 25）
- [ ] T1：`|a|` 在 9.7–9.9、`acc.z` 為正
- [ ] T2：`xyzw` 的 **pitch** 與加速度計解同號且差 < 3°
- [ ] T3：`xyzw` 的 **roll** 與加速度計解同號且差 < 3°

通過之後，把結果寫進 `task7/docs/` 並更新 `obs_max.py` 開頭那張表的
「驗證程度」欄（把 ⚠️ 改成 ★，並註明日期）。

### 中止條件 —— 任何一項不符就停，不要硬推

| 現象 | 意思 | 怎麼辦 |
|---|---|---|
| T0 連續相同 | SHM 是靜態的 | **停**。RL 的 obs 前 6 維沒有來源，這條線要重新規劃 |
| `\|a\|` 明顯不是 9.8 | 欄位位移或單位錯 | **停**。回頭重解 `shm_decode.py` 的位移 |
| **`xyzw` 與 `wxyz` 兩個都對得上** | 這次的姿態分辨不出來 | 把傾角**加大到 20°** 再做一次；仍分辨不出就換成「把狗側躺 90°」 |
| `xyzw` 對不上但 `wxyz` 對得上 | **順序推錯了** | ⚠️ 這是**好結果**（趁上機前抓到）。改 `obs_max.py` 與 `cpg_max.w2b` 的呼叫端，並在文件記下來 |
| roll/pitch 對得上但符號相反 | 座標系手性或軸定義不同 | **停**並記錄。這會讓 policy 往反方向修正，比順序錯更難察覺 |

## 附註：為什麼不順便驗 gyro 的軸向

因為那需要「以已知角速度轉動機身」，而平放狀態下做不準。
gyro 的軸向錯誤在訓練裡由 `GYRO_NOISE` / `GYRO_BIAS` 的隨機化**蓋不住**
（那是雜訊不是軸向），所以它是一個**已知的剩餘風險**，
建議在第一次實機走路前用「把狗繞 z 軸原地轉 90°、看 `gyro.z` 的積分」補驗。
本卡不含這一項。
