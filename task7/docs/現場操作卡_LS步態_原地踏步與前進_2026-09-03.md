## 2. 參數（★ 兩組，不要混用）

兩組**共用**的部分：

```
--seq ls  --kp 120 --kd 1.0 --wheel-kd 3.0  --g-c 0.048  --duty 0.80  --omega 1.4
--sway-x 0.015 --sway-y 0.010 --sway-lead-x 0.90 --sway-lead-y 0.20
```

| | **A. 原地踏步** | **B. 往前走** |
|---|---|---|
| `--march`（`d_step`=0）| ✅ | ✗（`--d-step 0.10`）|
| `--x-off` | **+0.070** | **−0.020** |
| Δhip（姿態不對稱）| −19.7° | **+5.7°** ★ |
| 前 / 後大腿∠機身 | 55.3° / 35.6° | **41.4° / 47.1°** |

**兩組只差 `d_step` 與 `x_off`。**

### ★ B 就是「LS walk + body sway 對稱組」（影片 `x_split_now_sway.mp4` 右邊那個）

`x_off = −20 mm` 決定姿態，Δhip **5.7°**（現行 30.5°）。**這是這趟的重點。**

⚠️ 但 `g_c` 從影片那組的 0.07 降到 **0.048**，理由是命令速度：

```
影片那組（ω1.4 / g_c 0.07）→ 命令速度 15.96 rad/s ＞ 護欄 14   ❌
本組  （ω1.4 / g_c 0.048）→ 命令速度 13.80 rad/s              ✅
```

**影片是模擬，看不到這件事**：模擬撓 32.5 mm、實機 kp=120 撓 72 mm，
所以實機的 `z_sag` 要補 0.075（模擬只補 0.0325），同樣的 `g_c`／`ω`
命令幅度多 42 mm、命令速度高 50%。
★ **降 `g_c` 不動 `x_off`，所以姿態對稱度完全沒變** —— 換掉的是抬腿量
（85 → 64 mm）與速度（0.255 → 0.203 m/s）。

### ⚠️ 為什麼兩組的 `x_off` 差這麼多、還反號

`x_off` 是**配平點**，會隨 `d_step` 和 `ω` 移動。實測（60 s、模擬）：

| | 漂移過零的 `x_off` |
|---|---|
| **原地踏步 ω=1.4 / g_c 0.048** | **+70 mm**（+60 → +518 mm、+80 → −835 mm）|
| 原地踏步 ω=1.1 / g_c 0.07 | +85 mm |
| 原地踏步 ω=0.8 / g_c 0.07 | +50 mm |
| **前進 ω=1.4** | **−20 mm** |
| 前進 ω=1.2 | −30 mm |
| 前進 ω=1.1 | −60 mm |

**照抄另一組的值 = 狗會自己往前或往後跑掉**（差 10 mm 就是 0.6–1.6 m/60s）。

⚠️ **原地踏步沒有對稱版本可選。** 它的配平點必然是**正的**（+50~+85），
所以姿態必然是「前腿挺、後腿斜」的反向不對稱（Δhip −19.7°）。
那是 `d_step=0` 的物理特性，不是選錯參數 —— 對稱的目標只適用於**前進**那組。

### ⚠️ ω 為什麼是 1.4，以及為什麼不能再降

**ω 決定配平點，配平點決定姿態。** 這是這趟最容易踩的坑：

| ω | 前進的配平點 | Δhip |
|---|---|---|
| 1.1 | −60 mm | 16.9° |
| 1.2 | −30 mm | 8.5° |
| **1.4** | **−20 mm** | **5.7°** ★ |

**要拿到 5.7° 的對稱姿態就必須用 ω=1.4。** 降 ω 會把配平點推遠、姿態變回不對稱
（我第一版操作卡就是這樣把對稱度弄丟的）。ω 的上限由命令速度管，
所以留在 1.4 而改用降 `g_c` 換餘裕。

★ 另外，**`ω` 低不等於溫和，是相反的**。實測前進的 max 膝：
ω0.8 → 55.0、ω1.0 → 53.5、ω1.4 → 41.8。低 ω 時俯仰大到 10°，機身傾斜讓單腿多扛。
**不要為了保守把 ω 往下調** —— 那同時弄糟姿態與力矩。真要保守就縮短時間。

## 3. 預期值（模擬，60 s；用來判斷「對不對」）

| | A. 原地踏步 | B. 往前走 |
|---|---|---|
| 跌倒 | 否（0/2）| 否（0/4）|
| **Δhip（姿態）** | −19.7° | **+5.7°** ★ |
| 前後漂移（60 s）| **−105 mm**（應接近 0）| 前進 **0.203 m/s** |
| 側偏（60 s）| −116 mm | 1.98 m |
| 偏航（60 s，擾動×4）| 全距 0.6° | **+17.0°**，全距 2.1° |
| **max 膝力矩** | **37.7** | **41.8** |
| 實際離地 | 47.5 mm | 64.5 mm |
| 週期俯仰 | 3.9° | — |
| 前腳執行率 | —（d_step=0）| 0.61 |
| 命令速度峰值 | 13.51 rad/s | 13.80 rad/s |

**⚠️ 實機膝力矩推估 = 模擬 × 1.46–1.52**（已知的系統性低估）：
A → **55–57 N·m**、B → **61–64 N·m**。**兩組都在門檻 70 以內**（這版比前一版低很多，
因為 `g_c` 從 0.07 降到 0.048 讓觸地衝擊下降）。
→ 若仍連續中止：**不要降 ω**（見上，那同時弄糟姿態與力矩），改降 `--g-c` 到 0.04。
⚠️ 但 `g_c` 不能再往下太多 —— 實際離地 = `g_c`，0.04 時只剩 40 mm。

## 4.4 ★ 互動模式（B 往前走建議用這個）

`--interactive` 把 B 拆成三段，每段之間停下來等你按 **Enter**：

```
站起來 →〔Enter〕→ 往前走 →〔Enter〕→ 原地停 →〔Enter〕→ crouch → 趴下
```

```bash
# ① 乾跑
python3 M9_gait.py --traj B_walk_ls.json --interactive \
        --kp 120 --kd 1.0 --wheel-kd 3.0 --seq ls --x-off -0.020 --g-c 0.048 \
        --sway-x 0.015 --sway-y 0.010 --sway-lead-x 0.90 --sway-lead-y 0.20 \
        --hold-max 10 --walk-max 10

# ② 確認乾跑全綠之後
sudo python3 M9_gait.py --traj B_walk_ls.json --interactive ... --confirm
```

**乾跑會印出最壞情況的時間預算**，要看到 `✅ 在承重上限 ... 之內`。
上面這組是 **8.5 + 10 + 1.5 + 3 + 10 + 3 + 1.5 + 10 + 6.5 = 54 秒**，
在預設的 `--max-secs 60` 之內。要走久一點就加大 `--walk-max`，
但**同時要放寬 `--max-secs`**，而那是承重時間 —— M7/M8 最長只撐 34.6 秒，
**41 kg 壓在腿上的發熱我們從來沒量過**。

### 互動模式的四件事

1. **按鍵是 Enter**（不是單鍵）。只在三個等待階段有效，其他階段按了會提示忽略 ——
   **按 Enter 跳不過站起來**。
2. **三個等待都有逾時**（`--hold-max`，走路段是 `--walk-max`）。
   逾時是**自動往下走**，不是中止 —— 忘了按也不會讓狗一直站著。
3. **增益過渡**：`READY` 之後有 1.5 秒的 `KP_DOWN`（250 → 120，狗靜止），
   停下來之後有 `KP_UP`（120 → 250）。★ 承重中 kp 階躍砍半會讓機身掉下去
   （靜態撓度 8.9 → 18 mm），所以那兩段刻意分開、而且在狗靜止時做。
4. **等待期間狗是承重站著的**，`estop` 隨時可用（第二個終端機）。
   保護中止在任何階段都照常生效，中止語意仍是「凍結目標角、原地撐住」。

## 5. 中止條件（除了 M9 內建的）

| 現場看到 | 動作 |
|---|---|
| 原地踏步 20 秒漂超過 **0.3 m** | 停。配平點不對，調 `--x-off`：**往前跑 → 加大**（+70 → +80）、**往後 → 減小**。實測靈敏度約 **10 mm ↔ 0.7 m/60s** |
| 機身明顯左右晃 | 停。**先把 `--sway-y` 設 0** 再試一次（sway 是今天新加的，且模擬對側向不可信）|
| 膝關節聲音變大 / 溫度上升 | 停，讀 `joint_state` 溫度 |
| 輪子明顯打滑（看膠帶）| 停。`--wheel-kd 3.0` 是新值，可先退回 1.0 |

## 6. ⚠️ 這趟最大的三個未知

1. **模擬對側向（ABAD 方向）不可信** —— 實測模擬/實機 = **10.8 倍**。
   **body sway 的橫向分量（`--sway-y`）正是純側向動作**，實機表現可能與模擬差很多。
   → 若一開始就晃，`--sway-y 0` 是第一個要試的（縱向 `--sway-x` 才是解前腳執行率的那一項）。
2. **A 的膝力矩推估 74–77 N·m 超過門檻 70。** 保護不要放寬；真的一直中止就降 `--omega`。
3. **LS 序列從沒上過機。** 它與 DS 只差 fr/fl 對調，外觀很像 —— **靠影片分不出來**，
   要靠 M9 印的「擺動順序 RL → FL → RR → FR」確認。
