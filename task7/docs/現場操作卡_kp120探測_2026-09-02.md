## 0. ⚠️ 這一趟的定位：**是量測，不是預演**

原本想「先跑 march 版預演最終設定」，但模擬跑完發現**模擬對這個改動的
好處和代價都算不準**：

| | 模擬說 | 為什麼不可信 |
|---|---|---|
| 力矩好處 | kp 250→120 只降 21%（53.9 → 42.5）| **模擬低估的正好是撞擊那一項**，而 kp 該發揮作用的就是那裡。原廠在 kp=120 實測是 28–40，我們 kp=250 是 80 —— 真實差距遠大於 21% |
| 漂移代價 | 倒退 888 mm（10 秒步態）| 實機漂移一向是模擬的 **2.8 倍**，而且這是同一套算不準的接觸模型 |

**所以這趟是去量三個模擬答不了的數字：**

1. **狗在 kp=120 撐不撐得住**（新的增益排程碼第一次上機）
2. **實機膝力矩降到多少**（模擬 42；原廠同增益是 28–40；我們 kp=250 是 80）
3. **實機倒退多少**（模擬 −185 mm，可信度低）

⚠️ **這趟跑完之前，不要規劃前進步態。** 上面三個數字會決定最終設定長怎樣。

## 1. 這一趟改了什麼（和前四趟比）

| | 前四趟 | **這趟** |
|---|---|---|
| 步態 kp / kd | 250 / 5.0 | **120 / 1.0** ← 原廠動作時用的值 |
| **站起來/坐下 kp** | 250 | **250**（沒變，見 §2）|
| `z_sag` 補償 | 0.036 | **0**（原廠不補償）|
| `g_c` | 0.08 | **0.06** |
| ω | 0.3–1.0 | **1.4** |
| 步態長度 | 16 秒 | **4 秒** |

### 為什麼 ω 反而調高

M6 錄到**原廠的步頻是 2.15 Hz** —— 比我們跑過最快的（trip13，1.0 Hz）還快兩倍，
而它的膝力矩只有我們的 1/3。**步頻從來不是問題，幅度和剛度才是。**
前面整條 ω 階梯往「更慢」找安全，方向是錯的。

## 2. ★★ 程式改了：站起來不再用步態增益

`STANDUP_KP = 250` 以前**定義了卻從沒被用過** —— 整支程式（站起來、承重、
步態、坐回去）全部跑 `--kp`。kp 一直是 250 時沒差，但這趟下 `--kp 120`，
狗就會用**沒測過的增益從趴姿站起來**，而 M7 只驗證過 250（四趟）。

已修成 `phase_gains()`：

```
RAMP_UP / GO_crouch / HOLD_crouch / GO_stand   → 250 / 5.0（M7 驗證過）
HOLD_stand                                     → 250 平滑降到 120（狗靜止時降）
GAIT                                           → 120 / 1.0
BACK_crouch 前半                                → 120 升回 250（往上收，安全方向）
HOLDB_crouch / BACK_LIE / RAMP_DOWN            → 250 / 5.0
按 Enter 坐回趴姿                                → 250 / 5.0（承重動作）
```

⚠️ 切換是**平滑的**，不是階躍 —— 承重中 kp 砍半會讓撐機身的力矩瞬間砍半。
6 個新測試釘住，含「kp=250 時行為與舊版完全一致」的迴歸。

★ **你在畫面上會看到 `kp` 欄在 `HOLD_stand` 那 2 秒從 250 滑到 120。**
那是正常的，而且是這趟最該確認的一件事。

⚠️⚠️ **`--kp 120 --kd 1.0` 不可以省。** 預設是 250/5.0（前四趟的值），

那是刻意的「說兩次」防呆：**軌跡檔說一次、你在命令列說一次**，

六項確認：

1. `✅ 前後膝反號`
2. **沒有**印「起點比 crouch 還高」
3. 表頭印 **`原地踏步　duty 0.8 ω 1.4 d_step 0.0 x_off 0.04 g_c 0.06 z_sag 0.0000`**
   ★ **`z_sag 0.0000` 和 `g_c 0.06` 是這趟的指紋**，和前四趟都不同
4. `增益：腿 kp 120.0 kd 1.0`（★ 命令列要帶 `--kp 120 --kd 1.0`，見上）

6. `總時長 19.0 秒`（不是 31 秒 —— 步態只有 4 秒）

## 9. 這趟**不**做的事

- **不跑前進步態。** 要等這三個數字出來才設計得了。
- **不動 `wheel_kd`。** 那是獨立的一格改善，不要疊。
- ⚠️ **不要因為「離地變小、看起來溫和」就想加長步態。** 模擬顯示這個設定
  **會持續倒退**（10 秒步態倒退 888 mm），而且 `x_off` 從 −0.02 掃到 +0.10
  都改不掉 —— 那是**拖地**造成的，不是配平問題。步態只給 4 秒就是為了這個。
