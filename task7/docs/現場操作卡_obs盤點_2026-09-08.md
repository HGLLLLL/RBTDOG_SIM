## 1. 狗上：階 I（IMU）＋ 電腦探測

先 `ssh robot@192.168.234.1`（密碼 `bot`），檔案在 `~/`。狗**由原廠遙控器控制**，我們不寫任何東西。

| 階 | 指令 | 狗的狀態 | **你要記的** |
|---|---|---|---|
| **I-a 平放** | `python3 M6_load_probe.py flat --record --secs 30 --hz 200 --note "趴平不動"` | 趴平、馬達洩力、**不碰**；地面先用手機水平儀看一眼 | — |
| **I-b 跳舞** | `python3 M6_load_probe.py dance --record --secs 90 --hz 500 --note "遙控器跳舞"` | 起錄後**等 5 秒**再按跳舞（前 5 秒是靜態基線） | ★ **機身一開始先往狗的左側低還是右側低** |
| **I-c 原地轉** | `python3 M6_load_probe.py turn --record --secs 30 --hz 200 --note "左轉5s 停3s 右轉5s"` | 起錄後：**左轉** 5 s → 停 3 s → 右轉 5 s（9/2 錄過 `yaw_spin`，遙控器有這功能） | 先左（照做就是） |
| **I-d 電腦探測** | `python3 M_env_probe.py` | 趴著，30 秒 | 看它印的 numpy 有無、前向 ms |

> I-b 錄完會印 `hz_actual`；若明顯低於 450，改 `--hz 400` 再錄一次（更新率估計只需 ≥ 400）。
> I-b 跳舞若中途停了，讓它再跳一次也沒關係，錄滿 90 秒。

## 2. 狗上：階 II（步態側錄）

**兩個 ssh 視窗。** ssh#2 先開錄、再在 ssh#1 跑 M9；M9 結束（趴下）後才 Ctrl-C 停錄——要錄到「趴著→站→走→停→趴」的全程。

## 3. 本機：收檔、判讀

```bash
cd ~/rbtdog_sim
bash task7/realbot/pull_from_dog.sh trip18            # 收到 task7/logs/m_logs_trip18/
ls task7/logs/m_logs_trip18/M6_*.json                  # 應有 flat / dance / turn / walk 四個
```

階 I（把 `<flat>` 等換成實際檔名；`--seen-first` 填你眼睛看到的）：
```bash
conda run -n rbtdog python task7/inference/imu_check.py \
    --flat task7/logs/m_logs_trip18/M6_<flat>.json \
    --dance task7/logs/m_logs_trip18/M6_<dance>.json \
    --turn task7/logs/m_logs_trip18/M6_<turn>.json \
    --seen-first left|right --turn-first left
```
→ `task7/outputs/imu_check.json`。**要看到**：`quat_order xyzw`（兩段一致 True）、
`gyro 單位 rad/s`、`軸對調 False`、`first_roll.consistent True`、`turn.consistent True`、
`IMU vs 腿FK corr` 兩軸 > 0.9。任何一項不是 → 先別訓練，回來討論。

階 II：
```bash
conda run -n rbtdog python task7/inference/obs_compare.py \
    task7/logs/m_logs_trip18/M6_<walk>.json \
    --imu-check task7/outputs/imu_check.json \
    --md task7/outputs/obs_compare_table.md --video task7/outputs/obs_replay.mp4
```
→ `task7/outputs/obs_noise_model.json`（訓練端直接讀）＋ 逐欄表 ＋ 回放影片。

結果整理成 `docs/H_實機obs盤點_2026-09-08.md`，並把 `logs/m_logs_trip18/` 進版控。

## 4. 已經從舊資料知道的（trip14，9/2 原廠七段 500 Hz）

上機前先知道「大概會看到什麼」，現場才分得出異常：

| 量 | trip14 結果 | 這趟要確認什麼 |
|---|---|---|
| quat 順序 | **xyzw**（重力方向誤差 2.2° vs 122°） | 刻意平放＋跳舞再證一次 |
| acc 單位 | m/s²（模長 9.95） | — |
| gyro | **rad/s、三軸同號、無軸對調**（k 0.91/1.07/0.98） | 跳舞幅度大，擬合會更乾淨；轉向定 z 正負 |
| 更新率 | gyro/acc/關節 ≥ 480 Hz（受 500 Hz 錄製上限） | 500 Hz 跳舞再看一次 |
| 關節角量化 | 0.00038 rad（14 位元） | — |
| IMU 安裝偏置 | pitch 約 −1 ~ −1.4°、roll ~0 | 平放＋腿 FK 定案 |
| des→q 延遲 | 實機 33 ms vs 模擬 17 ms（原廠增益） | **我們的增益（kp250）下是多少** —— 這是階 II 最重要的一個數字 |
| joint_vel 欄位 | 500 Hz 下比角度差分乾淨（driver 有濾波），落後 12–20 ms | 200 Hz、步態工況下的雜訊與延遲 |
