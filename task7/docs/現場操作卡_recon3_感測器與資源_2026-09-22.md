
## 2. 跑腳本

```bash
cd ~/rbtdog_sim
bash task7/realbot/recon3_sensors_d1max.sh
```

順序是：本機預檢 → 連線暖機（密碼在這裡一次打完）→ 兩塊板靜態盤點 →
**待機採樣 30 秒** → 停下來等你 → **走路採樣 40 秒** → RTSP 實測 → 產表。

走路那段的提示出現時：

1. 場地淨空，另開一個終端機備好急停
   ```bash
   bash task7/realbot/estop_max.sh
   ```
2. 用**原廠遙控器**讓狗站起來走（直走或原地踏步都行，**動作不要停**）
3. 狗**正在走**的時候回來按 Enter，等 40 秒
4. 採樣完讓狗停下來／趴下，再按 Enter 做 RTSP

不方便讓狗走就加 `--no-walk`，7.1／7.2／7.4 照樣全拿得到，只有 1.3 少了對照組。

常用旗標：

| 旗標 | 用途 |
|---|---|
| `--no-walk` | 不操狗，只做靜態盤點與待機採樣 |
| `--rk-only` | Orin NX 連不上時 |
| `--wired` | 走有線（RK 變 192.168.168.168） |
| `--idle 60 --walk 60` | 採樣拉長 |
| `--no-sudo` | 完全不用 sudo（NPU/GPU 負載會少） |

## 4. 已知的坑（都已經寫進腳本，這裡只是讓你看懂輸出）

1. **ROS2 topic list 是空的不代表沒有 topic** —— 先看 log 裡的 `ROS_DOMAIN_ID` 與
   `RMW_IMPLEMENTATION`。運控在 RK 是 **66**，NX 是 **24**，官方文件只寫 24。
2. **感測 topic 多半是 best_effort**，用預設 QoS 訂閱會一筆都收不到，
   看起來像「topic 在但沒資料」。腳本每個量測都會自動退一步用 best_effort 再試一次。
3. **`set -u` 會被 `/opt/runtime/env.bash` 弄死**（`LD_LIBRARY_PATH` 未設）。
   第一趟偵察的 ROS2 整段就是這樣沒跑到，而且錯誤被 `2>/dev/null` 吞了。遠端段一律不用 `set -u`。
4. **`cpu7` 被核心隔離保留給運控**（`isolcpus=7`）。每核對照表就是在驗這件事，
   也決定我們的推論程式能排在哪幾顆核。
5. **光達在獨立網段**（前 `192.168.1.102`、後 `192.168.2.102`），
   從 PC 連不到是正常的，腳本是**從狗上**去 ping 它們。
