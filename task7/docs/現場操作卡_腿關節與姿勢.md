- [ ] 四腿**自由下垂、不觸地**、不碰任何東西

- [ ] 腿的擺動範圍內沒有人、沒有牆、沒有桌角

### 2. 狗必須是「洩力」狀態

- [ ] 16 顆馬達**全部零增益**（`kp = kd = effort = 0`）
- [ ] 做法：遙控器讓狗趴下／關閉運控，**不要讓它站著**

M5 自己會擋（讀 `joint_cmd`，有任何一顆帶增益就拒跑），
但**現場要先做到**，不要靠程式擋。理由有兩層：

1. 站著的時候凍結 `mc_ctrl`，腿會失去支撐（task6 的教訓）
2. 這個前置條件同時保證了「事後補一個 `SIGCONT` 不會突跳」——
   `mc_ctrl` 恢復時它記得的姿勢就是洩力，不會突然出力

### 3. 人與急停

- [ ] 急停鈕（機身鈕 / 遙控器 APP 紅色鈕）位置已確認、在手邊
- [ ] 電源開關位置已確認
- [ ] **至少一個人沒有在碰狗**，負責按急停
- [ ] ★ **第二個終端機已經開好、已經 ssh 進狗、游標停在急停指令上**：

```bash

```

**為什麼需要軟體急停，硬體急停鈕不夠**：
硬體急停切的是馬達電源，但**我們的程式還在跑、`mc_ctrl` 還凍著**。
`estop_max.sh` 處理的是另一半：殺掉我們的程式、確認死透、才把控制權交回原廠。

它做三件事，**順序不能換**：

```
1) 殺掉我們所有會寫 joint_cmd 的程式
2) 確認真的死了（含掃 /proc/*/maps 找出漏網的寫入者）
3) 才解凍 mc_ctrl
```

> ⚠️ **殺不掉卻解凍 = 我們的程式與原廠運控同時寫同一塊指令區**，
> 比什麼都不做更糟。所以第 2 步失敗時腳本會**拒絕解凍**並叫你切電源。
> （task6 的教訓，直接照抄。）

⚠️ 按下 estop 之後，腿會在約 **0.5 秒**後失力下垂（controller 逾時清零），
不是立刻、也不是阻尼。**腿下方不要有人或東西。**

### 4. 心理準備

輪子測試錯了，最壞是輪子亂轉。
**腿關節錯了，是把腿甩到機械停點上，帶著 41 kg 的慣量。**
所以整套流程的設計是**低增益 + 重力對照**，不是「先給原廠增益看它動不動」。

> 的態度與保固範圍。

## 1. 為什麼低增益比較安全，也比較有鑑別力

`kp` 給小的時候關節撐不住腿重，會**穩定地垂在一個誤差上**，滿足

```
τ_重力 = kp × 追蹤誤差
```

而 `τ_重力` 已經由 `inference/hang_rehearsal.py` 用官方 MJCF 事先算好，
存在 `hang_torque_ref.json`。**上機時就有對照值可以互比**：

| 現場看到 | 意思 |
|---|---|
| 同數量級、**同號** | ✅ 換算式、腿序、增益符號全部正確 |
| 差一個**負號** | ❌ `side_sign` 用反了。**立刻停，不要加大 kp** |
| 差好幾倍 | ⚠️ 腿序對錯，或 `kp` 的單位不是我們以為的那個 |

低 kp 錯了也只是垂下去，不會衝到停點。這比大增益試錯好一個量級。

**這也是為什麼對照表一定要帶上狗** —— 沒有它，現場只剩「追蹤誤差」一個判準，
而追蹤誤差看不出符號錯誤（反號時誤差一樣會變大，長得像增益不足）。

> ⚠️ **上面這條只適用 S2 以後**（命令一個遠離平衡的姿勢）。
> S1 微動從自然下垂出發，而自然下垂**依定義**就是零力矩平衡點 —— 那裡沒有
> 重力力矩可以量。S1 改看**位移**，判準與注意事項見 §3。

## 2. 部署腳本到狗上

```bash
cd ~/rbtdog_sim
nmcli con up d1max-wifi && ping -c3 192.168.234.1

bash task7/realbot/push_to_dog.sh        # ★ 傳檔 + sha256 雙向比對 + 清 __pycache__
```

腳本會逐檔比對本機與狗上的 sha256，**有一個對不上就 exit 1 並叫你不要上機測試**。
它也會清掉狗上的 `__pycache__` —— 舊的 `.pyc` 會讓 `import` 拿到上一版模組，
那正是「版本不一致偽裝成硬體問題」最常見的形式。

手動傳的備援寫法（腳本掛掉時用）：

```bash
scp task7/realbot/{shm_io.py,coord.py,M5_leg_pose.py,M0_probe.py,M_faultwatch.py,estop_max.sh} \
    task7/reference/hang_torque_ref.json \
    robot@192.168.234.1:~/
ssh robot@192.168.234.1 'rm -rf ~/__pycache__ && chmod +x ~/estop_max.sh'
```

**七個檔案**必須在**同一個目錄**（`~/`）：

| 檔案 | 為什麼要 |
|---|---|
| `shm_io.py` | SHM 讀寫底層，其他全部 `import` 它 |
| `coord.py` | 座標換算 + 限位 + 姿勢的**單一事實來源** |
| `M5_leg_pose.py` | 主程式 |
| `M0_probe.py` | 前提檢查、收工複核 |
| `M_faultwatch.py` | 閃紅燈時的取證工具 |
| `estop_max.sh` | ★ **急停**。第二個終端機備著（`sudo ~/estop_max.sh`） |
| `hang_torque_ref.json` | ★ **力矩對照表**。必須跟腳本同一層（M5 先找 `./`，再找 `../reference/`） |

### ⚠️ 鐵則：每次上機都重傳**全部**會用到的腳本

HANDOFF 特別記了這條。版本不一致的症狀會**偽裝成硬體問題** ——
例如「M0 過了但 M5 的腿不動」，看起來像馬達沒回應，其實是狗上的 `shm_io.py`
是舊版、心跳寫法不同。

不要因為「這次只改了 coord.py」就只傳一個。**七個一起傳，每次。**
★ `estop_max.sh` 裡有一份「會寫 joint_cmd 的程式」清單 ——
  **新增任何會寫入的工具時必須同步加進去**（task6 就是漏加，按下 estop 只解凍不殺程式）。

`push_to_dog.sh` 已經做完校驗和比對。手動傳的話要自己對一次：

```bash
ssh robot@192.168.234.1 'sha256sum ~/shm_io.py ~/coord.py ~/M5_leg_pose.py ~/hang_torque_ref.json'
# 跟本機 sha256sum 的結果逐行比對
```

## 3. ★ 增益與保護門檻

數值由 MuJoCo 吊掛預演算出（來源 `reference/hang_torque_ref.json`），**已經填好了**。
現場沒有網路也跑不了 MuJoCo，所以這裡不留空白。**S0 乾跑會再確認一次。**

| 階段 | `--kp` | `--kd` | `--emax` | 依據 |
|---|---|---|---|---|
| **S1** 微動（`fl2_hip_pitch`） | **15** | **1.0** | **0.15** | `s1_kp_by_kind.HIP`；挑法是移動比例 ≈ 0.5 |
| **S2/S3/S4** 驗證用 | **40** | **1.5** | **0.40** | 軌跡模擬 `40/1`～`40/4`：終端誤差 0.115 rad、峰值力矩 4.62 N·m、無過衝、未觸限位 |
| **S4/S5** 真的要到位時 | **120** | **4.0** | **0.30** | `traj_kp` / `traj_kd`；下垂降到 ≈ 0.05 rad |

`--abort-kd` 用預設 `3.0`，`--abort-hold` 用預設 `20`，`--tmax` 不用給（見下）。

**S1 的預期位移**（指令 `--delta 0.05`，kp=15）：

| 關節 | 剛度 k | τ₀ | 預期實走 | 比例 |
|---|---|---|---|---|
| `fl2_hip_pitch` | 14.24 | +0.014 | **+0.0252 rad（+1.44°）** | +0.50 |
| `fl3_knee_pitch` | 4.94 | +0.007 | +0.0373 rad | +0.75 |
| `fl1_hip_roll` | 15.89 | **+1.850** | **−0.0356 rad** | **−0.71** ← 反向，正常 |

> **★ 為什麼 kp 分兩階（40 → 120）而不是直接用 120**
> 40 的時候關節**撐不住、會明顯垂下來**，而垂多少是可以事先算出來的
> —— 那個下垂量就是驗證換算式與符號的訊號。
> 120 之下下垂只有 0.05 rad，訊號小、也失去了「錯了也只是垂下去」的保護。
> **先用 40 確認判讀全部 ✅，再升到 120 讓腿真的到位。**

**`--tmax` 不用填** —— 不給的話 M5 會**逐關節**自動採用預演的建議值
（`recommended.tau_limit_Nm`，ABAD/HIP/KNEE 各不同）。S0 會把實際採用的值印出來，
確認一下就好。只有在想更保守時才手動指定。

### ★ S1 的判讀量是「位移」，不是「下垂量」

自然下垂處依定義就是**零致動器力矩的平衡點**，那裡沒有重力力矩可以量。
所以 S1 看的是關節**走了多遠**：

```
實際位移 = (kp·Δ − τ₀) / (kp + k)
```

⚠️⚠️ **`τ₀` 對 ABAD 不是 0，而且會讓它往指令的反方向走。**

原因是一個吊起來才會出現的物理事實：**左右輪會在機身正下方互相頂住**
（預演偵測到 3 個接觸點，法向力約 3 N）。所以：

- 自然下垂時 **abad ≈ ∓0.28 rad（±16°）**，不是 0
- 該處 abad 的純重力力矩 **τ₀ ≈ ±1.85 N·m**，不是 0
- 對 abad 下 `+0.05` 的指令，它會往 **−0.036** 走 —— **這不是符號錯，是正常的**

M5 已經把 τ₀ 算進預測裡，判讀時是拿實測跟**預測值**比，不是跟指令的號比。
所以現場**照 M5 印的判讀欄看就好**，不要自己用「有沒有往指令方向走」去判。

### 怎麼決定 `--kp` 與 `--emax`（不必背數字，用法則）

1. **先跑 S0 乾跑**，它會印兩個關鍵值：
   - 每個關節的 `預演τ`
   - `預測最大下垂 = 預演τ / kp`
2. **`--emax` 至少要是「預測最大下垂」的 2 倍。**
   低 kp 是**故意**讓關節垂下來當量測手段；若 `emax` 比預測下垂還小，
   第一個 tick 就會中止 —— **那不是故障，是門檻設錯**。
   M5 會自己警告：「已達 --emax 的 80%，會誤中止，建議 --emax ○○」，照它印的填。
3. **`--tmax` 交給預演的逐關節建議值**（不給就是自動）。S0 會印出實際採用的值。
4. **`--kp` 由「預測下垂落在 `emax` 的 1/3 上下」反推。**
   太小 → 腿幾乎不動，量不到東西；太大 → 沒有低增益的保護意義了。
   微動階段另一個判準：讓 S0 印的**移動比例落在 0.3～0.7**，
   這時「有沒有走到位」的鑑別力最高（比例接近 1 的話，什麼都看不出來）。

> ★ ABAD（`*1_hip_roll`）在站姿下的重力力矩**明顯比 hip/knee 大**，
> 所以同一個 `kp` 之下它的下垂量最大，`--emax` 常常是被 ABAD 決定的。
> S0 的表裡看得出來，不要憑印象。

## 4. 逐階操作

每一階都是：**先乾跑 → 看預期 → 再實跑 → 對判讀表**。
任何一階的判讀不是 ✅，就**停在那一階**，不要往下。

### 通則

- 乾跑 = **不帶 `--confirm`**。不凍結行程、不寫入任何東西、不需要 `sudo`
- 實跑 = 帶 `--confirm`，**需要 `sudo`**
- **沒被 `--joints` 選中的關節，每一輪都被壓成零增益** —— 它們會自由下垂，這是預期的
- 每次結束後看一眼「心跳速率」，應接近 **1000/s**
- 每次跑完會在狗上留兩個檔：
  `~/m_logs/M5_<時間戳>.log`（人看的）與 `~/m_logs/M5_<時間戳>.json`（機器看的）

### ★ 分段把資料搬回來（不要跑完整趟才收）

這是 task7 前幾趟就在做的事（trip3 在 M1 後、M2 後各收一次），這份流程照辦。
**三個回收點：S1 之後、S4 之後、S6 之後。** 在筆電上（另一個終端機）：

```bash
scp -r robot@192.168.234.1:~/m_logs ./task7/logs/m_logs_trip7
```

三個理由，第三個最重要：

1. **防丟** —— 後面若閃紅燈 / 要 reboot，前面的資料已經下船了
2. **本機才做得了的檢查** —— 狗上沒有 numpy/mujoco。左右對稱性、
   前後對稱性、同一顆關節在 S2（單腿）vs S4（全身）表現是否一致，
   這些都要拿 `.json` 回來比
3. **強迫你停下來想** —— 不然很容易靠慣性一路 S1→S6 跑完。
   **每個回收點就是一個「要不要往下」的決策點**，不是形式

> `.json` 是 `schema: m5_run/1`，含每個關節 HOLD 期間的
> `q/des/err/tau` 平均、峰值、溫度，以及該關節的預演對照值
> （`tau_gravity` / `stiffness` / `tau_at_hang` / `predicted_move`）。
> **不要去 parse `.log` 的表格** —— 那種 parser 遲早會靜靜讀錯一欄。

### S0 — 乾跑（零風險，不需 sudo）

```bash
python3 M5_leg_pose.py --joints fl2_hip_pitch --delta 0.05
python3 M5_leg_pose.py --joints all --pose stand --kp 40
python3 M5_leg_pose.py --joints all --pose crouch --kp 40
python3 M5_leg_pose.py --joints all --pose stand --knee-back --kp 40
```

**四個都跑一遍**，把要用到的組合先在乾跑裡看過。

#### 要看到什麼

| 輸出 | 預期 |
|---|---|
| `✅ 已載入預演對照表 /home/robot/hang_torque_ref.json` | 路徑必須是 `~/`，不是別的 |
| `✅ 結構檢查通過（16 個關節名與順序相符）` | 必須 |
| `✅ 16 顆全部洩力中` | 必須 |
| `✅ mc_ctrl PID=… 狀態=S`（或 `R`） | 不可以是 `T`（T = 還凍著，上一次沒解凍） |
| 關節表的 **`預演τ` 欄** | ★ **不可以整欄都是「—」** |
| `✅ 起點與目標都在機構限位內（含餘裕）` | 必須 |
| `起始角 vs 預演自然下垂：最大差 … ✅ 相符` | 差 > 0.25 rad 就要檢查吊帶 |
| `預測最大下垂 … = 預演τ / kp` | 拿來決定 `--emax`（見 §3） |
| `預測位移 = (kp·Δ − τ₀)/(kp + k)`（只有 `--delta` 模式會印） | S1 的量化預期值。★ ABAD 那列的比例會是**負的**，那是正常的（見 §3） |
| `⚠️ 對照表裡沒有這個姿勢的力矩` | ❌ **這一階沒有大小的對照**，風險升高。四個姿勢現在都該有值，出現這行就是對照表版本不對 |

#### 什麼情況要停

- ❌ **`預演τ` 整欄是「—」** → 對照表沒被讀到，或姿勢名對不上。
  **這是沉默的降級**：程式仍會印「已載入」，但你其實沒有對照值。
  → 檢查 `~/hang_torque_ref.json` 存在、且是這次帶上來的版本。
  對照表拿不到就**不要往下**，因為反號判讀完全依賴它。
- ❌ `起始角 vs 預演自然下垂` 差很大 → 狗不是自由下垂。**吊帶纏到腿？腳踩到東西？**

- ❌ `16 顆洩力` 不過，而且只有 `kd` 非零 → 那是**上一次 M5 中止留下的阻尼**。
  照 M5 印的指示 `sudo kill -CONT <PID>` 解凍後重跑（見 §6）。

- ❌ `❌與預測反號` → **`side_sign` 用反了。不要加大 kp。**

- ❌ 動的是**別條腿**或**別的關節** → 腿序或索引對錯。立刻停。

- ⚠️ `⚠️幾乎沒動` → 多半是 kp 太小掙不脫靜摩擦。一次加一點（例如 ×1.5），
  不要一次跳很大。

只做一個方向的話，「剛好被重力帶著走」和「伺服真的在追」分不出來。

|---|---|

| 現象 | 意思 | **怎麼做** |

| 心跳速率 **0/s** | 心跳完全沒跟上 | 🛑 後面所有判讀都不用看了。回頭確認狗上的 `shm_io.py` 是這次傳的版本 |
| 中止訊息 `joint_state 的心跳連續 N 次沒有前進` | **驅動層凍住了**，讀回的角度不再更新 | 🛑 停。這個故障會**偽裝成**「追蹤誤差一直不收斂」，M5 特地把它分開報出來。不要當成增益不足去加大 kp |

| 溫度保護觸發 | 馬達過熱 | 🛑 停，讓它涼下來。連續跑很多階時要留間隔 |

## 6. 中止與復原 ★

### 保護觸發時 M5 做什麼

```
任何保護觸發 → 腿關節切成【純阻尼】（kp=0、effort=0、kd=--abort-kd）
             → 輪子歸零
             → 背景執行緒【持續】重寫指令與心跳（★ 不是只寫一次）
             → 印統計，然後停在這裡等你按 Enter
             → mc_ctrl **保持凍結**，不自動解凍
```

**為什麼不歸零**：腿帶著載荷時全歸零 = 自由落體撞機械停點。
純阻尼是「鬆手但有黏滯」，腿會慢慢垂下而不是砸下去。

**為什麼要背景執行緒**：只寫一次的話，controller 500 ms 後會把指令區清成 0，
阻尼就消失了 —— 而印統計 + 等人確認遠超過 0.5 秒。畫面上寫著「已切成純阻尼」，
實際上那個狀態早就沒了。**這是 2026-08-26 在本機測試抓到的真 bug。**

⚠️ **按下 Enter 之後阻尼就結束了，腿會失力慢慢垂下。**
所以按 Enter 前一定要先確認：腿的位置安全、沒有人在下方、吊帶沒纏住。
（非互動模式下改成自動維持 `--abort-hold` 秒，預設 20 秒。）

**為什麼故意不自動 `SIGCONT`**：`mc_ctrl` 恢復後會繼續下指令去**它凍結前的姿勢**。
若我們已經把腿移遠了，那就是一次**突跳** —— 中止時最不該做的事。

### 現場怎麼收

1. **先看狗。** 腿的位置、有沒有卡住、吊帶有沒有纏到。人退開。
2. 確認安全之後**手動解凍**（PID 會印在 M5 的輸出裡）：

```bash
sudo kill -CONT <PID>
```

前置條件已保證 `mc_ctrl` 凍結前是洩力狀態，所以**解凍本身不會出力**。

3. 找不到 PID 就自己抓：

```bash
pgrep -x mc_ctrl                          # 拿 PID
awk '{print $3}' /proc/<PID>/stat         # T = 還凍著，S/R = 正常
sudo kill -CONT <PID>
```

4. 解凍後跑一次 `python3 M0_probe.py` 確認 16 顆回到 `kp=kd=tau=0`。

> ⚠️ 中止後直接重跑 M5 會被擋下（`❌ 這些關節目前帶著非零增益`），
> 因為留著的 `--abort-kd` 阻尼還在。M5 會認出「只有 kd 非零」並告訴你去解凍。
> **先解凍，再重跑。**

### 程式整個當掉 / SSH 斷線

⚠️ **這一條的後果目前有兩種說法，尚未釘死。** 逾時是 `joint_cmd_timeout: 500 ms`：

| 說法 | 依據 | 後果 |
|---|---|---|
| **把指令區清成 0** | **實測**（M1 首次寫入失敗讀回全 0） | 腿**失力**下垂 |
| 套 `estop_kd = 35` | 讀設定檔推的，無觀測佐證 | 阻尼停止 |

**現場請當成「會失力」來準備**（保守的那一邊）。吊掛狀態下腿失力只是垂下去，
可以承受 —— 但**不要把它當安全網**，也不要在腿下方放東西或站人。

仍然要手動確認並解凍 `mc_ctrl`（同上）。

> 這也是為什麼 M5 中止時會開一個**背景執行緒持續餵心跳**維持阻尼：
> 寫一次就不管的話，0.5 秒後阻尼就沒了。結束時它會印
> 「阻尼保持結束：○ 秒內送出 ○ 幀（○/s）」—— **速率遠低於 200/s 就代表有段時間失去保護**。

### 狗有異常動作 / 聲音

**按急停**（機身鈕或遙控器 APP 紅色鈕）。然後解凍 `mc_ctrl`。

### 閃紅燈 / 故障

```bash
python3 M_faultwatch.py --hz 20 --secs 600
```

★ **開機後 1 分鐘內就要啟動。**（task6 的教訓：晚 1 分 49 秒就錯過了
`ready` 1→0 的轉換瞬間，那次白跑。**轉換點才是證據，穩態值沒有用。**）

它是唯讀的、不需 sudo，可以放心在故障狀態下跑。

### `mc_ctrl` 解凍後行為怪怪的

```bash
robot-launch list                        # 找到對應的 egg id
robot-launch restart <id>
```

最後手段是整台重開機。**`SIGSTOP` / `SIGCONT` 不會造成永久性改變。**

### ⚠️ 千萬不要做

- ❌ 反號時加大 `kp`（正回授，越大跑越遠）
- ❌ 受阻時加大 `kp`（只會把力矩推更高）
- ❌ 用 `--margin` 硬放寬限位檢查
- ❌ 用 `--no-return`（結束時腿不回起始姿勢，直接垂下），除非你已經確定安全
- ❌ 用 `pkill -f` / `pgrep -f` 搭配會匹配到自己命令列的字串（task6 中過兩次，
  一次直接殺掉自己的 SSH）。M5 內部一律用 `pgrep -x`
- ❌ 在 `mc_ctrl` 凍結狀態下離開現場
- ❌ 把輪關節（`*4_foot`）放進 `--joints`（M5 會擋，不要繞過）

## 附：M5 的完整參數表（從 `--help` 逐項核對過）

| 參數 | 預設 | 說明 |
|---|---|---|
| `--joints` | `fl2_hip_pitch` | `all` / `front` / `rear` / 腿名 `fl,fr,bl,br` / 完整關節名，逗號分隔。**輪子不會被展開進來** |
| `--pose` | 無 | `crouch` / `home` / `stand`（與 `--delta` 互斥） |
| `--delta` | 無 | 相對當前角度的增量（rad），微動測試用（與 `--pose` 互斥） |
| `--knee-back` | 關 | 用「後腿往後彎」的膝模式（預設往前彎） |
| `--confirm` | 關 | **不帶就是乾跑**：不凍結、不寫入 |
| `--kp` | 10.0 | 位置增益（原廠站立用 60~120） |
| `--kd` | 1.0 | 阻尼增益（原廠 1.0） |
| `--abort-kd` | 3.0 | 中止時的純阻尼值 |
| `--ramp` | 2.0 | kp 斜坡升／降的秒數 |
| `--move` | 4.0 | 移動到目標的秒數 |
| `--hold` | 3.0 | 到位後維持的秒數（統計就是取這段） |
| `--no-return` | 關 | 結束時**不回**起始姿勢（★ 腿會垂下，僅在確定安全時用） |
| `--hz` | 200.0 | 控制迴圈頻率 |
| `--tmax` | **自動** | 不給就逐關節採用預演建議值（ABAD 10 / HIP 8 / KNEE 7 N·m 量級）。硬體上限 150 |
| `--emax` | 0.40 | 追蹤誤差保護 rad |
| `--vmax` | 2.0 | 關節速度保護 rad/s |
| `--temp-max` | 70.0 | 馬達溫度保護 °C |
| `--margin` | 0.05 | 機構限位的安全餘裕 rad（只套用在**規劃的**軌跡，實測角用硬限位） |
| `--wheel-vel` | 0.0 | HOLD 期間同時以此角速度轉四輪（rad/s），0 = 不轉 |
| `--wheel-kd` | 1.5 | 輪子的阻尼增益 |
| `--wheel-tff` | 0.0 | 輪子的前饋力矩 |

### 時序（總長 = ramp + move + hold + move + ramp）

```
RAMP_UP  (--ramp)  kp 0 → 目標值，目標角維持在起始角
MOVE     (--move)  目標角餘弦插值到目標姿勢
HOLD     (--hold)  維持並記錄  ← ★ 統計與判讀取這一段
RETURN   (--move)  插值回起始角（--no-return 會跳過）
RAMP_DOWN(--ramp)  kp 降回 0
→ 全部歸零 + 補心跳 → SIGCONT 解凍
```

預設值下一次約 **15 秒**。
