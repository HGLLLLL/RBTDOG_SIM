## 1. 核心手法：低增益下的偏差量本身就是一次量測

kp 給小的時候，關節撐不住負載，會穩定地停在一個偏差上。那個偏差可以事先算出來。

### 1.1 遠離平衡點時（S2 以後）：偏差 = 重力力矩 / kp

```
τ_重力 = kp × 追蹤誤差
```

`τ_重力` 由 `inference/hang_rehearsal.py` 用官方 MJCF 事先算好，存在對照表裡。

| 實測 vs 預演 | 判讀 |
|---|---|
| 對得上（同數量級、**同號**） | 換算式、腿序、增益符號全部正確 |
| **差一個負號** | `side_sign` 用反了 → **立刻停，不要加大 kp** |
| 差好幾倍 | 腿序對錯，或 kp 的單位不是我們以為的那個 |

### 1.2 ★ 但微動測試（S1）不適用 1.1

**自然下垂姿勢依定義就是「零致動器力矩的平衡點」**，所以那裡的 `τ_重力 ≈ 0`，
偏差量沒有訊號。這是設計過程中發現並修正的一個漏洞。

S1 改用兩個判準：

1. **方向** —— 有沒有往指令的方向走。`side_sign` 錯會直接走反，一眼可見
2. **移動比例** —— 位置伺服與重力回復力矩並聯，平衡點是

```
q_eq − q_下垂 = kp · Δ指令 / (kp + k)
```

`k` 是該關節在下垂點附近的**局部重力剛度** `dτ/dq`（單擺的回復係數），
同樣由預演算出。所以「只走到指令量的 kp/(kp+k) 倍」是可預測的量。

kp 要挑到讓這個比例落在 **0.3 ~ 0.7** ——
比例明顯不等於 1、又不會小到量不出來，這時「有沒有走到位」的鑑別力最高。

### 1.3 為什麼低 kp 同時是安全設計

若 `side_sign` 反了，位置控制變成**正回授**，kp 越大跑得越遠。
但在下垂點附近，重力回復力矩 `k` 與錯誤的伺服互相抵消 ——
只要 `kp < k`，系統仍是穩定的，錯誤只會表現為「走偏」而不是「衝到限位」。

**低 kp 既安全又有鑑別力。** 這比「先給原廠的 kp=60~120 看它動不動」好一個量級。

## 2. 接管時序（中間沒有空窗）

```
讀當前實測角  →  SIGSTOP mc_ctrl  →  第一幀就寫 p_des = 當前角、kp = 0、kd = 小阻尼
  →  RAMP_UP    kp 0 → 目標值
  →  MOVE       p_des 由當前角**餘弦插值**到目標
  →  HOLD       維持並記錄（★ 主要證據就在這一段）
  →  RETURN     插值回起始角
  →  RAMP_DOWN  kp 降回 0
  →  歸零 + 補心跳  →  SIGCONT
```

- **第一幀就有指令**：凍結後心跳停、controller 會在 500 ms 後判定過期並清零，
  中間若有空窗腿會失力下墜
- **餘弦插值而非線性**：線性插值在起點與終點速度不連續，對吊在吊帶上的 41 kg
  來說那是兩次衝擊，會讓吊帶盪起來

## 3. 中止行為：阻尼停止，而且**保持凍結**

任何保護觸發 → `kp=0`、`effort=0`、`kd=--abort-kd`（純阻尼），補心跳，**不解凍**。

| 選項 | 為什麼不選 |
|---|---|
| 全部歸零 | 腿帶著載荷時等於**自由落體**撞機械停點 |
| 直接 SIGCONT | mc_ctrl 恢復後會繼續下指令去它凍結前的姿勢。若腿已移遠，**那就是一次突跳** |

所以中止一定有**人工判斷點**：印出 PID 與 `sudo kill -CONT <pid>`，由現場的人決定何時解凍。

**程式整個當掉也安全**：controller 的 `joint_cmd_timeout`(500 ms) 逾時會接手套
`estop_kd=35`，同樣是阻尼停止而不是失力。

而「16 顆全部洩力」這個前置條件，同時保證了 **mc_ctrl 凍結前也是洩力狀態**，
所以事後補一個 SIGCONT 不會造成出力。這是前置檢查不能跳過的真正理由。

## 4. 升階階梯（同一支程式，只換參數）

| 階 | `--joints` | 目標 | 這一階在驗什麼 |
|---|---|---|---|
| S0 | 任意 | 乾跑 | 換算、限位、預演力矩、預測偏差量 —— **不凍結、不寫入** |
| S1 | `fl2_hip_pitch` | `--delta` | **方向** + 移動比例。★ 不挑 hip_roll（見 §5） |
| S2 | `fl` | `--pose stand` | 第一次多關節協調，只有一條腿動，機身晃動小 |
| S3 | `front` | `--pose stand` | |
| S4 | `all` | `--pose stand` | 12 個腿關節 |
| S5 | `all` | `--pose crouch` / `home` / `--knee-back` | 站立、匍匐、膝模式切換 |

用同一份程式碼而非三支腳本，理由來自 HANDOFF 的鐵則：
**版本不一致的症狀會偽裝成硬體問題**。三支腳本就是三套 bug，
升階時無法分辨行為差異來自硬體還是來自程式差異。

## 5. ★ 為什麼 S1 挑 hip_pitch 而不是 hip_roll

ABAD（hip_roll）的行程只有 1.22 rad，而且**左右不對稱**：

| 關節 | MJCF range |
|---|---|
| `fr1` / `br1`（右側） | −0.697 ~ **+0.523** |
| `fl1` / `bl1`（左側） | **−0.523** ~ +0.697 |

而 hip_roll 的 `offset` 正好是 **±0.523** —— 也就是「控制器角 0」附近就已經
接近行程的一端。微動的方向若挑錯，很快就頂到限位。

hip_pitch 的行程是 5.2 rad，寬鬆得多，是微動測試的正確選擇。

## 6. 保護與判讀

逐關節、每個 tick 檢查：力矩、追蹤誤差、機構限位、速度、溫度、心跳速率。

### 6.1 座標系（★ 這裡是本專案第七號坑的重演點）

`joint_state` 的 `position` / `velocity` / `effort` **全都是馬達座標系**。
拿去跟 MJCF 預演的力矩比之前必須換算：

```
角度： θ_m = s·θ_c + off
速度： ω_m = s·ω_c              （offset 是常數，微分掉了）
力矩： τ_c = s·τ_m              （由功率守恆 τ_c·ω_c = τ_m·ω_m 推得）
```

raw `effort` 直接拿去比，**一半的關節會憑空反號**。
（這個錯誤在寫本程式的過程中真的犯了一次，事後才抓到。）

### 6.2 兩種長得像、成因完全不同的症狀

| 症狀 | 成因 | 處置 |
|---|---|---|
| 力矩接近上限**且**誤差不收斂 | **機構受阻**（吊帶纏到腿？碰到機身？） | 加大 kp 只會推高力矩。目視檢查 |
| 誤差大**但**力矩小 | **增益不足** | 低 kp 階段的預期行為，不是故障 |

程式會分開判並印出來 —— 這正是「多印一個可以互相對照的量」。

### 6.3 限位檢查用兩個不同的餘裕

- **規劃的軌跡**（起點與目標）：用 `--margin`（預設 0.05 rad），啟動時查一次
- **實測角**：用**硬限位**（margin=0）

若實測角也套餘裕，低 kp 故意讓它偏差的設計會在第一個 tick 就誤中止。

## 8. 已知限制

1. **腿關節摩擦仍是 0**（沒量過；只有輪的 0.15 是實測值）→ 預演的力矩略微樂觀
2. **沒有前饋重力力矩**。刻意的：前饋的符號若錯，錯誤會直接變成出力，
   而低 kp + 純回授的錯誤只會變成位置偏差。等 §1 的對照通過之後再考慮加
3. **吊掛狀態驗不了承重**。這一趟證明的是「能不能指揮到指定角度」，
   不是「站得住 41 kg」。落地測試是另一件事
4. MJCF 的 knee 限位 ±2.791 比 URDF 的 ±2.801 緊 0.01 rad。
   **保持略緊是安全的**，本次不動它
