# 步態診斷腳本（2026-08-27）

用來找出「前腳幾乎不往前踏」根因的一次性腳本。結論在
`task7/docs/前腳不跨步的根因_2026-08-27.md`。

★ 這些不是常設工具，沒有測試。留著是因為**量法本身**值得重用：

| 腳本 | 回答什麼 |
|---|---|
| `stride_world.py` | 每一腳在擺動相**實際往前跨多少**（世界座標）—— 「向前踏」最沒歧義的定義 |
| `swing_decomp.py` | 把上面那個量拆成「機身帶的」＋「腳自己走的」→ 得到**執行率** |
| `swing_trace2.py` | 單次擺動的逐控制步軌跡：指令 vs 實際 vs 追蹤誤差 |
| `wheel_roll.py` | **逐輪**淨滾動（`net_roll` 只印四輪平均，前後抵銷會把它藏起來） |
| `kp_test.py` | 證偽「是剛度不是時間」：掃 kp 與 ω |
| `gain_compare.py` | 原廠 RL 設定檔(120/kd1) vs 原廠站立實測(250/kd5) |
| `zsag_sweep.py` | 換增益後重掃 `z_sag`（它與 `KP3` 綁死） |

## 兩個量法上的坑（別重踩）

1. **擺動相判定**用 `duty_remap` 後的 `sin(th) > 0`（軌跡公式自己的定義），
   不要用離地高度門檻 —— 那在會彈跳的步態上會騙人。
2. **輪角讀數是包裹的**（`[−π, π]`）。轉超過半圈直接相減會得到完全錯誤的值，
   要逐步折回增量再累加（與 `realbot/shm_io.wrap_pi`、`Trace.yaw_total` 同一個坑）。
