## ★ 我們對官方原檔做的修改

> ⚠️ **`zgws.xml` 已經不是逐字元原檔了。** 這一節就是為了不讓下一個人誤以為它還是。

**改了什麼**：四個輪關節各加一個屬性 `frictionloss="0.15"`，其餘一個字都沒動。

```diff
-<joint name="FAR_FOOT_JOINT" ... actuatorfrcrange="-40 40"/>
+<joint name="FAR_FOOT_JOINT" ... actuatorfrcrange="-40 40" frictionloss="0.15"/>
```

四個關節：`FAR_FOOT_JOINT`(FR)、`FBL_FOOT_JOINT`(FL)、`RAR_FOOT_JOINT`(RR)、`RBL_FOOT_JOINT`(RL)。
**`damping` 維持不加**（理由見下）。腿關節不動，仍然是 0。

**為什麼**：原檔輪關節沒有任何被動阻力（`frictionloss` 與 `damping` 都是 0），
對輪子是**樂觀**的假設 —— 模擬裡輪子比實機更容易空轉。

**依據**：2026-08-25 實機單顆輪馬達驅動測試（`task7/docs/實機四輪驅動結果_2026-08-25.md`）。
四顆輪各跑多次，量到的摩擦力矩：

| 輪 | 摩擦力矩 (N·m) |
|---|---|
| 右前 FR | 0.13 |
| 左前 FL | 0.15 |
| 右後 RR | 0.15 |
| 左後 RL | 0.18 |
| **四組獨立量測平均** | **0.15** ← 填進 MJCF 的值 |

**為什麼是 `frictionloss` 而不是 `damping`**：實測是**純庫倫摩擦，沒有黏滯成分**。
低速 0.19 rad/s 時摩擦 0.152–0.160、高速 0.84 rad/s 時摩擦 0.135 ——
速度差 4.4 倍，摩擦不升反微降。黏滯摩擦會隨速度線性上升，這裡沒有，
所以 `damping`（= 黏滯項）**不能加**，只填 `frictionloss`（= 庫倫項）。

## ★ 第二次修改（2026-08-26）：腿關節填入實測靜摩擦

**改了什麼**：12 個腿關節（ABAD / HIP / KNEE × 4 腿）各加 `frictionloss="1.5"`。
原本是 **0** —— 從來沒量過。

**依據**：2026-08-26 吊掛實測（`docs/實機腿關節與16顆全控結果_2026-08-26.md` §2.1）。
量法是**力矩爬升法**：命令關節慢慢離開靜止角，`kp·誤差` 從 0 爬上去，
記錄「開始持續滑動」那一刻的力矩。**正反兩個方向相減即可不靠模型分離摩擦與重力**：

```
|τ₊| = τ_重力 + f        |τ₋| = f − τ_重力
→ f = (|τ₊| + |τ₋|)/2
```

| 關節 | 掙脫門檻 | 可信度 |
|---|---|---|
| HIP | **1.505 N·m** | 高（正反兩向、三種判讀門檻全一致） |
| KNEE | 1.5 – 1.7 N·m | 中（正向乾淨，反向是黏滑，±0.15） |
| ABAD | ≥ 1.25 N·m | **只有下界** —— 見下 |

**⚠️ 三個關節都填 1.5，但 ABAD 那個是「假定」不是量到的。**
ABAD 正向給到 2.41 N·m 只動了 0.13°；而它靜止在 q=−0.31 時，
模型算出的重力保持力矩是 1.25 N·m，馬達出力為 0 卻不動
→ 摩擦至少 1.25。真值可能到 2.5，但那次量測**可能被左右輪互相接觸污染**
（靜止角 −0.31 已超過預演算出的輪對輪接觸角 ∓0.277）。
**要在 stand 姿勢（輪子相距 150 mm）重測。**

**⚠️ 同樣是靜摩擦當動摩擦用**：MuJoCo 的 `frictionloss` 靜／動不分家，
而我們量到的是**掙脫門檻（靜摩擦）**。所以模擬在運動中會比實機**多阻力**。
與輪子那次是相反方向的偏差（輪子填的是動摩擦，靜摩擦門檻沒量到）。

### A/B：填了之後 CPG 步態變什麼樣

`--leg-friction 0` 可取回舊的無摩擦對照組。`walk`（同 x_off −30 mm）：

| | 無摩擦 | 實測 1.5 |
|---|---|---|
| 離地（最小） | 101.7 mm | **91.0 mm** |
| 彈跳 | 27.3 mm | **17.5 mm** |
| 路徑速度 | 0.27 m/s | **0.24 m/s** |
| **偏航（20 秒）** | **−12.4°** | **−0.1°** |
| 跌倒 | 否 | 否 |

★ **`x_off` 的配平點又動了**：平均俯仰過零點從 **−30 mm 移回 −40 mm**。
歷次：無摩擦 −42 → 併入輪摩擦 −30 → 併入腿關節摩擦 **−40**。
**這是第二次驗證「摩擦會移動配平點，不是只讓速度整體平移」。**
`GAITS` 的 `walk` / `walk_fast` 預設已改。

其餘判準重掃後結論不變：`duty` ≤0.70 仍必跌、`mu_y`=1.5 仍是唯一能好好走的、
地面摩擦門檻由 0.5 略降到 0.4（0.3 已不會跌倒，但速度只有 0.02 m/s、彈跳 100 mm，
是在原地彈不是在走 —— **「不跌倒」在這裡是很弱的判準**）。

---

**⚠️ 這 0.15 是「動摩擦」，不是「靜摩擦掙脫門檻」。**
實機那次三顆輪都是一給指令就轉，**掙脫門檻沒量到**（見量測文件 §「仍是動摩擦」）。
MuJoCo 的 `frictionloss` 只有一個值，靜／動不分家，所以這裡是拿動摩擦當兩者用。
若之後掃 kd 量到靜摩擦明顯大於 0.15，這個值要往上修。

**改動已驗證進到求解器**（不是只改了字串）：關掉重力、對輪施定力矩 1 s，
掙脫門檻正好落在 0.149 與 0.151 N·m 之間；且超過門檻後 ω(τ) 與原檔的 ω(τ−0.15)
逐位數相同（τ=0.20 → 12.3812 rad/s＝原檔 τ=0.05 → 12.3812 rad/s）。
純庫倫偏移、無黏滯項，與實機量到的性質一致。

**與 `cpg_walk_max.py --wheel-friction` 的關係**：
該旗標是在載入後改寫 `dof_frictionloss`，效果與這裡改 XML **完全等價**
（19 組步態參數逐項比對，數值逐位數相同）。旗標預設 0 且有 `if wheel_friction > 0` 的保護，
**不會覆蓋掉 XML 的值** —— 所以現在不加旗標跑，拿到的就是 0.15。
要回到「無摩擦」的舊行為，只能改 XML，旗標做不到。

**加了之後的模擬影響**（同一份程式碼、同一組參數 A/B，`walk_stable` ω=1.4）：
穩定性沒變（改前改後都不跌倒、支撐腳 2.93、機身高 481 mm、彈跳與週期俯仰差 <1%），
**前進速度反而快 4–10%**（0.303 → 0.318 m/s）。
機制：機身路徑長變長（8.91 → 9.17 m）而輪子總行程變短（4.42 → 4.03 m），
也就是摩擦把「輪子空轉」換成了「機身前進」。
與 `cpg_walk_max.py` §2 原本的預期（「靜摩擦只會讓腿式步態更好走」）一致。

官方原本附的 `scene_terrain_*.xml`（20 幾個地圖場景）沒有收，
它們塞滿障礙物與 hfield、依賴外部 png，不適合調步態。要用時從發布包取。

### 關節順序（qpos 位址）

```
qpos[0:7]   基座 freejoint
qpos[7,8,9]     FAR = FR  ABAD / HIP / KNEE      qpos[10] FR 輪
qpos[11,12,13]  FBL = FL  ABAD / HIP / KNEE      qpos[14] FL 輪
qpos[15,16,17]  RAR = RR  ABAD / HIP / KNEE      qpos[18] RR 輪
qpos[19,20,21]  RBL = RL  ABAD / HIP / KNEE      qpos[22] RL 輪
```

**腿序 FR, FL, RR, RL**，與 `zg_wheels-motion_config.yaml`（原廠動作腳本）一致。
腿名對應由 MJCF 自己的 `<sensor>` 段確認（`FR_hip_pos` 綁 `FAR_ABAD_JOINT`，餘類推）：
`FAR→FR`、`FBL→FL`、`RAR→RR`、`RBL→RL`。

⚠️ **12 個腿關節在 qpos 裡不連續**（每 3 個之後夾一個輪關節）。
task6 踩過這個坑：`qpos[7:19]` 這種寫法會把輪角當關節角讀進去，IK 變奇異矩陣而不報錯。
照 task6 `d1_model.LEG_QPOS_IDX` 的做法明列位址。

### ★ 站姿驗證：確認了「前後鏡像的 X 型」

把原廠設定檔的姿態餵進去做正向運動學：

| 姿態 | 結果 |
|---|---|
| 原廠站姿 `hip=[.6,.6,−.6,−.6]` `knee=[−1.2,−1.2,1.2,1.2]` | ✅ 四輪 x = **±0.3398**，前後對稱；前腿膝在輪後、後腿膝在輪前（**X 型**） |
| 四腿同號 `hip=[.6]*4` `knee=[−1.2]*4` | ❌ 後腿膝 x = −0.4753 但輪 x = −0.3172 → 後腿整條往後翹，前後**不對稱** |

→ **原廠那組（前後反號）才是對的。**
MJCF 本身也佐證：後腿的 hip 限位是鏡像的（`RAR_HIP range=[−2.791, 2.442]`
vs `FAR_HIP range=[−2.442, 2.791]`），URDF 那份則四腿都寫 ±2.443。

### ★ 質心幾乎沒有前後偏移（與 D1 EDU 差很多）

原廠站姿下：四輪 x 平均 = +0.0000、全機質心 x = −0.0006 → **偏移只有 −0.6 mm**。

對照 task6 的 D1 EDU：質心偏後 **17 mm**，逼得 CPG 要用 `x_off = −40 ~ −55 mm` 配平，
而且那個值隨步態與步頻變動、低步頻下還是雙穩態。

→ **這台可能幾乎不需要 `x_off`。** 這是個好消息，但**要用實際步態驗證**——
靜態質心對齊不保證動態俯仰也對齊。

## ⚠️ 直接用這份 MJCF 之前要處理的三件事

1. **致動器是純力矩 `<motor>`，沒有 ctrlrange、沒有 gear、沒有位置伺服。**
   官方的 PD 是由外部 `mc_ctrl` 提供的。要做位置控制得自己加
   `<position>` 致動器，或在迴圈裡自己算 PD（task6 是後者）。
   加的時候用原廠增益：ABAD 60 / HIP 120 / KNEE 120、Kd 1.0、輪 60/0.5。
2. **沒有 keyframe。** 沒有現成的初始站姿，要自己建（用上面驗過的 RL 預設姿）。
3. ~~**輪關節沒有 damping / frictionloss。**~~
   ✅ **已解決（2026-08-25）**：實機量到 0.15 N·m 純庫倫摩擦，已填進 `frictionloss`，
   見上面「我們對官方原檔做的唯一修改」。`damping` 仍是 0，而且**應該維持 0**
   （實測沒有黏滯成分）。腿關節的 damping / frictionloss 則**還沒量過，仍是 0**。
